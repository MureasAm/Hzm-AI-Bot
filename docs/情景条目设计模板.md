# 情景条目设计模板（behaviors 怎么写才有用）

> 起因：2026-10-04 针对"traits 里的『乐观的悲观主义者』细分进 behaviors"做的一轮实验。
> 这一轮第一次跑出**明确的正向结果**，也第一次定位到"复读"和"泛化"的分界线。
> 本文把这个结果固化成**可复用的写法和模板**，供后续所有 behaviors 条目使用。

---

## 一、核心结论（一句话）

> **模型能从一个情景的例句里抽出"反应骨架"，套到完全不同的话题上——前提是这些例句话题不同。**
> **一旦例句和用户当前说的是同一个话题，它就直接搬答案。**

这不是猜测，是实测。见第三节。

---

## 二、为什么 behaviors 是这个项目最重要的文件

这是本轮实验之后才看清的一件事：

```
traits / styles   抽象描述 → 模型读不懂"什么时候用"，最该开火时反而失效
voice_samples     具体例句 → 会泛化，但没有"什么时候用它"的开关
behaviors         情景 + 反应 + 例句 → 同时有开关和内容，是唯一两头都齐的形态
```

**behaviors 是"抽象描述"和"具体例句"之间的桥**：

| | 缺什么 |
|---|---|
| `traits`/`styles`（抽象） | 缺"什么时候用" → 触发不了 |
| `voice_samples`（例句） | 缺"什么时候用" → 检索只能按话题找，一撞车就复读 |
| **`behaviors`** | **情景（开关）+ 反应（骨架）+ 例句（内容）三样齐** |

**所以"泛化"这件事的本质是：`情景触发` + `反应骨架` + `异构例句` 三者共同作用的结果。**
只给例句（voice_samples）会复读；只给描述（traits）触发不了。

---

## 三、实测：同一批例句，撞车 vs 不撞车

### 实验设置

- **情景**：有人判她这件事以后肯定不行
- **例句 4 条**（全部是**直播**话题，内容互不相同）
- **两组输入**：一组与例句同话题，一组换话题

### 结果 A：输入与例句**同话题** → 逐字搬

输入「你现在是不是已经没什么人看了？」（例句①的 user 是"你这直播以后肯定没人看了"）

```
· 没人看就没人看呗，反正灰泽满也没指着这个活。   ← 逐字等于例句①
· 没人看就没人看呗，灰泽满也没指着这个活。       ← 逐字
· 没人看就没人看呗，灰泽满也没指着这个活。       ← 逐字
· 没人看就没人看呗，反正灰泽满也没指着这个活。   ← 逐字
```
**4/4 逐字。** 同话题 = 直接把例句当答案交付。

### 结果 B：输入与例句**不同话题** → 泛化换词

输入「灰泽满，你以后生活肯定不会很好。」（例句全是直播话题）

```
· 好不好也不是嘴上说了算的，灰泽满现在不也过得挺好的嘛。
· 好不好也不是说了算的，灰泽满现在过得还行啊。
· 好不好也不是你说算的嘛。
· 好不好也不是现在能看出来的嘛。灰泽满现在不还活得好好的。
```
**直播词泄漏 0 处。** 骨架留着（"X不X的，反正…"+"现在…"），内容全换。

输入「你这种人以后肯定没人要吧。」

```
· 没人要就没人要呗，灰泽满又不是为了给谁要才活着的。
· 没人要就没人要呗，灰泽满也没指着嫁人活。       ← 借了"没指着"的句式
· 没人要就没人要呗，灰泽满自己一个人也过得挺好。
· 没人要就没人要呗，灰泽满又不是货架上的东西等人来挑。
```
**"直播"自动换成"嫁人"，直播词 0 处。**

### 结论

| | 例句同质（同一件事换个说法） | 例句异构（同一情景不同内容） |
|---|---|---|
| 输出多样性 | 几乎为零 | 高 |
| 行为 | 死抱最贴的一条 | 抽骨架 + 换内容 |

**关键变量不是例句条数，是例句之间"像不像"。**

## 三之二 ⭐⭐ 第二条轴：**样本越泛化，越会被整句搬走**

> 2026-10-05 发现。**这条和上面"话题必须异构"是两条独立的轴**，别混。

### 数据（同一输入「我是认真的，我想和你交往」，各生成 12 次）

| 样本类型 | 例子 | 最高逐字复读 | 回复种类 |
|---|---|---|---|
| **A 泛化型**（放哪都成立的结论） | 「灰泽满才16岁，你这话说得跟灰泽满能答应似的」<br>「你问一百遍，答案还是这句」 | **12/12 = 100%** | **1 种** |
| **B 中等**（通用理由 + 一点细节） | 「灰泽满的课表排到晚上十一点，谈恋爱是要排在哪一格」 | 9/12 = 75% | 4 种 |
| **C 情境绑定型**（理由挂在**具体的事**上） | 「刚才还主人呢，现在又降级成老公了，你这称呼一天换三回」<br>「灰泽满从来没亲过别人，不亲」 | **4/12 = 33%** | **7 种** |

### 机制

```
泛化的句子 = 一个自足的**结论**，放到任何同情景的输入上都成立
          → 模型照抄它 = 又对又省事 → 必然复读

绑情境的句子 = 结论**挂在一件具体的事上**
          → 照抄就得把"三回""从没亲过"一起搬过去，
            而这件事跟当前输入无关 → 抄了不成立 → 模型只能自己组织语言
```

**⚠️ 但要看后半句**：C 组里最高频那句仍被抄 4 次，因为它是
「灰泽满的稿子还堆着三篇没写（具体 ✅），**你先等灰泽满把这个月活过去（泛化结论 ❌）**」。
**判据不是"整句具体不具体"，而是：这句里有没有一个"搬得走的泛化结论"。**

### 与"本土化"那条的关系（**两条独立的轴，别互相抵消**）

| 轴 | 怕什么 | 解法 | 例子 |
|---|---|---|---|
| **时间锚点** | 被当成**现在**复用 | **去掉**时间锚点 | 「明天要搬家」→「她一贯会拖」 |
| **泛化结论** | 被**整句搬走** | **加上**情境锚点 | 「我才16岁」→「刚才还主人呢，现在又降级成老公」 |

**所以"样本要本土化"不等于"样本要泛化"**——本土化去掉的是**时间**，不是**情境**。

### 实操判据（写 samples 时逐条过）

```
❌ 这句能不能原封不动搬到别的对话里？  能 → 它是泛化结论 → 改
✅ 抄它是不是必须连着一件具体的事一起搬？是 → 安全
```

**并且：拒绝/推脱类的样本，理由要具体**（"称呼一天换三回""从来没亲过别人""不想拿公式哄人"），
**不要给"我还小""我不谈这个"这种放之四海皆准的声明**——
真实记录里她本来就是**在讲具体理由**，泛化声明反而是我们加的。

## 四、模板

新增一条 behavior 时，按这个结构写：

```json
{
  "name": "被说以后不行时",
  "trigger": "<这个大情景的泛化描述>",
  "response": "<反应骨架：先做什么、再做什么，不带任何台词>",
  "samples": [ "<3~5 条，话题必须互不相同>" ],
  "evidence": [ "<来源：哪场直播、哪一段>" ]
}
```

### 4.1 `trigger` —— 写泛化的大情景，不写具体话题

```
❌ 太窄（把话题写进了触发条件）：
   被说直播没人看、热度掉的时候
   → 结果：说她"生活不好""没出息"时触发不了

✅ 对（只写情景）：
   有人判她这件事以后肯定不行——做不长、会散、会被忘记、会失去什么
   → 结果：直播、生活、感情、前途都能归进来（实测都触发成功）
```

**判据**：`trigger` 里出现的词，如果是**某个具体话题的名词**（直播、热度、粉丝），就是写窄了。

### 4.2 `response` —— 写反应骨架，不写台词

```
❌ 写了台词（实测被逐字抄）：
   先点头认领（'确实会''早晚的事'），再接一句'反正现在还在做'，最后自嘲收掉
   → 结果：模型逐字复读"确实会，早晚的事"

❌ 只写情境、不写反应（实测会跑偏去套例句）：
   有人当着她的面说这件事长不了
   → 结果：4 条里 3 条逐字抄例句，且跟当前问法不对应

✅ 对（反应结构，无台词）：
   不否认、不嘴硬顶回去。先承认，但是说起现在的情况，最后用一句自嘲或不在乎收掉。
   **只说状态，不举例子、不提具体的日子/几点/做过什么事。**
```

**两个必须遵守的点：**

1. **不带任何引号里的词**——带词的措辞会被原样搬走（这是项目里反复验证过的）
2. **必须写"不举例子、不提具体的事"**——不写这句，模型会编事实。
   实测：`response` 里写了"讲一件她此刻仍在做的小事"，模型就编出"昨天播到十二点"
   （输入里根本没有"昨天"），**编造率 2/5**；改成"只说状态"后 **0/5**。

### 4.3 `samples` —— 3~5 条，**话题必须互不相同** ★ 最要紧的一条

```
❌ 同质（同一件事换说法）：              ✅ 异构（同一情景不同话题）：
   你这直播以后肯定没人看了                你这直播以后肯定没人看了
   你这热度掉得也太快了吧                  你迟早会不想播了吧
   你这种小主播能撑多久啊                  等你毕业了肯定就把我们忘了
   ↑ 全在说"热度/没人看"                  ↑ 各有各的具体内容
   → 模型死抱一条，输出复读                → 模型抽骨架，换内容
```

**收集时该怎么挑**：不是"同一件事找 5 种说法"，而是**"同一类情景找 5 件不同的事"**。

### 4.3.1 ⚠️ 前 2 条 `samples` 还兼任"给分类器看的路标"

`routing.py:170` 里，L3 分类器拿到的每条 behavior 定义是：

```
- <name>：<trigger>
    例：<samples[0].user>
    例：<samples[1].user>
```

**只取前 2 条**，而且只取 `user`（不取 reply）。所以：

> **`samples[0]` 和 `samples[1]` 要放"用户最可能怎么说出这个情景"的真实话**，
> 光放"嗯。""哦"这种没有信息量的短句，分类器就判不出来。

**实测**：冷场那条曾把前两条写成"嗯。""哦。"→ L3 判空、该触发的用例失败；
换成"今天你在小群里成冷场大王了"后立刻恢复。

**剩下第 3 条起，才是纯粹给生成模型看的示范。**

### 4.3.2 ⚠️ 写完必须查"撞车"

**样本的 `user` 和用户真实会说的话越像，模型越会把样本当标准答案逐字搬。**
实测踩过两次：写完 `失约被催` 的样本（"你怎么又迟到了"），
而回归用例正好就是这句 → **6/6 逐字复读，回归从 7/7 掉到 6/7**。

```bash
.\.venv\Scripts\python.exe outputs\_experiments\check_collision.py
```

它拿全部评测/回归用例的 query 去比每条样本的 `user`，**只在"特有词"上比重合**
（去掉"灰泽满/是不是/直播"这类到处都有的词，否则误报一堆），重合 ≥50% 就报出来。
**发现撞车就改样本，不要改用例**——用例代表"用户真会说的话"，样本才是可以换的。

### 4.4 一条完整的合格样例

```json
{
  "name": "被说以后不行时",
  "trigger": "有人判她这件事以后肯定不行——做不长、会散、会被忘记、会失去什么",
  "response": "不否认、不嘴硬顶回去。先承认，但是说起现在的情况，最后用一句自嘲或不在乎收掉。只说状态，不举例子、不提具体的日子/几点/做过什么事。",
  "samples": [
    {"user": "你这直播以后肯定没人看了", "reply": "没人看就没人看呗，反正灰泽满也没指着这个活。"},
    {"user": "你迟早会不想播了吧", "reply": "迟早的事。真到那天就不播了，现在不还在这儿嘛。"},
    {"user": "等你毕业了肯定就把我们忘了", "reply": "忘不忘的，灰泽满现在还没毕业呢。想那么远干嘛。"},
    {"user": "你这种东西过两年就没人记得了", "reply": "不记得就不记得，灰泽满又不是为了被记住才做的。"}
  ]
}
```

## 五、从直播素材里怎么分出这些内容

### 5.1 现状与瓶颈

现成的工具有：

```
transcribe         音频 → 带时间戳的转写（large-v3 可用，40 分钟音频约 7.5 分钟）
clean-transcript   转写 → 按时间间隔聚合成话轮，调 LLM 清洗
persona-pipeline   再往后走到 corpus / behaviors（voice-samples / phrases 已下线）
```

**但"从直播里认出情景"这一步目前没有可靠工具。** 实测（0713 病弱电台，221 话轮）：
纯致谢占 28%、事务占约 20%、真正含自我表达的话轮约 44 条——**靠关键词筛出来的候选噪声极大**
（试过一次，766 条候选，人工基本没法读）。

### 5.2 建议的流程（先标注、再提取）

**关键点：不要一上来就让模型自己"提炼情景"，那会产出一堆你无法验证的抽象标签
（现在的 `traits` 就是这么来的，结果是"写了一套、执行了另一套"）。**

正确顺序是她自己参与的分步法：

```
第 1 步 人工在转写片段上标"这段有情景价值"      ← 只有人能做，判据是"这是不是一种待人接物的方式"
第 2 步 把这些片段按"情景"聚类（人来做）         ← 自然的聚类数量通常在 10~30 之间
第 3 步 给每个情景写 trigger / response（照第四节模板）
第 4 步 从片段里挑 3~5 条，话题必须互不相同，填进 samples
第 5 步 拿这个条目去跑真实的用户问法，看是不是"泛化"而不是"复读"
```

**第 1 步的标注判据**（一条话轮值不值得进 behaviors）：

| 收 | 不收 |
|---|---|
| 她在应对某类人际情境（被夸、被质疑、被越界、被真心戳中…） | 她在陈述事实（今天做了什么、吃了什么） |
| 这个反应**换个人问也会一样** | 只对当时那个人/那件事成立 |
| 能说出"这是什么情景" | 说不出情景，只能说"她说了句话" |

### 5.3 参考方向

外部产品（Character.AI 的 Lorebook、SillyTavern 的 World Info）**只做到"关键词触发条目"这个粒度**，
没有"从直播素材里自动分出情景"的成熟方案——**这一步没有现成答案可抄，得自己趟**。
唯一可借鉴的是它们对条目的判据（见 `注入设计原理.md` §4.5 的对照表）。

## 六、这条路线推翻/修正了什么

| 原来的说法 | 修正后 |
|---|---|
| "碎片不自足→织进新句；自足句→被整句搬走"（`注入设计原理.md` §3.3） | ⚠️ **过于绝对**。实测：碎片（"不还在这儿""没指着"）被大量复用，**而它们是从完整例句里切出来被复用的**；真正决定复读的是**例句与输入是否同话题**，不是自足与否 |
| "多给例句会更容易复读" | ❌ **错**。正确说法：**例句同质**会复读，**例句异构**会泛化 |
| "包装语对怎么用零作用" | ⚠️ **部分成立**。实测强包装语能把"整句逐字抄"从 1/4 压到 0/4，但改不了"抄半句" |
| "traits 可以细分进 behaviors" | ✅ **成立**，但必须按第四节模板写；直接搬过去（带台词的 response）会变成逐字复读 |
| `traits.json` / `styles.json` 是两个"人格层"文件 | ❌ **两个文件都不该存在**（2026-10-04 已拆掉）。见六之二 |

## 六之二 ⭐ 贯穿性原则：没有"第三个文件"

拆掉 `traits` / `styles` 之后才看清的结构。**任何一条内容，只有三种归宿：**

| 归宿 | 判据 | 在哪 |
|---|---|---|
| **① 骨架** | 这条倾向**对每一轮都生效**（节奏 / 自称 / 标点 / 篇幅 / 代词） | `persona/core/system_prompt.txt` |
| **② behaviors** | 这条倾向**只在某类处境下出现** | `persona/behavior/behaviors.json` |
| **③ 数据** | 这是**事实 / 词义 / 固定应答**，不是"怎么说" | schedule / terms / corpus / legendary / voice_samples |

**"第三条路"不存在。** 一条内容如果既没有可识别的触发条件、又不是事实，
那它必然是"对每轮都生效的说话习惯" → **它就属于骨架**。

**这正是 `styles.json` 一直"看起来没作用"的原因**：它是个没有归属的文件。实测拆解：

| 原 styles 条目 | 性质 | 去处 |
|---|---|---|
| 重复与自我修正 | **触发条件写在描述里了**（"面对窘境或需要强调时"）→ 情景绑定 | ✅ 变成 behavior『窘迫或要强调时碎碎念』 |
| 反问与挑衅式推进 | 对每轮都生效 | ✅ 并进骨架【说话节奏】 |
| 戏剧化叙事与画面感 | 对每轮都生效 | ⛔ **直接删掉**（见六之三） |

（`traits.json` 同理：4 条里「乐观的悲观主义者」是情景；其余是骨架已覆盖的因果描述或偏好类事实。）

## 六之三 ⛔ 为什么「戏剧化叙事与画面感」被删掉

实测它**效果巨大**（问她"今天过得怎么样" 23→41 字；让她讲一段经历 46→**106 字**，
画面感很强）。**但仍然必须删**，两条理由：

### 理由 1：它让模型**编**，而且编出来的会跟别的行为打架

```
它生成的："上次出门……一只袋鼠蹲在垃圾桶旁边，跟个流浪汉似的……灰泽满跟它对峙了三分钟"
          "澳洲大妈用韩语跟灰泽满打招呼，最后憋出一句四川话'你说啥子'"
```

**这些全是编的**（素材里没有袋鼠、没有韩语大妈）。而"讲具体"与另一条行为直接冲突：

> 『被追问私事细节时含糊带过』= 问到具体情况**含糊带过**
> 『戏剧化叙事』= 把小事**讲出具体细节**
> → **同一件事上两个行为给出相反指令**

### 理由 2：**长文本本身就是直播的产物**

直播要讲故事、要撑时长，所以素材里长叙事多；**私聊里几乎不存在长文**。
把它当风格注入，等于把"直播的篇幅"搬进私聊 —— **这是"直播→私聊"的又一处失真**，
跟"情景层面的直播专属"是同一类问题，只是这次失真的是**长度**。

### 由此得到的两条规则

```
① 凡是靠"讲具体"来表现的风格，都要警惕——模型没有真材料，讲具体就是编。
② 篇幅是"域相关"的：直播的篇幅不能直接搬到私聊。
   骨架里要显式写"私聊里基本没有讲长故事这回事"，否则模型会按素材的篇幅感走。
```

**残留风险（已记录，暂不处理）**：`voice_samples` 里若混有直播式长叙事样本，
同样会把篇幅拉长。抽查时留意 `reply` 超过 60 字的样本。
