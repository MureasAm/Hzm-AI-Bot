# 数据迭代（怎么用聊天记录发现该改哪个文件）

> 2026-10-20 建。目标：把“偶然看到一条聊天记录 → 手改数据”变成一套**每周可重复**的流程。
> 核心原则：**模型只读日志、提候选；人审拍板；回归验收**。模型不直接改/删任何数据文件。

## 2. 日志：现在缺什么

**已有（都在 `data/`，不入库）**

| 日志 | 记什么 |
|---|---|
| `data/chat_log/<会话>.jsonl` | 用户文本、她的回复、图片描述、本批消息条数 |
| `data/block_hits.jsonl` | 这一轮实际开火了哪些块（块名） |
| `data/corpus_hits.jsonl` | 实际注入的 corpus 条目 id |
| `data/llm_usage.jsonl` | 每类调用、通道、token |
| `user_memory/memory_v2_audit.jsonl` | 记忆提取/作废决策 |
| `data/sticker_log.jsonl` | 表情包判定/发送 |

**需要补：每轮的条目级注入轨迹**

新建 `data/injection_trace.jsonl`（只记 id/名称，不记整段提示词）：

```json
{
  "t": 179..., "session": "2807992783", "route": "私",
  "blocks": ["history", "behaviors", "preferences", "terms", "corpus", "associations", "scene_private", "now"],
  "items": {
    "behaviors": ["被夸时把夸奖调小"],
    "terms": ["东野圭吾", "小说家"],
    "preferences": ["author", "favorite_books"],
    "core_stories": ["writer_dream"],
    "corpus": ["388", "391"],
    "memory": ["bc97c0b0d76d92df5e1f"],
    "associations": ["空中杀人现场", "东野圭吾"]
  },
  "values": {"now": "...", "mood": "...", "daily": true},
  "reply_used_nickname": false
}
```

- 只给**实际进提示词**的条目，不给候选/被拒的；候选与判定另由 `corpus_hits`/audit 覆盖。
- 条目级是模型诊断的前提；只有块名时，它只能猜“可能是 behaviors”。
- `reply_used_nickname` 用于观察称呼提示有没有真的被用。

## 3. 每个文件的评测指标（骨架/周表除外）

| 文件 | 看什么 | 怎么量 |
|---|---|---|
| 偏好 | 关键词覆盖、和回复是否冲突、是否过期 | `retrieval-eval` 的 preference 路；冲突用回放/模型只读诊断；命中率用 trace |
| 词条 | 该命中的别名/问法有没有覆盖、误触发、事实是否正确 | 用真实问法回放；**“听不懂/不明白”反查**（见 §5） |
| 行为 | 触发准不准、样本是否多样、固定句式率、用户纠正率 | L3 判定 vs 人工标注；opener 频率；trace 里的行为名；§6 漏情景挖掘 |
| 语料 | 利用率、候选召回、判官精度、重复/过期 | `corpus_hits`、`corpus_entry_audit`、`corpus_usage_replay` |
| 核心记忆 | 命中率、相关性 | `retrieval-eval` core_story 路 + trace |
| 长期记忆 | 提取准确率、注入相关性、矛盾/过期 | `memory_v2_audit` + trace + 回放 |
| 会话/短期 | 前后矛盾、指代错人、历史是否够用 | 回放最近 N 轮；人工/模型只读诊断 |
| 批次/短消息 | 开火率、注入文案是否正确 | `block_hits` + `daily_acceptance` / 回放 |
| 群聊 | 无主语的“你”被误认成她的比例、该接时有没有接 | 20 批真实群聊回放 + 人工判 |

**判定方式**：每个文件单独“通过/不通过 + 趋势”，不做跨文件总分；模型只负责找证据，不负责拍板。

## 4. 每周流程

1. **取数**：最近 7 天 `data/chat_log/` + `injection_trace` + 各 audit。
2. **跑确定性指标**：用户下一轮纠正/抱怨率、同一 opener 重复率、检索空轮次、`听不懂/不明白` 回复数、偏好/行为冲突数。
3. **挑问题轮次**：用户明确纠正（“让你评价小说没让你评价表情包”）、重复口癖、检索空、答非所问、该接没接。
4. **模型只读诊断**：给它“那一轮 + 当时注入的条目”，输出：哪个文件、哪一条、证据、建议改成什么、置信度、预期改善指标。
5. **候选落盘**：`outputs/review/YYYY-MM-DD.md` + `.json`（不入库）。
6. **人审 + 修改**：按现有流程（`persona-pipeline` / 手工）；一次只改一个文件的一条。
7. **验收 + 回滚**：见 §7；每条被采纳的修改都新增一条回归/验收用例。

**频率**：每周固定一次 + 看到翻车时手动跑。

## 5. 词条：从“听不懂/不明白”反查

她回复里出现这些信号时，说明**用户问的词她没接住**：

`听不懂 / 不明白 / 没懂 / 啥意思 / 不知道你在说什么 / 没听说过 / 这是什么`

流程：

1. 扫最近聊天记录，抓“她的回复含上述信号”的轮次；
2. 取同一轮用户原文 + 前一小段上下文；
3. 模型只读判断这是哪一类：
   - **缺词条**：用户用了她不该不懂的词/人名/梗；
   - **缺别名**：词条有，但用户说法没进 keyword/aliases；
   - **检索没命中**：词条命中条件写了但没注入；
   - **不是知识问题**：她在玩梗/装傻/话题本来就不需要懂。
4. 只有前两类产出“新增词条/补别名”候选；第三类查 trace；第四类不记。
5. 候选必须带用户原话与上下文，人工确认后才进 `terms.json`。

## 6. 行为：从聊天记录发现“频繁但没进行为库”的情景

可以，但要求比词条严：**高频 ≠ 该进行为库**。行为库收的是“她一贯的情境反应”，不是单个用户的习惯。

流程：

1. 取最近 N 天用户消息 + 前文，去掉寒暄；
2. 用模型或向量聚成“情景簇”；
3. 只保留 **≥5 次、跨 ≥3 个用户/会话** 的簇；
4. 模型只读判断：
   - 这个情景是否已有 behaviors 的 trigger 覆盖？
   - 她在这些轮里是否有**一致的反应**（不是每次都换）？
   - 这是“她对所有人的一贯反应”，还是“某个用户的习惯/一段关系”？
5. 只有“未覆盖 + 反应一致 + 跨用户”才产出新行为候选；
   单用户习惯走 `03_profile`/偏好/记忆，不进行为库。
6. 候选必须带 3 条以上真实例句；人工确认后按 behaviors 格式加入，并补回归用例。

## 7. 候选格式、验收、回滚

**候选（`outputs/review/`，不入库）**

| 字段 | 内容 |
|---|---|
| `file` | 要改的文件（behaviors/terms/preferences/...） |
| `item` | 条目 id / 关键词 / 行为名 |
| `problem` | 一句话说清哪里不对 |
| `evidence` | 2~5 条真实轮次（会话、时间、用户原话、她的回复） |
| `proposal` | 按该文件格式给出的候选改法 |
| `confidence` | 低/中/高 |
| `expected_metric` | 改完应该改善哪个读数（opener 率、纠正率、命中率…） |

**验收**

- 相关文件的验收用例（如 `retrieval-eval` 对应路、`daily_acceptance`、回放 case）；
- `run_tool.py regression --check`；
- `pytest -q`；
- 检索/语料/行为改动再加 `retrieval-eval`。

任何一项低于基线就回滚；每条采纳的修改都新增一条回归/验收用例。

**隐私**

- `data/`、`user_memory/`、`outputs/` 都不入库；轨迹和候选只在本机；
- 轨迹只存 id/名称/值，不存整段提示词；候选里的用户原话只留在本地报告里；
- 原始 handoff 语料/全量转写仍遵守交接信：不公开再分发。
