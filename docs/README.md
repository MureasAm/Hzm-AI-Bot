## ⭐ 先看这条分类（整个架构就看这两张表）

**2026-10-04 起，项目只有两个概念。** 详细版见 `注入链路.md` 第二、三节。

### 分类①：人格文件 vs 事实文件

| | 人格文件 | 事实文件 |
|---|---|---|
| **回答** | 她是谁、怎么说话 | 她知道什么、发生过什么 |
| **几个** | **2 个** | 其余全部 |
| **文件** | `core/system_prompt.txt`（骨架，**每轮常驻 3452 字 = 输入 91%**）<br>`behavior/behaviors.json`（16 条情景，**命中才注**） | 周表 / 名词库 / 时间 / 直播记忆 / 偏好 / 核心记忆 / 记忆三件 / 历史 / 连续索要计数 |

**判据**：说「**她怎么说话 / 遇什么情境怎么反应**」 → 人格层；说「**她知道某个词/某件事/某个偏好**」 → 事实层。
**台词/原句不算独立文件**——必须挂在某条 behaviors 的 `samples` 里。

### 分类②：判定方式（**改素材前先确认它属于哪种**）

| 判定方式 | 谁用 | 代价 |
|---|---|---|
| **⓪ 常驻** | **骨架**、周表、时间感知 | 骨架吃 91% 预算 |
| **① 关键词/子串/正则** | 名词库 terms、偏好 preferences、legendary | 免费（本地） |
| **② 向量相似度** | 直播记忆 corpus（**初筛**）、核心记忆 | 一次 embedding |
| **③ LLM 判断** | **behaviors（★真 LLM）**、corpus（初筛后**再审**） | 每轮多 1 次 LLM |

## 一句话记住这个项目的四条判据

```
① 判据按任务选   归类→LLM分类 ｜ 关键词能说出口→子串 ｜ 说法不可枚举→向量+LLM判
② 样本必须挂情景 按话题检索→必然灌事实 ｜ 按情景检索→只带走形态
③ 位置决定视角   紧挨用户那句→"刚发生过的事「 ｜ 放前面→」参考资料"
④ 包装语管不住   想让模型怎么用，改形式（换话题/不自足），别加说明
```

（每条都有实验数据，见 `注入设计原理.md` 与 `情景条目设计模板.md`）
