```bash

```

代码里有**进程内缓存**（人格数据、向量库等启动时加载）。**改任何代码或数据后，重启 `bot.py`**，否则改动不生效。


- 当前基线：`retrieval-eval` **47/48**；`regression --check` **7/7**。
- 某句话答得不对，先 `run_tool.py problems --query "那句话"` 看**检索实况**，再决定改哪个文件（见 §5）。

## 1. 新增直播素材 → corpus / behaviors（安全流水线）

**只做一件事：拿到一场新直播素材后，安全更新 `corpus`（事实层）或 `behaviors`（人格层）。**

统一入口：

```bash
python scripts/run_tool.py persona-pipeline <target> [参数]
```

`target` **只有两个**：

| target | 落点 | 走什么 |
|---|---|---|
| `corpus` | `persona/world/statement_final.json` | 向量 + LLM 判 |
| `behaviors` | `persona/behavior/behaviors.json` | 判别词 + LLM 分类（**不走向量**） |

### 三步：prepare → review → apply

```text
音频或清洗 JSON
  → 生成候选（prepare，默认模式，不改 persona）
  → 写入 outputs/persona_pipeline/<session>/
  → 人工看 <target>_review.md
  → 确认后加 --apply 写回（自动备份原文件）
  → corpus 写回后自动重建向量 + 补钩子
```

**输入方式 A：直接从音频**（内部 `transcribe → clean-transcript → 对应处理`）

```bash
python scripts/run_tool.py persona-pipeline corpus \
  --audio assets/audio/xxx.m4a --session 20261001
```

同一 `--session` 首次跑完会留 `cleaned.json`；后续复用，不重复转写。强制重跑音频加 `--refresh`。
当前解释器没有 `faster-whisper` 时设 `WHISPER_PYTHON=D:\whisper_env\Scripts\python.exe`，或用 `--whisper-python`。

**输入方式 B：从已清洗 JSON**

```bash
python scripts/run_tool.py persona-pipeline corpus \
  -i outputs/clean/cleaned_xxx.json --session 20261001
```

`-i` 可传多份（`-i a.json b.json`）。

### 输出位置

```text
outputs/persona_pipeline/<session>/
├── cleaned.json            # 从音频开始时才有
├── <target>_raw.json       # 原始生成结果
├── <target>_candidates.json
├── <target>_review.md      # ← 人工看这份
└── backup/                 # --apply 时自动备份
```

### 审查后写回

需要删条目 / 改文字，**直接编辑 `<target>_candidates.json`**，然后（不加 `--refresh`）复用这份候选写回：

```bash
python scripts/run_tool.py persona-pipeline corpus --session 20261001 --apply
```

想重新生成候选再加 `--apply --refresh`。`corpus` 若暂时不想重建向量加 `--no-vectorize`（批量合并多场时最后统一重建）。

### 安全规则

- 默认**不写** persona，只有 `--apply` 才写；写回前自动备份；重复内容自动去重。
- `corpus` 写回后自动跑 `generate_vectors` 重建 `corpus_vectors.json`；向量生成失败时保留写回结果和备份并报错。
- `corpus` 写回后自动补 `corpus_keywords.json`（**只补缺失索引，不覆盖手工钩子**）。本轮不要这步加 `--no-hooks`。
- `behaviors` 不走向量，不需要 precompute。

### corpus 的判断标准

- 只写「发生过什么」；**不保留她的成句台词**；具体事件要真实；不要带时间戳。
- **不要写「灰泽满……她/他……」**：主语是灰泽满后，后续同主语省略或继续写灰泽满；只有「她/他」明显指别人（女同学/老师/满妈）时才保留。
- 流水线写回前会**自动审计自指代词**，用 LLM 只改写复指灰泽满的句子，改写前后存 `corpus_self_pronoun_before.json` / `corpus_self_pronoun_after.json`。

### 清理已有 corpus 的自指代词（`--sanitize-existing`）

历史 corpus 已落库、但仍残留「灰泽满……她/他……」时：

```bash
# 审计整个 statement_final.json
python scripts/run_tool.py persona-pipeline corpus \
  --session corpus-self-pronoun-cleanup --from-index 0 --sanitize-existing --apply

# 只清理某一批新增（例如本次新增从 322 号开始）
python scripts/run_tool.py persona-pipeline corpus \
  --session 20260923-wanjianzatan --from-index 322 --sanitize-existing --apply
```

它审计整份 `statement_final.json`：复指灰泽满的「她/他」→ LLM 定向改写；指别人的 → 不动。
**索引不变**，所以 `corpus_keywords.json` 不用重建；默认同时重建 `corpus_vectors.json`。

### behaviors 流水线的判断标准

- 只保留**反复出现、稳定**的行为模式。
- `response` 只描述「做什么」，**不写具体台词**（写台词会被逐字抄，见 §3）。
- `samples` 必须来自 `convert-to-chat` 的真实素材，**话题必须互不相同**（见 §3）。

## 2. 从直播素材挖「处境」填 behaviors（四层工具链）

**回答一个问题：怎么从几十小时直播转写里，挖出「她在一类人际处境下怎么应对」，写成 behaviors 条目？**

### 为什么不能直接用 `extract_persona.py`

它吃的是**已经切好的单轮问答对**。切分时同一句提问会被复制给她的多个碎语（实测 `converted_0726.json` 前 3 条 `user_situation` 全是「粉丝说：中午好」，`reply` 却是一段话切出来的 3 个碎片）→ 模型看到的全是「同一情境配不同回答」→ 只能得出「没有稳定模式」。**成绩：877 对 → 2 条。**

根因：① 单轮对在结构上表达不了「情景」（情景是连续几轮推进出来的）；② `BATCH_SIZE=50` + 提示词「通常 2-5 条」上限太低；③ 旧 `SCENE_GROUPS` 清单已过期，归错类甚至被丢。

### 四层工具链（都在 `outputs/_experiments/`，不入库、一次性）

```text
outputs/clean/*.json（连续话轮，带 start/end）
   │
   ├─ ① scene_segment.py   切情景（在连续时间轴上标区间）
   │      产出 outputs/scene_segments/<场次>_scenes.json
   │
   ├─ ② scene_cluster.py   分批归并（45 条一批，合并同处境）
   │      产出 outputs/scene_clusters.json
   │
   └─ ③ scene_merge.py     层级归并 + 标「已覆盖 / 缺口 / 直播专属丢弃」
          产出 outputs/scene_final.json
```

一键跑全部场次 / 单场调试：

```bash
.venv\Scripts\python.exe outputs\_experiments\run_scene_pipeline.py

# 单场：--dry 只切分不写文件
.venv\Scripts\python.exe outputs\_experiments\scene_segment.py outputs/clean/cleaned_百日.json
```

> 旧版还有 `scene_recount.py`（数回原始片段），**已不存在**；结论是"不靠谱，别依赖"。

### 每层在干什么（三个关键判据）

**判据 1：这是「处境」还是「事件」？**「把这件事换成别的话题，这套应对还成立吗？」
成立 → 处境（标）；不成立 → 事件（别标）。
反例（事件）：`被弹幕起哄怀孕`、`被追问孩子他爸`、`质疑周表真假`。
正例（处境）：`被反复索要同一样东西`、`被质疑说法真实性`、`被真心对待时别扭缩回`。

**判据 2：能不能搬进一对一私聊？**「把『弹幕/观众/投稿/直播』从这段去掉，处境还成立吗？」
直播专属要丢弃：念投稿/点评二创/看粉丝视频、游戏实况解说、答谢打赏/欢迎舰长、念弹幕/回应刷屏、展示形象/换装、直播设备操作、下播催播/周表。
私聊照样发生：被夸 / 被质疑 / 被催 / 被反复要东西 / 被追问私事 / 被索要亲密 / 被逼表态 / 对方道歉 / 自我否定 / 情绪崩溃 / 骂她 / 造谣 / 真诚感谢 / 倒苦水。
⚠️ 没有这个筛子时实测 17 条缺口里 **12 条是直播专属，白跑**。

**判据 3：模型只许标区间，不许写原文。** 原文由程序按话轮号回填；模型写的 `her_move` 里不许出现原句 —— 从源头杜绝"模型改写素材"。

### 层级归并为什么要"层级"

实测 149 条一次喂进去，模型输出超 `max_tokens` 被截断（`Unterminated string`）。所以分批并 → 再并结果 → 直到并不动。停止条件是"这一轮没并动"，不是"达到某个条数"（实测 149→107→87→78→65→62→49→47→46 才停）。

`scene_merge.py` 同时标三件事：`covered: "现有条目的名字"`（同处境）/ `covered: ""`（**缺口**）/ `drop: true`（直播专属丢掉）。

### 实测框架（2026-10-04，11 场 / 3080 话轮）

```
11 场 → 329 个片段 → 149 条候选 → 层级归并 → 44 条
  其中：6 条已被现有条目覆盖 ｜ 38 条缺口 ｜ 2 条判为直播专属丢弃
```

**高频处境全部已在现有条目里**，缺口都在中低频侧。

### 从候选到条目：三条硬规则

1. **段数 > 10 才值得入选**。低频条目会稀释分类器、占注入预算、且难验证；尾部那批大多是个别用户的特殊行为。
2. **先合并明显重复的候选**（如「对方讲自己的事时陪聊投入」23 段 + 「对方讲事时陪聊接话」4 段 → 同一条）。
3. **和现有条目划清边界**：写之前先答「它和现有哪条最像，区别在哪」。

### 已知的坑（都踩过）

| # | 坑 | 应对 |
|---|---|---|
| 1 | **`samples.user` 与真实输入撞车 → 逐字复读**（最频繁） | 写完样本必跑 `check_collision.py`；发现撞车**改样本，不要改用例** |
| 2 | **`samples` 前 2 条兼任 L3 分类器路标**（只取 `samples[:2].user`） | 前 2 条必须是「用户最可能怎么说出这个处境」的真实话；放「嗯。」「哦。」→ L3 判空 |
| 3 | 括号概括式 `user` 可用，但**不解决撞车** | 照抄与否取决于撞不撞车，与写法无关 |
| 4 | 层级归并要**防死循环** | 停止条件是"没并动"，不是条数 |
| 5 | **`段数` 绝对值不可信** | 脚本没保留"来自哪几场"，多是单批内计数；**排序方向可用，绝对值偏低** |

撞车检查工具（写完样本必跑）：

```bash
.venv\Scripts\python.exe outputs\_experiments\check_collision.py
```

它拿全部评测/回归用例的 query 比每条样本的 `user`，**只在"特有词"上比重合**（去掉"灰泽满/是不是/直播"这类到处都有的词），重合 ≥50% 就报出来。

### 完整操作流程（下次直接用）

```text
1. 转写 + 清洗（没有现成清洗稿时）
   env 版 python scripts\run_tool.py transcribe "assets\audio\xxx.m4a" --model large-v3 --out-dir outputs\transcribe_lv3
   .venv\Scripts\python.exe scripts\run_tool.py clean-transcript -i <转写.json> -o outputs\clean\cleaned_xxx.json
2. 跑情景流水线：.venv\Scripts\python.exe outputs\_experiments\run_scene_pipeline.py
3. 看结果：outputs/scene_final.json 的 gaps / covered / dropped
4. 人工筛选：段数 > 10 的先看，合并明显重复的
5. 逐条写条目（照 §3 模板）+ 挑 samples（话题必须互不相同）
6. 写完必跑三件套：
   .venv\Scripts\python.exe outputs\_experiments\check_collision.py   # 撞车
   .venv\Scripts\python.exe -m pytest -q                             # 单测
   .venv\Scripts\python.exe scripts\run_tool.py retrieval-eval       # 检索评测
   .venv\Scripts\python.exe scripts\run_tool.py regression --check   # 工程回归
```

## 3. behaviors 条目怎么写（模板）

### 一句话核心结论

> **模型能从一个情景的例句里抽出"反应骨架"，套到完全不同的话题上——前提是这些例句话题不同。**
> **一旦例句和用户当前说的是同一个话题，它就直接搬答案。**

### 为什么 behaviors 是最重要的文件

| 形态 | 缺什么 |
|---|---|
| `traits`/`styles`（抽象描述） | 缺"什么时候用" → 触发不了（**两个文件都已拆掉**） |
| 例句堆（旧 `voice_samples`） | 缺"什么时候用" → 只能按话题找，一撞车就复读（**已下线**） |
| **`behaviors`** | **情景（开关）+ 反应（骨架）+ 例句（内容）三样齐** |

### 两条轴（**独立，别混**）

**轴一：例句话题必须异构**（同质 → 死抱一条、复读；异构 → 抽骨架、换内容）。
**关键变量不是例句条数，是例句之间"像不像"。**

**轴二：样本越泛化，越会被整句搬走**（2026-10-05 发现）。同一输入「我是认真的，我想和你交往」各生成 12 次：

| 样本类型 | 例子 | 最高逐字复读 | 回复种类 |
|---|---|---|---|
| A 泛化型（放哪都成立的结论） | 「灰泽满才16岁，你这话说得跟灰泽满能答应似的」 | **12/12** | **1 种** |
| B 中等（通用理由 + 一点细节） | 「灰泽满的课表排到晚上十一点，谈恋爱是要排在哪一格」 | 9/12 | 4 种 |
| C 情境绑定型（理由挂在具体的事上） | 「刚才还主人呢，现在又降级成老公了，你这称呼一天换三回」 | **4/12** | **7 种** |

**判据不是"整句具体不具体"，而是：这句里有没有一个"搬得走的泛化结论"。**

⚠️ **两条轴别互相抵消**：本土化去掉的是**时间锚点**（「明天要搬家」→「她一贯会拖」），不是情境锚点。

### 模板

```json
{
  "name": "被说以后不行时",
  "trigger": "<这个大情景的泛化描述>",
  "response": "<反应骨架：先做什么、再做什么，不带任何台词>",
  "samples": [ "<3~5 条，话题必须互不相同>" ],
  "evidence": [ "<来源：哪场直播、哪一段>" ]
}
```

**`trigger`** —— 写泛化的大情景，不写具体话题。
判定：`trigger` 里若出现某个具体话题的名词（直播、热度、粉丝），就是写窄了。
例：「有人判她这件事以后肯定不行——做不长、会散、会被忘记、会失去什么」。

**`response`** —— 写反应骨架，**不写台词**。两条必须遵守：
1. **不带任何引号里的词**（带词的措辞会被原样搬走）。
2. **必须写"不举例子、不提具体的事"**——不写这句模型会编事实（实测编造率 2/5 → 0/5）。

**`samples`** —— 3~5 条，**话题必须互不相同**（最要紧一条）。收集时不是"同一件事找 5 种说法"，而是**"同一类情景找 5 件不同的事"**。
- **前 2 条兼任 L3 分类器路标**（`routing.py` 只取 `samples[:2].user`）→ 必须是用户最可能怎么说出这个情景的真实话。
- **写完必查撞车**（`check_collision.py`，见 §2）；发现撞车**改样本，不改用例**。

### 一条完整的合格样例

```json
{
  "name": "被说以后不行时",
  "trigger": "有人判她这件事以后肯定不行——做不长、会散、会被忘记、会失去什么",
  "response": "不否认、不嘴硬顶回去。先承认，但是说起现在的情况，最后用一句自嘲或不在乎收掉。只说状态，不举例子、不提具体的日子/几点/做过什么事。",
  "samples": [
    {"user": "你这直播以后肯定没人看了", "reply": "没人看就没人看呗，反正灰泽满也没指着这个活。"},
    {"user": "你迟早会不想播了吧", "reply": "迟早的事。真到那天就不播了，现在不还在这儿嘛。"},
    {"user": "等你毕业了肯定就把我们忘了", "reply": "忘不忘的，灰泽满现在还没毕业呢。想那么远干嘛。"},
    {"user": "你这种东西过两年就没人记得了", "reply": "不记得就不记得，灰泽满又不是为了被记住才做的。"}
  ]
}
```

### 从直播素材里怎么分出这些内容

"从直播里认出情景"这一步**目前没有可靠工具**（纯致谢占大半，关键词筛出来的候选噪声极大）。建议流程：**人工先标注、再提取**——不要一上来就让模型自己"提炼情景"（会产出一堆无法验证的抽象标签）。

第 1 步的标注判据（一条话轮值不值得进 behaviors）：

| 收 | 不收 |
|---|---|
| 她在应对某类人际情境（被夸、被质疑、被越界、被真心戳中…） | 她在陈述事实（今天做了什么、吃了什么） |
| 这个反应换个人问也会一样 | 只对当时那个人/那件事成立 |
| 能说出"这是什么情景" | 说不出情景，只能说"她说了句话" |

## 4. 改人格与事实文件：改哪个、改完跑什么

**先判这条内容属于哪一类**（判据见 `架构.md`）：说「她怎么说话 / 遇什么情境怎么反应」→ 人格层；说「她知道某个词/某件事/某个偏好」→ 事实层。
**任何一条内容只有三种归宿**：① 对每轮都生效的说话习惯 → **骨架** `core/system_prompt.txt`；② 只在某类处境下出现 → **behaviors**；③ 事实 / 词义 / 固定应答 → **数据**（schedule / terms / corpus / legendary）。**"第三个文件"不存在。**

| 改什么 | 动哪个文件 | 改完要跑什么 |
|---|---|---|
| 她怎么说话 / 遇情境怎么反应 | `persona/core/system_prompt.txt`（骨架）、`persona/behavior/behaviors.json` | **重启 bot**（behaviors **不走向量**，无需重算） |
| 直播记忆（事实层 corpus） | `persona/world/statement_final.json` | `run_tool.py generate-vectors -i persona/world/statement_final.json` → `corpus_vectors.json`，再重启 |
| 核心记忆 | `persona/world/core_stories.json` | `run_tool.py precompute core-stories` → `core_story_vectors.json` |
| 偏好 | `persona/world/preferences.json` | **只改 keywords，不重算向量**（判据走子串命中） |
| 懂词 / 梗 / 人物 | `persona/world/terms.json`、`legendary.json` | 重启（关键词 / 正则触发，不走向量） |
| corpus 的"用户会怎么问" | `persona/world/corpus_keywords.json`（钩子） | 合并式，手补不会被重跑覆盖；补完记进 `_readme` |
| 检索该不该命中 / 权重 | `src/plugins/chatbot/retrieval.py`、`constants.py` 的 `SOURCE_WEIGHTS` | `run_tool.py retrieval-eval`（**改语料会洗牌排名**）+ `regression --check` |
| 周表 | 根目录 `更新周表.bat`（拖图 OCR） | 重启 |
| 新表情包 | `assets/stickers/` → `label_stickers.py` → 人工补 `group` | 重启 |
| 记忆（长期卡格式） | `memory_manager.py` + `constants.py` | `pytest tests/test_memory.py` |
| 语音 | `voice.py` | `pytest tests/test_voice.py` |
| 群聊接不接话 | `group_gate.py` / `constants.GROUP_GATE` | 重启 |

⚠️ **黄金律 5**：改 `core_stories` / `statement_final` / `preferences` 后要重算对应向量——**但 `preferences` 现在只走 keywords，不走向量**；`behaviors` / `terms` / `legendary` 也不走向量。别照抄旧说明去跑已停用的 `precompute` 目标。
⚠️ **改完必须重启 bot**（有进程内缓存）。

## 5. 看到一条答得不对：问题驱动

**你只做一件事：把"这条答得不对"记下来。** 变成用例是工具的活。
入口：`python scripts/run_tool.py problems`（实现 `scripts/problem_cases.py`）。
⚠️ **没有"人工标注"这个动作**——`scripts/retrieval_eval_cases.json` 里那 48 条是**已有资产**，平时不用标。

### 三条入口

| 你想干什么 | 用哪条 |
|---|---|
| 平时聊天看到答得不对 | **随手记**（A） |
| 想主动抽查她最近答得怎么样 | **抽查**（B） |
| 想复核**已有用例**里有没有标错的 | **复核**（C，⚠️ 老用例是人手工定的，可能有错） |

### A · 随手记（最常用）

**第 1 步**：打开根目录 `问题记录.md`，最下面写三行（格式随意）：

```
用户说：你多高啊
她答：灰泽满大概一米七吧
应该是：该想起身高那条（她说自己1米6）
```

**第 2 步**：

```bash
python scripts/run_tool.py problems --from-note
```

**第 3 步**：屏幕给两样东西——① 这句话**实际召回了什么**（各类素材逐条列，带原文）② 一条**草案**。

**第 4 步**：看实况决定：
- 草案不对 → 回 `问题记录.md` 补一行再跑：
  `该中：corpus:1米6` / `不该中：behavior` / `层：检索`（检索 / 生成；不写会替你猜）/ `禁词：搬家,搬东西`（生成层专用）
- 草案对 → 加 `--write` 写进去：`run_tool.py problems --from-note --write`（同样 query 不重复写）

**第 5 步（别跳）**：确认新用例**是红的**：

```bash
python scripts/run_tool.py retrieval-eval --case <上一步打印的 id>
```

- **红 = 好**：它真的复现了你看到的问题 ✅ 这时才去改素材。
- **绿 = 白加**：判据没抓住问题 → 回第 4 步改判据。（本项目踩过的坑：**合成场景自测 8/8，一上真实数据就崩**，绿的用例给的是假信心。）

### B · 抽查（主动找问题）

```bash
python scripts/spot_check.py                 # 自动挑出最可疑的几条 → outputs/spot_check.md
python scripts/run_tool.py problems --from-spot   # 读勾了「有」的条目，后面同 A 的第 3~5 步
```

打开 `outputs/spot_check.md`，每条后面把 `[ ] 有` 改成 `[x] 有：为什么不对`。每条带一个 `t=` 是定位用的唯一键，**别手改**。

### C · 复核已有用例

```bash
python scripts/run_tool.py problems --audit
```

它读**最近一次评测报告**（`outputs/eval/retrieval/eval_report.json`），把用例按「最可能标错」排序（当前失败 → 边界 → 老标注），每条问「认可这条期望吗？[回车=认可 / s=有问题 / q=退出]」。标 `s` 的写进 `问题记录.md`（复用 A 的通道）。
**没有评测报告它会让你先跑一次评测**（"实测结果"是复核的主要依据）。

### 用例落定后去哪里改

| 问题出在 | 去改 |
|---|---|
| 该想起某段经历却没想起 / 想起了不该想的 | 检索层：`persona/world/*.json`（corpus 是 `statement_final.json`）；入口不够先看 `python scripts/entry_audit.py all` |
| 用户的说法勾不出那条素材 | `persona/world/corpus_keywords.json` 的钩子（合并式，手补不覆盖） |
| 她话说错了（用旧事当现在 / 复读 / 客服腔） | 生成层：`persona/behavior/behaviors.json`、`persona/core/system_prompt.txt` |
| 想知道整条链上到底哪一步出了问题 | `python scripts/trace_chain.py "那句话" --reply` |

### 常见疑问

- **一条问题会变成几条用例？** 看它属于哪层：**检索层**进 `retrieval_eval_cases.json`，**生成层**进 `regression_cases.json`。一条只进一个文件（`层：` 那行说了算）。
- **生成层用例贵吗？** 贵。一条 ≈ `跑次` × 4~8 次 LLM 调用。`跑次` 默认 3，加之前先单跑一条：`run_tool.py regression --check --case <id>`。

## 6. 抽查她的回复

**用途**：抽查她的回复时，对着这张表看，而不是凭感觉。
**来源**：CharacterEval（ACL 2024 中文角色扮演评测基准）的 13 项指标，翻成人话。

推荐用 `spot_check.py` 自动挑（见 §5 B），只回答是/否；下表是"看什么"的标准。

### A. 对话能力（像不像"在聊天"）

| # | 检查什么 | 怎么算不合格 |
|---|---|---|
| A1 | 说不说得通 | 句子通顺、没有语病或拼接痕迹 |
| A2 | 接不接得上 | 是否针对用户刚说的事？有没有答非所问 |
| A3 | 前后矛不矛盾 | 前面说过的事，这句有没有自己打自己脸（**事实层面**，不是态度变化） |

### B. 角色一致性（像不像"她"）★ 最重要

| # | 检查什么 | 怎么算不合格 |
|---|---|---|
| B1 | 知识准确 | 她说的关于自己的事，是对的吗（身高/室友/作息/喜好…） |
| B2 | **知识幻觉** ★ | **她编了吗**——说了一件根本没经历过的事，或把某次的事当成"现在" |
| B3 | 人物行为 | 该嘴硬时嘴硬了吗？该认怂时认怂了吗？（不是"合理"，是"像她"） |
| B4 | 说话风格 | 自称对吗（hzm/灰泽满）？句长对吗？语气词用法像吗？ |

> ⚠️ **B2 是这套系统最容易出的问题**："想起错的"比"想不起来"伤害大。判据：**这件事她有依据吗？** 没依据还说得斩钉截铁 = 幻觉。

### C. 角色吸引力（像不像"一个有意思的人"）

| # | 检查什么 | 怎么算不合格 |
|---|---|---|
| C1 | 像真人 | 是不是"AI 在扮演"，有没有咨询师腔/客服腔/助手腔 |
| C2 | 沟通技巧 | 有没有把话聊下去（反问/自嘲/延伸），还是干巴巴答完就停 |
| C3 | 表达多样 | 有没有反复用同一个词/句式开头（复读感） |
| C4 | 共情 | 用户诉苦/撒娇时，反应对得上情绪吗 |

### D. 人格回溯（内在一致）

| # | 检查什么 |
|---|---|
| D1 | 她的立场稳不稳——同一件事，答案是否在合理范围内波动 |
| D2 | 她的"人设"有没有漂——有没有突然特别温柔/热情/配合（不像她） |

### 怎么用最省事

1. **先只看 B2（知识幻觉）**——最伤、最容易一眼看出；
2. 再看 **B3/B4（行为/风格像不像她）**；
3. 剩下的扫一眼。

记录一句话就够，攒够 20~30 条，哪类问题最多就是下一步的目标。

### 已知的"高发区"

| 高发区 | 为什么 | 看哪项 |
|---|---|---|
| 用旧记忆回答当下 | 素材携带具体情境会被当"现在"复用（"搬家"那个坑） | B2 |
| 想起错的 | corpus 召回判错 / 素材含具体措辞被照搬 | B2 |
| 复读 | 同一话题反复问时，可能把上轮那句原样搬出来 | C3 |
| "刚说过了" | assistant turn 的样本被当成"刚发生过的对话" | B1/B3 |
| 编偏好 | 偏好档案没覆盖的话题，她会现场编一个立场（且不进记忆） | B2/D1 |
| 大量轮次没有任何素材 | 只能靠骨架答 → 容易变成"遵守规则的人"而不是"她" | B3/B4/C1 |
