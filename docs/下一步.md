## 1. 群聊：代码注入 + 提示词一起改

### 目标

- 接话时**知道大家在聊什么**、接在**同一条线**上；
- 不再出现「没点灰泽满名字，灰泽满不回复」这类元回复。

### 索引（改哪）

| 要做 | 文件 | 函数 / 位置 |
|---|---|---|
| 攒批、群 transcript、点名情况 | `src/plugins/chatbot/chat_window.py` | `_flush` 群分支（约 288–351） |
| 批归纳 | `src/plugins/chatbot/core.py` | `summarize_batch`（约 115） |
| 消息组装 / 群块注入 | `src/plugins/chatbot/core.py` | `build_message_list`（约 404、465–472） |
| 群聊主循环 | `src/plugins/chatbot/core.py` | `handle_chat`（约 1056–1071、1264） |
| 接话门 | `src/plugins/chatbot/group_gate.py` | `should_reply_in_group` |
| 群块文案 | `persona/injection/06_group/block.json` | `strings.main` / `strings.address_note` |
| 短期历史落盘 | `src/plugins/chatbot/memory.py` | `append_user_history` / `get_user_history` |

### 步骤

**A. 不再注入“无人点名”（先做，去掉元回复的根）**
1. `_flush`：只有 `batch_addressed` 为真时才构造 `group_address_note`；未点名传空串。
2. `build_message_list`：`group_address_note` 为空就不注入。
3. `06_group/block.json`：`address_note` 只保留正向文案：
   `【有人在跟你说话】{note}（内部信息，不要在回复里提到它）`。
4. `strings.main` 加一句：不要提“点名/没点名/被@/潜水/说不说”；安静由接话门决定。

**B. 群块 main 改写**
- 从“点名或 @ 才是直接跟她说；其余是群友互聊”改成：
  “这是多人群聊。有人直接问你，就正面回；没人直接问，也可以顺着话题接一句。不用声明自己在不在被点名。”
- 保留“群里同时有好几个绿冻，别把别人的话算到她头上”。

**C. 批归纳带发言人 / 对话线**
- 新函数 `summarize_group_batch(items)`（`core.py`），输入 `(昵称, 文本, 图片描述)`；
- 输出 1–3 句：谁在对谁说什么、这批有几条线、最后停在什么话头上；
- `_flush` 用它替换现在的 `summarize_batch([(t, imgs)])`，结果作为 `group_thread_note`；
- `build_message_list` 新增参数 `group_thread_note`，在群块后注入 `【群聊对话线】{note}`。

**D. 前情 + 群历史格式**
- `_flush` 取本批之前最近 6–8 行（`get_user_history(群号)[-8:]`），作为 `group_pre_context`；
- `build_message_list` 注入 `【群聊前文】`（放在 `【最近对话记录】` 前）；
- `append_user_history` 群聊落盘改成 `群聊：A：…` / `灰泽满（回 A）：…`；
- `get_user_history` 的“谁说的”判断兼容 `群聊：` 前缀（`reply_style` / `core.recent_bot` 也要看）。

**E. 接话门拿到对话线**
- `should_reply_in_group(client, history, batch, thread_note="")`；
- 提示词在 `【群里刚才聊的】/【刚安静下来的一批】` 之前加 `【对话线】{thread_note}`；
- 判据不变，只补上下文。

### 验收

- 20 批真实群聊（从 `data/chat_log/*.jsonl` 挑 ≥3 人发言的批次）；
- 指标：
  - 元回复（“没点我/潜水/不回复”）**0 条**；
  - 接话在同一话题 **≥70%**（人工 0/1）；
  - 该接没接率**不上升**；
  - 私聊回归不受影响。
- 命令：`pytest -q`、`run_tool regression --check`、`run_tool retrieval-eval`。
- 回滚：`GROUP_GATE=0` 只关接话门；`06_group` 可单独回退文案。

### 待定

- 群历史窗口 10 行还是 16 行；前情块与最近记录是否重复；
- 归纳升级的延迟（每批已有归纳 + 接话门两次调用）；
- 她的回复记“回的是谁”会改历史格式，需要回归。

## 2. 长期记忆里的名字：5 轮内出现过就前置提醒

### 索引（改哪）

| 要做 | 文件 | 函数 / 位置 |
|---|---|---|
| 名字预算提示 | `src/plugins/chatbot/core.py` | 新增 `name_budget_note(user_id)` |
| 注入 | `src/plugins/chatbot/core.py` | `build_message_list`（profile 之后） |
| 文案 | `persona/injection/03_profile/block.json` | 新增 `strings.name_budget` |
| 现有守卫 | `src/plugins/chatbot/core.py` | `starts_with_name` 那段（约 1178） |

### 步骤

1. `name_budget_note(user_id)`：
   - `name = _user_name_for(user_id)`，空则返回空串；
   - 取 `get_user_history(user_id)[-10:]`（5 轮），**只统计 `灰泽满：` 开头的 bot 行**里出现 name 的次数；
   - 达到阈值返回：`【称呼】最近 5 轮里已经叫过他「{name}」{n} 次，这轮尽量别再叫名字，直接说事。`
2. `build_message_list` 增加 `name_budget` 参数，在 `profile_context` 之后注入。
3. 阈值三档 A/B：5 轮内 ≥1 次 / ≥2 次 / 最近 2 条 bot 回复里出现。
4. 现有 `starts_with_name` 守卫保留；若前置提醒不够，把回看窗口从 2 条放宽到 5 条。

### 验收

- 20 条真实私聊（历史里名字出现过），三档 + 基线；
- 指标：名字使用率、名字开头率、是否出现“整段完全不称呼”的僵硬回复；
- 目标：名字使用率相对基线降 50% 以上，群聊不受影响。

### 待定

- 统计只算 bot 行（建议）还是连用户消息里提到的名字也算；
- 提醒用“不要再叫”还是“这轮尽量别叫”，后者更软。
