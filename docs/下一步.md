# 第一部分 · 本项目：一条回复是被什么决定的

## 1.0 一句话链路

```
QQ 消息
 → __init__._handle_chat（过滤/权限）
 → chat_window.enqueue（进窗口）
 → 读秒窗口：攒批 / 插话取消
 → chat_window._flush（读图 + 归纳 + 接话门）
 → core.handle_chat（检索 → 组装 21 段注入 → 生成）
 → core.generate_reply（走降级链）
 → clean_reply → 名字替换 → split_reply / voice
 → 发送 + 写短期记忆 + 写聊天日志
```

## 1.1 入口与攒批（`chat_window.py`）

- **窗口按会话开**（私聊=QQ 号，群聊=群号），不是按消息。新消息进来 → `pending` 追加 → 重置读秒定时器。
- **去抖**：连续消息在窗口内合并成一批；窗口内又有新消息 → 取消正在进行的 `_process`（代际号判断），
  重新起跑。踩坑记录在 `_flush` 的注释里（旧代码取走 pending 后取消会静默丢消息）。
- **读图**：本批**所有**图片在建上下文前统一解析（不是收到就解析，避免节奏割裂）。
  视觉模型：`get_vision_client()` → 辅助链端点（traxnode）`gemini-2.5-flash-lite`。
  输出第一行是类型标签 `[表情包]/[截图]/[照片]/[文档]/[其他]`，认出是她本人会写成 `[表情包·灰泽满本人]`。
- **图片进用户消息的三种形态**（`_image_note`，2026-10-30 起）：
  - 纯图 / 文字≤4字非问句 / 文字明确指图 → **完整描述** `[图片：…]`；
  - 文字 + 普通表情包 → **只带情绪词的短标签** `[表情包：无奈]`（描述里的名词不进用户消息，防"评价虫子"翻车）；
  - 图里是灰泽满本人 → **完整描述不压缩**（那种图本来就在聊她）。
- **私聊 transcript**：文本行 + 图片行按原顺序内联。
- **群聊 transcript**：`昵称：文本 [图片：…]`；同时算出：
  - `batch_addressed`（确定性点名判定：@ / 引用她 / 直呼名字）；
  - `group_thread_note`（`summarize_group_batch` → 谁在对谁说、几条线、停在哪句）；
  - `group_address_note`（**只有点名时**才有值；未点名时什么都不注，防元回复）。
- **接话门**（仅群聊）：`group_gate.should_reply_in_group`（辅助链模型），不接 → 只记用户侧、不发。
- 结果交给 `core.handle_chat(user_id, combined, vision_desc, batch_summary, user_transcript, …)`。

### 检索四路（`core.handle_chat` 里按顺序）

1. **会话记忆 probe**（`session_memory.probe_session`）：判"话题延续/切换"、把短 query 扩写成检索用句、
   产出 `mood`（用户此刻情绪）、`events`、`entities`（作品/作者/地点/动物）。
   → 影响 `session`、`query_hint`、`mood`、`same_request`。
2. **L3 行为分类**（`routing.classify_l3`）：拿用户这句在 17 条 behaviors 里判"这是哪种情景"，
   顺带数"连续索要第几轮"。→ `behaviors` + `same_request`。
3. **corpus 检索（直播记忆）**：两路召回（向量 + 关键词/钩子）→ RRF 融合 → `corpus_judge.judge_corpus`
   再判一次"用户是不是在问她这段经历"（宁可漏不可错）。→ `corpus`。
4. **偏好 / 核心记忆**：preference 走 keywords 子串（不走向量）；core_stories 走向量。→ `preference`、`core_story`。

### 记忆（`memory_v2`，长期）+ 短期

- **长期**：类型化条目（fact / request / habit / ritual / commitment…），按 `status`（confirmed/active/superseded）
  与 `expires_at` 过滤。注入路径有：`request`（长期请求）、`interaction_preference`（相处方式）、
  `commitment`（未完成约定）、`daily`（今天日常）、`habit`（个人习惯）、`nickname_hint`（外号）、
  `name_budget`（称呼预算）。
- **习惯注入**（`build_habit_hint`）：只对**有这条记忆的用户**出现；按"作息/互动、频率、时段、线索"判断；
  早间问候有专用文案（"这轮先顺口问他一句今天还照不照常"）；最近几轮她已提过 → 这轮不再提示。
  ⚠️ 开 `INJECTION_V3=1` 之后，习惯被并进【本轮提醒】(`reminders`)，不再有独立 `habit_hint` 块。
- **短期**：`user_memory/short_term/<session>.json`，最多 10 行（最近 5 轮），
  行格式 `用户：…` / `灰泽满：…`（群聊 `群聊：甲：…` / `灰泽满（回甲）：…`）。
  **注入前先转述**：`self_speech.annotate_turn` 把她的原话压成 `灰泽满（转述）：<一句话事实>`，
  缓存 `data/self_speech_cache.json`；目的是不让她从历史里学自己的句式。

### 术语与消歧

- `core.build_terms_note(user_msg)`：`priority=always` 每轮注；其余按 keyword/别名/正则命中才注。
- 命中歧义词时 `core.confirm_ambiguous_terms` 再用一次 LLM 判"这个词在当前语境是不是那个意思"（tag `术语消歧`）。

### 感知

- `context_probe.frame_now`（日期/星期/是否在播）、`session_time_hint`（本场时段）、
  天气/城市（从记忆里的 location 取）、`daily`（今天的日常记忆）。

## 1.3 组装顺序与"缓存前缀纪律"

`core.build_message_list` 把上面这些按固定顺序 append 成 **一串 system 消息**，最后一条是 user：

```
骨架 → 场景 → 周表 → 相处方式 → 称呼预算 → 长期请求 → 偏好 → 核心记忆
→ 群块 → 对话线 → 点名 → 名词库 → 关联背景
→ 会话记忆 → 上次聊过 → 行为 → corpus → 约定
→ 最近对话 → 连续索要 → 批次 → 短句语境
→ 日期/时刻 → 本场时段 → 情绪 → 外号 → 日常 → 习惯
→ （v3）本轮提醒：把"约定/习惯/称呼预算/外号"并成一条，放在用户消息前
→ selfref（"需要自称就用灰泽满"这句收尾约束）
→ user
```

**为什么这个顺序**：前缀尽量稳定（骨架、名词库、周表在前），每轮变化的东西（情绪、批次、现在）往后放，
这样 deepseek 的前缀缓存能吃到 80%+。**改顺序等于改缓存命中率**。

## 1.4 生成与后处理

- **模型**：主链 `apigoto deepseek-flash` → 失败降级 `u-ai gemini-3.1-flash-lite` → `deepseek 官方`。
  辅助链（话题探测/接话门/记忆提取等）：`traxnode gemini-2.5-lite` → 同两级兜底。
- **参数**：temperature 0.85、frequency_penalty 0.3、max_tokens 150、`THINKING_DISABLED`（关思考）。
- **工具轮**：`tool_loop.generate_with_tools`（`RECALL_TOOLS=1` 时，模型可主动调 `recall` 取记忆）。
- **`clean_reply`（确定性兜底）**：换行归一、去开头括号/说话人标注、至多 1 个括号、省略号纪律、
  结巴消融、第三人称自指兜底（"她/他"→删）。
- **名字替换**（2026-10-30）：回复里第一处**安全的"你"**换成对方要的名字（排除引号/括号、你们/你好/你俩、"迷你"），
  默认 100%；只在私聊、且 `name_budget_note` 说"最近叫太多"时跳过。
- **拆分**：`split_reply` 按逗号分段（两边≥5字才切、问号不动、语气词并句），段间按字数算打字延迟。
- **语音**：`should_voice` → `_synthesize`（参考音频池 + 重试轮换；静音门峰值<1000、总长<期望70% 改发文字）。

## 1.5 写回与持久化

- `memory.append_user_history` 写短期记忆（私聊原文；群聊带点名者）。
- `memory_v2.extract_and_ingest`（异步）：从这一轮抽名字/事实/偏好/请求写长期记忆（有前置闸门）。
- `chatlog.log_turn` 写 `data/chat_log/<session>.jsonl`（user/reply/images 数）。
- `data/injection_trace.jsonl`：这一轮**注入了哪些块、块里的值**（`blocks` / `values` / `items`）——排查"她为什么这么说"的第一入口。
- `data/llm_usage.jsonl`：每次调用的 model/layer/tag/route/prompt/hit/miss/output/ms。

## 1.6 成本与缓存

- 主回复一次输入约 3,000 token；注入顺序决定前缀稳定度；deepseek 命中 84% → 单条主回复约 946 积分。
- 辅助调用 4 次/轮左右；`data/llm_usage.jsonl` + `scripts/llm_cost.py` 可按通道/模型/层分账。

# 第二部分 · DeepSeek Harness / 大肥鱼：它的回复是被什么决定的

> 来源：`Derpyu520/qq-bridge`（★3.3k）、`accomplish07zrh-eng/dsh-aurabot-qq`（★173）、
> `tencent-connect/dsh-qqbot`（官方插件，★453）、`xmanrui/dsh-im`（★2.8k）。
> **以下全部是 README/preset 文件的描述，未读源码。**

## 2.1 总体架构

```
QQ ── SnowLuma（OneBot v11 WS + HTTP）── 桥接/插件（Node.js）
   ── DSH Web/api（DeepSeek Harness，本机 3080）
   ── agent preset（qq-chat / qq-chat-v2 / aurabot-private / aurabot-social）
   ── MCP 工具（QQ 安全子集、联网搜索）
   ── 回复 → 桥接 → QQ
```

- **每个 QQ 会话 = 一个独立的 DSH 会话**（私聊/群各一个），映射持久化在 `state/sessions.json`。
- 模型按会话固定：`dsh.model`（默认 `deepseek-flash` = DeepSeek-V4-Flash，多模态），
  可配置 `reasoningEffort`（默认 max，可选 high/low）。
- 人格/行为**不是**每轮拼一整串注入块，而是**三层**：preset 的 persona 段（行为规则）+ 角色卡（人设）+ 会话初始提示词。

## 2.2 人格与角色的注入方式（和本项目最大的差别）

1. **preset 的 persona（`@deepseek-ai/dsh-persona`）**：写在 `agent.cordis.yml` 的 `prefix` 里，
   内容是**QQ 场景规则**而非人设——安全边界、回复长度（3~5 句）、禁 Markdown、@/引用怎么判、
   图片怎么看、什么时候该搜索、**禁止汇报自己做了什么**。
2. **角色卡（role）**：`state/current-role.json` 由控制台设置，桥接**每条消息注入**【角色扮演】标记，
   群友无法改。仓库自带 `roles/傲娇助手.md`、`roles/小鲸鱼.md` 这类角色文件。
3. **会话初始提示词**（二代仿真）：给某个群/私聊预写一段环境说明（圈子主题、群内氛围、常见话题、忌讳），
   AI **只在该会话第一次唤醒时收到一次**，之后就在会话上下文里不再重复注入；会话重置后重来。

> 也就是说：**它靠"会话自带的上下文"记住说过的话，靠"角色卡"决定人设，靠"preset"决定行为规则**；
> 本项目靠"每轮重新组装的 21 段注入"。

## 2.3 每轮上下文（桥接交给 DSH 的东西）

- **消息正文**：QQ 文本；**图片/表情（含动图 GIF）** 直接附带在消息上下文里（走 QQ CDN 直链，
  `get_image` 失败用 `emoji_id` 推 CDN，单条上限 8MB/64MP/5 张）。
- **引用/回复**：解析成 `[引用 某人：原文]` 注入，AI 先判断"这句是对谁说的"；
  引用机器人自己 → 视为必回。
- **群聊分段**：群里停顿几秒算一段；她回上一段时新消息先攒着，看完整段再回（不会一条一回）。
  交给她的是一段里"谁说了什么 + 之前在聊什么"，**新消息带编号**，想接某条可引用回复。
- **合并转发**：展开成里面的聊天记录再给她。
- **拍一拍**：当成对她说的话，她也能戳回去。

## 2.4 记忆（aurabot 版，最接近本项目"检索"的一层）

- **本地索引记忆库**：中文二元切词 + **BM25** 检索，再按"关于当前说话人""重要程度""遗忘曲线"加权
  （越常被想起的忘得越慢）。
- **来源**：她自己记的、每天两次从聊天和空间动态里整理、她自己的经历（唱了什么、评论了谁）、
  空间日记、你手动加的。
- **新旧事实处理**：新事实先和旧记忆比对——补充就合并，旧的过时就把旧的标成"已过时"（**不删，可恢复**）。
- **常驻结构**：每个人一张"人物小档案"；每个人/群还有"相处经验"和"说话方式"。
- **想起的记忆带时间**；对方只说"嗯嗯"时连上一句一起想；面板能看到最近几轮想起了哪几条。
- **心情**：默认按关键词、可选每轮模型判；被夸/被凶会推动心情，按半衰期回到平常；
  心情明显时每轮告诉她该怎么说话，并**实际影响**发表情/语音的概率、回复快慢、插话积极程度。
- **注入位置**：心情与记忆走 `agent.ctx.systemPrompt.context()`，**追加在对话末尾**，不破坏前缀缓存
  （与本项目"变化的放后面"是同一条思路）。

## 2.5 工具与 agent loop

- QQ 工具是 **MCP server** 提供的**安全子集**：查状态/查群/查消息/发消息（发送白名单），
  可选 `replyToMessageId`；另有 `qq_reply` 专用引用回复工具。
- 联网：`mcp__web-search-safe__`（防 SSRF），**搜索优先复用 DeepSeek 自己的联网搜索**，
  Bing 只在 DeepSeek 不可用时兜底；可连续搜 2~3 步再回。
- 工具审批/提问会转发到 QQ（回复"通过/拒绝"即可决策）。
- preset 里**没有本地工具**（无 bash/文件读写），这是硬边界；`qq-tool-restrict` 在执行期再拒一次白名单外的调用。

## 2.6 上下文管理

- `@deepseek-ai/dsh-compaction-basic`（长聊压缩）+ `tool-result-pruner`（工具结果超 50k 字符就裁头留尾）。
- 会话切换/重置：`/reset` 清上下文；会话映射可重置。
- token 账本：可按群/好友/每轮下钻，区分高峰/空闲价，带 24h/3d/7d/30d 走势。

## 2.7 运行模式（行为策略，不是提示词）

| 模式 | 行为 |
|---|---|
| `chat` | 白名单群/私聊 → 安全聊天 |
| `closed-agent` | 仅 owner 私聊 → 完整工具，可在 QQ 上操控 DSH |
| `reserved`（一代仿真） | 仿真群友：观望/活跃/试探/退场状态机；选择性参与；按空格分句；`[SILENT]` 表示潜水；主动收尾 |
| `reserved2`（二代仿真） | 文本不自动转发，AI 用 `qq_get_unread_messages` / `qq_send_message` 自己看消息、发言、等待、设唤醒/潜水 |

## 2.8 与本项目最值得对照的五个点

1. **上下文来源**：它 = 会话历史 + 角色卡 + 少量"记忆/心情"追加；本项目 = 每轮重组的 21 段检索注入。
2. **人格位置**：它把行为规则放 preset `prefix`（稳定），人设放角色卡（每条消息一个标记）；
   本项目把两者都放每轮注入，靠顺序保证缓存。
3. **记忆检索**：它 BM25 + 时间/重要度/遗忘曲线 + "关于当前说话人"加权，有"人物小档案"；
   本项目是 向量+关键词 RRF + 二次 LLM 判定 + 类型化条目（fact/request/habit/ritual…）。
4. **群聊**：它靠"停顿分段 + 新消息编号 + 引用解析 + 必回/相关度插话"；本项目靠"读秒窗口攒批 + 点名判定 + 对话线归纳 + 接话门"。
5. **主动性**：它有"主动收尾/等待/潜水"状态机与心情驱动；本项目有主动发言（动态→私聊）与习惯提醒。
