（`system_prompt` + 周表 ≈ 2176 token），**第 3 块起每轮都变**（检索/记忆/profile 全按当轮
query 现算）→ 主回复命中率结构性封顶在 **62~70%**（检索固定不变时能到 94%）。
所以**重排块序没有收益**（能救的早救了），想再往上只有三条路——**这是个产品决策，等你拍**：

| 选项 | 收益 | 代价 |

### B. 名字（私聊里"每句都叫名字"）

现状：**正反馈环已断**（`starts_with_name` + 重生成），存量重复也清了（`memory-dedupe`）。
**还没做的**：
- **降低"可用性"**：把 `preferred_name` 从 `_ALWAYS_ON_FACT_KEYS` 里拿掉 —— 现在是**每轮都注入**，
  等于每轮提醒她"这有个名字可以用"。改成只在**话题相关**时注入，频率天然就下来，**不用写规则**。
- 用户 2026-10-11 提的另一个方向：**"你"→名字的确定性替换**。⚠️ 不能字面做：中文里名字是**呼语**
  不是主语（"草草子哥在干嘛"读起来像在说他），而且"你"会撞词（你们/迷你）。要做只能做成
  "**偶尔在分句边界插一个呼语**"，且限频。**未定，先别动**。
- 要做**正向引导**（"只在有情绪/要拉近时才叫"）的话：**别写规则句，改成"用样本教"**。
  理由：上一次的**正向指令**（v1 那句"这个绿冻叫X，聊天时用TA的名字称呼TA"）就是这场
  100% 名字开头的起点——再写一条正向规则，大概率同一个坑（黄金律 1：样本 > 规则）。
  做法：在**情绪类情景的 samples 里**让名字自然出现（比如"对方难过时"那 5 条里放 1-2 条
  以名字起手、其余不带），**同情景内有/无对照** → 模型学到的是"这种时刻**可以**叫名字"，
  而不是"每句都该叫"。
