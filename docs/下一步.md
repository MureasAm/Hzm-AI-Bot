## 一、知识关联层：作品名 → 作者 → 喜好

### 目标

用户只报作品名（如《空中杀人现场》）时，模型能沿“作品 → 作者 → 她的喜好/态度”自己接上；**不逐本收书、不逐条写特例**。

### 数据：`07_terms/associations.json`

只存**实体别名 + 边**，不复制事实/态度：

```json
{
  "entities": {
    "空中杀人现场": {"kind": "work", "aliases": ["空中杀人事件", "殺人現場は雲の上"]},
    "东野圭吾": {"kind": "author", "aliases": ["东野"]},
    "袋鼠": {"kind": "animal", "aliases": ["kangaroo"]},
    "澳洲": {"kind": "place", "aliases": ["澳大利亚", "袋鼠国"]}
  },
  "edges": [
    {"from": "空中杀人现场", "to": "东野圭吾", "rel": "written_by"},
    {"from": "东野圭吾", "to": "preference:author", "rel": "has_preference"},
    {"from": "东野圭吾", "to": "空中杀人现场", "rel": "representative_work"},
    {"from": "袋鼠", "to": "澳洲", "rel": "located_in"},
    {"from": "袋鼠", "to": "term:袋鼠", "rel": "has_term"}
  ]
}
```

- 事实仍放 `07_terms`，态度仍放 `04_preferences`，边只存 id/关系。
- 新增书/地点只加实体和边，不改代码。

### 触发：不是 terms 的关键词匹配

`07_terms` 原本只按 keyword/别名在用户消息里做子串/正则命中；**关联背景不靠它**，单独走 `associations_note()`：

1. **已知实体**：用 `associations.json` 的别名做子串匹配；
2. **未知作品**：话题探测新增 `entities` 字段（每轮已有一次模型调用，不额外加），让模型给出“书/作者/地点/动物”；识别到作者后走作者的边；
3. 拿到实体后沿边走 **最多 2 跳、最多 3 个实体、约 300 字**，优先“作者态度 + 2 本代表作品”；
4. 识别不到 → 不加任何东西。

### 注入

- `handle_chat` 把 `entities` 和 `associations_note()` 的结果传给 `build_message_list`；
- 在【名词库】之后注入一段【关联背景】，段头文案放 `07_terms/block.json` 的 `strings.associations`；
- 不新增第 20 个块、不改现有 19 个块的序号。

### 验收

- `retrieval-eval`：
  - `空中杀人事件`（用户实际说法）→ 命中《空中杀人现场》+ 东野 + `author` 偏好；
  - `东野` / `东野圭吾` → `author` 偏好；
  - `袋鼠` → 袋鼠词条；`澳洲` → 地点/常识。
- 生成抽查：
  - `怎么看《空中杀人现场》` → 不应再说“那部电影”，应能说出是小说/短篇集并带她的态度；
  - `你在澳洲见过袋鼠吗` → 能用真实常识接，不编“我打过袋鼠”这种亲身经历。
- 反向检查：天气、普通闲聊不能被实体展开误触发。

**注入层验收（证明不是只算出来）**

- `build_message_list(association_context="...")` 的 system 段里必须出现【关联背景】；
- `hit_blocks` 记 `associations`，`block_hits` 能看到开火；
- `injection_snapshot` 的私聊/群聊快照里都能看到关联背景（有命中时）。

## 二、私聊 / 群聊环境拆分

### 骨架里移哪句（逐字）

文件：`persona/core/system_prompt.txt`，当前原文：

```text
你就是灰泽满本人，正在 QQ 上与绿冻聊天。文中提到的“灰泽满”或“hzm”均指你自己。你是在直接与对方聊天，不是在撰写关于灰泽满的旁白、故事、直播文案或角色分析。
```

改成：

```text
你就是灰泽满本人。文中提到的“灰泽满”或“hzm”均指你自己。你不是在撰写关于灰泽满的旁白、故事、直播文案或角色分析。
```

只删“正在 QQ 上与绿冻聊天”和“你是在直接与对方聊天，”；保留“你就是灰泽满本人”和“不是在撰写……角色分析”。**不要多删**，不要动后面的身份/性格/边界。

新的两段场景文案：

- 私聊：`现在是一对一私聊：对面是正在和你说话的人。`
- 群聊：`现在是群聊：群里有多个绿冻；只有点名或 @ 你时，才是在跟你说话。`

### NapCatQQ 状态 → 注入：唯一真值链路

不要从文本、`group_context` 是否为空、或 `to_me` 推断私聊/群聊。唯一来源是 NapCat/OneBot 事件字段：

1. `event.message_type`：`"private"` = 私聊，`"group"` = 群聊；
2. `__init__._handle_chat` 里 `is_private = getattr(event, "message_type", "private") == "private"`；
3. `target_id = user_id`（私聊）或 `event.group_id`（群聊）；
4. `chat_window.enqueue(..., is_private)` → `_UserWindow.is_private`；
5. `_flush` 调 `handle_chat(..., is_group=not win.is_private)`；
6. `handle_chat` 把 `is_group` 传给 `build_message_list(..., is_group=...)`（**现在没有这个参数，要新增**）；
7. `build_message_list` 在 `SYSTEM_PROMPT` 之后、周表之前，按 `is_group` 二选一注入 `00_scene` 的 private/group 文案。

`to_me` 只在群聊里表示“被 @ 了”，不能拿来判场景；私聊的 `to_me` 恒为真。

### 场景块

- 新建 `00_scene`（`order: 0`），`strings.private` / `strings.group` 两段文案；
- `build_message_list` 在 **SYSTEM_PROMPT 之后、周表之前**按 `is_group` 注入其中一段；
- 群成员名单和群近况仍留在原来的第 6 块，不搬。
- 注入时把 `hit_blocks.append("scene_private")` / `"scene_group"`，让 `block_hits` 能证明真的进了提示词；`block_hits` 的统计列表也要加这两个名字。

### 群聊消息结构

- 每条消息按顺序拼：`昵称：文本`，图片按顺序内联；
- 每条前面加确定性标记：
  - @她、引用她、消息里直接出现她的名字 → `[对灰泽满]`
  - 其余 → `[未点名]`
- 整批再加一句：`本批有人点名灰泽满` / `本批无人点名灰泽满`；
- 接话门已有的“点名”判定直接复用，不再让主模型猜“你”是谁。
