### 2.1 三个数据源，各自能干什么

| | 在哪 | 规模 | **只有它能干什么** |
|---|---|---|---|
| **转写** | `handoff-data/proof/<场次>/proof_segments.json` | 38 场 / **55,589 段** / 127 万字 / 4,829 条人工修正（26.03.29–26.08.22） | **拿到"她说了什么" + 前后文** |
| **问答对** | `handoff-data/a2-sft-round3.jsonl` (+ `.map.jsonl`) | **3,605 对** | **同时有"用户说了什么"和"她怎么答"** |
| **配对库** | `handoff-data/vup.db`（SQLite） | `pairs` 27.1 万 / `pair_verdicts` 3.0 万 | 判断一对配对**到底成不成立** |

**① 转写（proof）**——每段长这样：
```json
{"segment_id": 93, "start_ms": …, "end_ms": …, "text": "谢谢哦，绿冻也配上桌哦，对，那绿冻可以走了。", "emotion": "neutral", "flags": ["proof"]}
```
它是**人工校对终本**（修掉了「灰机板 → 灰泽满」这类同音误识）。**按 `segment_id` 取，
前后各取几段就是当时的上下文。**

**② 问答对（SFT）**——`messages` 三行：
```json
{"messages": [
  {"role": "system",    "content": "你是念念，B站虚拟主播，AI少女…"},
  {"role": "user",      "content": "绿冻也配上桌？"},
  {"role": "assistant", "content": "谢谢哦，绿冻也配上桌哦，对，那绿冻可以走了。"}]}
```
- `a2-sft-round1.jsonl` 是**同一批 3,605 对**，只有 system 那行不同（裸的，不带人设）。
  两版 `user`+`assistant` **逐字相同（3605/3605）**——别以为是两份数据。
- `a2-sft-round{1,3}.map.jsonl` **两个文件字节完全相同**，是同一份溯源表，每行
  `{"session_id": "26.03.29", "dm_id": "…", "segment_id": 93}`。
- ⚠️ **这 3,605 对全部是 `premium`、`confidence=high`**——是拿 `pair_verdicts` 筛过一遍的。

**③ 配对库（vup.db）**——Python 自带 `sqlite3`，不用装东西，三张表：

| 表 | 行数 | 里面有什么 |
|---|---|---|
| `chunks` | 9,660 | 转写切成的窗口：`text` + **`danmaku_digest`**（那个窗口里观众发的弹幕摘录）+ 4096 维向量 |
| `pairs` | 271,413 | `{dm_id, segment_id, direction, score, session_id, tier}`。tier：`anchor` 22,463（她念了实词）/ `convergent` 8,507 / `rest` 240,443 |
| `pair_verdicts` | 30,223 | `{…, verdict, confidence, reason, layer}`。**layer：premium 8,262 / echo 8,945 / low 5,247 / rejected 7,719** |

`reason` 那列是人话，长得像：
```
[premium]  复述『也配上桌』后展开让绿洞走
[echo]     机械念读『柜子歌』无新增      ← 「照念」的判据就在这
[rejected] 问句无对应回答实词
```

### 2.2 一条链路：从一条问答对追回当时的上下文

```
a2-sft-round3.jsonl 第 N 行
   ├─ messages[1] = 弹幕原文        「绿冻也配上桌？」
   ├─ messages[2] = 她的原话        「谢谢哦，绿冻也配上桌哦…」
   └─ map 第 N 行  = {session_id, dm_id, segment_id}
        ├─→ vup.db / pairs          → tier / direction / score
        ├─→ vup.db / pair_verdicts  → layer / verdict / confidence / reason
        └─→ proof/<场次>/proof_segments.json 取 segment_id 那一段
                                      → 她那一句 + 前后文
```
实测：**3,605/3,605 全能对上** `pairs` 和 `pair_verdicts`。

### 2.3 这套链路能干什么（已验证过的）

1. **挑 behaviors 例句** —— `scripts/curate_behavior_samples.py`：正则筛候选（**带一道
   "照念"筛子**：回复的二字组 ≥50% 能在弹幕里找到就扔掉）→ 让模型从候选里挑 + 按私聊改写
   → 人工过一遍。
   ⚠️ **模型可能把她的回复改写成"用户说的话"**，输出必须人工核。
2. **判断一条例句自不自足** —— 拿 `segment_id` 追回前后文，一眼看出 reply 里提到的东西
   是不是当时语境里的（这就是"三毛"那条毛病的硬判据）。
3. **找反例** —— `echo` 那 **8,945 条**是"机械念弹幕"的现成教材，还没用。
4. **补 trigger 的「这类话」** —— `chunks.danmaku_digest` 有 **27,324 条去重后的真实弹幕原文**
   （只有用户侧，没配她的回复）。

### 2.4 限制（用之前必须知道）

- ⚠️ **`pairs` 的 27 万条没有弹幕原文**，只有 `dm_id`（一串编号）——包里没有任何表能把编号
  翻回文字。**所以能还原"用户说了什么"的只有那 3,605 条。**
- ⚠️ **SFT 的回复是语音转写**：一半是"念弹幕"（直播里的动作，私聊没有）、一半长在直播语境上
  （弹幕/切片/下播/舰长）。**能直接当私聊例句的比例不高**——实测十几条里挑得出三五条。
- ⚠️ `pair_verdicts` 的 `premium` **不等于"不照念"**：它的判据是「复述实词 + 展开」，
  理由里本身就写着「念『X』后…」。抽查抓到漏网的（`[就这么富裕啊！] → [就这么富裕啊？]`
  被判 premium/high，其实没展开）。**所以自己还得再过一遍。**
