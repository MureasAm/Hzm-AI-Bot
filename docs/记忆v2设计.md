# 记忆 V2 设计（记什么 · 怎么影响对话）

> 2026-10-09 写。给"开个新窗口做这件事"用：现状 + 实测数据 + 框架 + 落地步骤都在这一份里。
> 相关文件：`src/plugins/chatbot/memory_v2.py`（影子实现）、`memory_manager.py`（v1，在跑）、
> `scripts/memory_v2_tool.py` + `run_tool.py memory-replay|memory-audit`（工具）。

---

## 一、现状：v2 是什么、为什么还没上

**v1（在跑）**：`memory_manager.py`。一张自由文本卡：`impressions`(标签+confidence) /
`user_facts` / `self_facts` / `significant_moments` / `promises` / `user_name` / `weather_city`。
每轮私聊后异步 LLM 提取 → `merge_memory_card` 合并。注入时**整张卡**进【关于这个绿冻的长期记忆】。

**v2（影子，未启用）**：`memory_v2.py`。类型化条目：`fact` / `interaction_preference` /
`emotional_state` / `commitment` + `upsert`/`retract` + 时间域 past/current/future/timeless。
每条**带证据**（哪一轮来的）、情绪 **6h TTL 且绑定会话**、**隐私闸门**（电话/地址/证件/银行/医疗拒收
+ 摘录打码）、**按当前话题取相关**再注入、有 `audit.jsonl`、有 `delete_user`。

开关：`MEMORY_V2_SHADOW=1`（默认关，fail-closed，失败不影响回复）。
接入点：`core.py` 的 `_MEMORY_V2_STORE` + `update_memory_v2_shadow_task`（只在**私聊**调用）。
**它现在不注入任何东西**——只写影子文件，看它"本来会注入什么"。

### v1 vs v2（一句话）
v1 是"往一张卡上堆自由文本、只增不减、注入整卡"；v2 是"带类型/证据/时效/隐私闸门的条目，
按话题取相关的注入"。v2 赢的地方正是 v1 的真毛病。

### 实测数据（别重测，直接用）
- **回放 40 轮真实私聊**（`memory-replay --limit 40`）→ 7 用户 / 18 条：
  `commitment 3 · emotional_state 9 · fact 6 · interaction_preference 0`；
  状态 `active 6 · confirmed 5 · superseded 7`。
  好的：`灰泽满答应当前就去躺着休息`、`答应用户发破音版晚安语音`、`对月饼一般，芒果味的可以考虑`。
  **收敛在工作**（`recent_activity` 从"循环歌回"被"翻切片"顶掉）。
- **三个洞**（都在那 18 条里）：
  1. **误记**：`fact/bot_version = V8.0`、`fact/bot_features = V8.0修复了…`——用户跟她说
     "你更新了 V8.0"被当成**关于他的事实**存下来。**这类永远不会改变她的回复**。
  2. **一半是情绪**：`emotional_state` 9/18，而它们 6 小时就过期。长期记忆的一半容量
     花在半天就没了的东西上。
  3. **偏好 0 条**：v2 的偏好只有 **4 个枚举维度**（support_style / banter_tolerance /
     directness / care_initiative），装不下 v1 现在记的那类相处印象。
- **现有 137 张 v1 卡**：`user_facts` 43 张 / `impressions` 23 张 / `moments` 9 张 /
  `promises` 3 张；**其余 114 张是空的**（只有计数器 + last_seen）。卡中位 69 B、最大 1.3 KB。
  → **机械搬 v1 进 v2 收益极小**，而且 v1 条目没有证据来源，硬塞会绕过 v2 的证据/隐私闸门。

## 二、框架：四个层，每层回答一个问题

**核心顺序**：先定"它要改变她的哪个**动作**"，再定"记什么"。
**准入的唯一标准：这条抽出来，会不会改变她下一次回复？** 不会的，一律记进反例清单。

### ① 事实层 `fact` ——「他是谁」
- **记**：稳定、会影响回应的客观事实——称呼/昵称、地域时区、身份（学生/社畜）、
  正在经历的大事（搬家/考试/生病）、明确喜好（"月饼一般，芒果味的可以"）。
- **不记**：关于机器人自身/开发日志（`bot_version` 那种）、单次闲聊、只出现一次的状态。
- **怎么影响对话**：**只做"不矛盾"的底线 + 被问时接得上**（他在澳洲 → 别说"你那边夏天"；
  "你不是要考试吗"）。**不主动背简历**——因此它只在**话题相关**时才注入。
- **时效**：稳定事实 timeless；"正在经历"类给 TTL（搬家结束了就过期）。

### ② 偏好层 `interaction_preference` ——「他想被怎么对待」★ 现在最缺
- **记**：**可执行的相处方式**，不是印象标签。现有 4 个维度是骨架但要**扩到 8 个**：
  称呼偏好 / 回复长度 / 主动关心阈值 / 玩笑尺度 / 低落时怎么接 / 拒绝方式 /
  话题偏好与雷区 / 她怎么自称。
- **怎么影响对话**：注入时**直接给行为句**（`_PREFERENCE_BEHAVIORS` 已经是这个机制，如
  "用户低落时先接住情绪，不要马上讲道理"）。**四层里优先级最高**——它是针对这个人的适配，
  与风格/习惯冲突时以它为准。
- **证据门槛**：**≥2 次独立证据**才升 `confirmed`。一次撒娇不该改变全局行为。
- ⚠️ 每个维度都必须是**枚举值 + 对应的行为句**——这就是黄金律第 2 条"行为 > 标签"。

### ③ 承诺层 `commitment` ——「她答应过什么」
- **记**：她说出口的承诺/约定（"答应用户发破音版晚安语音"、"答应当前就去躺着休息"）。
- **怎么影响对话**：**兑现之前不能被忘**；到期没做要有"欠着"的感觉。
- **时效**：`future` → 到点转 `past`。

### ④ 情绪层 `emotional_state` ——「他现在什么状态」
- **记**：用户当下的情绪（难过/兴奋/撒娇），**6h TTL + 绑定会话**（v2 已实现 ✓）。
- **怎么影响对话**：**只影响当下这一轮的语气**（先接情绪），**不进长期画像**。
- ⚠️ 这一层**不该和事实层抢注入位**——它本质是"当下语气提示"。

### 反例清单（抽到这些 → 不记）
- 关于机器人自身的事（版本、功能、更新日志、"你是不是 AI"）
- 单次闲聊/寒暄（"在吗""哈哈哈"）
- 只出现一次、不会影响下次回应的状态（"他刚打了个哈欠"）
- 已能从别处拿到的（时间/天气/直播状态——那是 `context_probe` 的活）
- 敏感信息（v2 已有闸门，保持）

## 三、注入：三层位置，作用不同

v2 现在把记忆渲染成**一整块**。应该拆成三段、放在不同位置：

| 层 | 注入位置 | 作用 |
|---|---|---|
| 偏好 → **行为句** | system，靠前 | 长期稳定的相处方式（个体适配） |
| 承诺 → **"你还欠着…"** | system，中段 | 别忘、要兑现 |
| 情绪 → **当下语气** | **紧挨用户消息**（跟【当前时间】一样放最后） | 只影响这一轮 |
| 事实 | 话题相关时才带 | 不矛盾 + 被问接得上 |

⚠️ **位置不是随便挑的**：`build_message_list` 里已经验证过"变量必须靠后"——
一是 DeepSeek 的**前缀缓存**按位置匹配（变量在前会让后面整段静态内容永远不命中，
实测 0% vs 68%，见 `docs/地图.md` 的缓存一节），二是注入位置会影响她把这内容
当"刚发生的事"还是"参考资料"。

## 四、落地三步

1. **定准入条件** → 改 `memory_v2.py` 的提取提示词（`build_extraction_prompt`）：
   把上面 ①-④ 的"记/不记"写进去，**尤其是反例清单**（现在它把 `bot_version` 也当年事实）。

## 六、落地状态（2026-10-10）

「落地三步」已全部落地，`pytest` 827 全绿，`regression --check` 7/7 通过。

1. **准入条件 + 反例清单**：`MEMORY_V2_EXTRACT_PROMPT` 加了「唯一的准入标准」和
   「反例清单」，并明确 **fact 必须是关于用户本人**的。实测：把那条更新日志
   （用户粘贴 "V8.0 再次修复…"）重跑 → **0 候选**（旧提示词会存成 `fact/bot_version`）。
   另加一道确定性闸门 `_is_bot_self_fact`（`memory_v2.py`）：key 以 `bot`/`hzm` 开头、
   或 value 以「灰泽满/机器人」等自称开头的事实条目直接拒收——模型输出本就当不可信输入校验，
   这是兜底。拒收会写进 `audit.jsonl`（reason=`bot_self_fact_blocked`）。
2. **偏好维度 4 → 8**：`_PREFERENCE_VALUES` / `_PREFERENCE_BEHAVIORS` 各加 4 组
   （`address_style` 称呼 / `reply_length` 长度 / `topic_preference` 话题雷区 /
   `self_reference` 自称）。每个值都有行为句，有测试断言"无遗漏枚举值"。
3. **注入拆三段**：`build_context` 拆成 `build_preference_context`（靠前）/
   `build_commitment_context`（中段）/ `build_emotion_context`（紧挨用户消息）。
   三个方法已接进 `build_message_list`（新参数 `profile_context`/`commitment_context`/
   `emotion_context`）。`build_context` 保留为聚合视图（审计/测试用）。
   **注入默认关**，开关 `MEMORY_V2_INJECT=1`（与影子提取的 `MEMORY_V2_SHADOW` 分开）——
   见上面 §上线路径，先影子验证再开注入。

回放实测（`memory-replay --limit 300`，干净重跑）：13 用户 / 18 条；
`emotional_state 8 · fact 9 · commitment 1 · interaction_preference 0`。
**偏好仍为 0**——模型很少主动产出偏好条目，这层要靠后续真实影子运行再攒证据。

⚠️ **回放工具已修**（2026-10-10）：`replay` 以前不清空 `outputs/memory_v2/replay_shadow.json`，
store 会**加载旧状态再往上叠** → 重复回放/换提示词对比全是脏数据（上一轮我以为 bot_version

## 七、v1 vs v2 离线对比（2026-10-10）

工具：`run_tool.py memory-ab --limit N --per-user M`（`scripts/memory_ab.py`）。
拿**同一批真实私聊**同时跑两路，产物写 `outputs/memory_ab/`。只取真实真人会话
（跳过 QA/联调脚本造的假会话、非 QQ 号 session），并**按会话活跃度**排序取人
（记忆层对常来的用户才有意义）。注意 v2 的 `now` 用**该用户最后一轮的历史时刻**，
不是 wall-clock——否则回放几周前的对话时情绪层会全部判过期，对比就假了。

### 一次实跑（432 轮 / 20 个真实用户）

| | v1 记忆卡 | v2 类型化记忆 |
|---|---|---|
| 有内容的用户 | 9/20 | 20/20（都有条目） |
| 条目总数 | 21（印象 4 / 事实 16 / 承诺 1 / 城市 1） | 40（情绪 26 / 事实 13 / 承诺 1） |
| 注入体积（中位 / 最大） | 17 / 215 字 | 0 / 106 字 |
| 机器自身噪声 | 0 | 0 |

### 结论（哪边赢在哪）

- **v2 赢**：类型分离、注入有界、有隐私闸门/证据/作废，不会把整卡糊上去。
  例：v1 把某用户的「躁郁症/车祸/被霸凌」整段**每轮**注入（215 字墙）；
  v2 只给当下情绪 + 相关事实（≤106 字）。
- **v1 赢**：它把稳定事实（"人在曼谷""躁郁症""留学泰国"）**一直挂着**；
  v2 其实也**存下来了**，但**话题相关才注入** → 那轮没命中就不出现，看着像"没记忆"。
- **两者都有的毛病**：情绪条目占比高（v2 `emotional_state` 占 65%，一半还已过期）——
  就是§一那个"洞 2"，扩维度没治到这个。

### 下一轮 v2 迭代的候选（按价值排，**尚未动手**）

1. **通用 key 会互相顶掉**（真·数据丢失）：作废规则按 `(kind, key)` 判"同键新值顶旧值"，
   但模型会拿 `past_experience` / `current_situation` / `current_location` 这种**通用键**
   装不同的事 → 后来的顶掉先前的。实测这名用户 13 条 fact 里 **3 条被顶掉**
   （`past_experience` 霸凌 被 车祸 顶掉、`current_location` 曼谷 被 泰国留学 顶掉）。
   改法二选一：① 只对**单值键**（`preferred_name`/`city`/`timezone`…）作废，其余键当累加；
   ② 让提取提示词产出**具体键**（`place_man_gugu` 之类）。这是**语义改动**，要先定。
2. **"核心键"对不上模型实际产出**：`_select_facts` 有个 `{preferred_name, name, city}` 的
   "永远注入"白名单，但模型实际产 `current_location` / `timezone` → 白名单基本不触发。
   要么把白名单换成模型真会用的键，要么干脆去掉"永远注入"。
3. **情绪层压制**：每轮都抽情绪 → 65% 是它、还互相作废。考虑：只在情绪**变化**时记、
   或不给情绪层单独的作废位（已经是每会话一条 active 了）。
4. **话题相关注入太保守**：也许该有一条"底线事实"永远带（至少名字/时区/城市），
   和§二事实层写的"不矛盾的底线"对齐。

## 八、2026-10-10 返工：情绪搬去会话记忆 + 事实分三类

用户看完§七后的两点指示（"其他的按你的建议改"）：

### 1. 情绪不住长期记忆了 → 会话记忆，和话题一起 3 小时消散

- **储存**：`session_memory` 的会话记录里新增 `mood` / `mood_at`；由**会话探测**每轮顺手产出
  （`SESSION_PROBE_PROMPT` 加了 `mood` 字段）——**不额外多一次 LLM 调用**，而且不受 v2 影子开关
  影响，生产里当场生效。
- **读取**：`session_memory.mood_note()`，超过 `MOOD_STALE_SECONDS`（=3h）返回空。
- **注入**：仍在**紧挨用户消息**处（`emotion_context`），只影响这一轮语气。
- **v2 侧**：`emotional_state` 这个 kind **整个删掉**（`_KINDS` / 提示词 / ingest / `_emotion_lines`
  / `build_emotion_context` / `EMOTION_TTL`）。抽到它一律拒收。
- **会话冷场阈值**：`SESSION_STALE_SECONDS` 从"话题年龄 24h"改成"**距上一条消息 3h**"
  （推翻 2026-10-05 的决定）。理由：真实对话是一阵一阵的，停几小时再回来就是新的一场；
  `topic_since` 保留用于"话题几点开始的"，但不再决定过期。`tests/test_session_memory.py`
  的 `TestTopicAge` 已按新语义重写。

### 2. 事实分三类，各自不同的倒旧/过期规则

| 类别 | temporal_scope | 规则 |
|---|---|---|
| 经历 / 喜好 | past / timeless | **累积，永不倒旧的** |
| 当前状态（换城市/在搬家/在准备考试） | current | **同 key 顶替**（单值槽） |
| 时效性近况 | current + `valid_for` | 到 `valid_for` 给的期限就过期 |

- 作废规则改成：**只有 `interaction_preference` 和 `temporal_scope=current` 的 fact 才顶替**
  （`ingest` 里判断）。这修掉了§七第 1 条的真丢数据——`past_experience` 下的"霸凌"不会再被"车祸"顶掉。
- 抽取提示词新增 `valid_for` 档位（`3d`/`14d`/`90d`/`none`，从用户话里的时间词读）+
  **明确要求 fact 用"具体到事的 key"**，禁用 `current_situation`/`past_experience` 这类通用键。
- "永远注入"的白名单从写死的 `{preferred_name,name,city}` 换成模型真会产出的
  `_ALWAYS_ON_FACT_KEYS`（`location`/`timezone`/`identity`…），修掉§七第 2 条的白名单空转。

验证：`pytest` 840 全绿；`regression --check` 中 `no_verbatim_repeat_after_late` 首跑挂 1 次、
**重跑两次均过**（该用例本身就是统计型，runs=24、阈值贴边，属 LLM 抖动）。

### 复跑 A/B 看效果（`memory-ab --limit 500 --per-user 25`，432 轮 / 20 人）

| | 改之前（§七） | 改之后 |
|---|---|---|
| v2 条目 | 40（情绪 26 / fact 13 / 承诺 1） | **13（全是 fact）** |
| fact 被顶掉 | 13 条里丢 3 条 | **0 丢失**（`past_*` 累积） |

## 九、常驻注入的可行性实验（2026-10-10，**结论：不采用，证据不足**）

想法：把"性格"和"痛处"也常驻注入（不只话题相关时才带），看她是不是更像"一直记得你"。
担心的是反面：常驻会让她**每轮都提/哪壶不开提哪壶**。

工具：`scripts/always_on_experiment.py`（隔离实验——绕开检索，只把三档注入塞进
`build_message_list` 的 `profile_context`，同一句话生成三条回复 + 盲评）：
A = 无记忆；B = +性格常驻；C = +性格 +痛处常驻。素材取自 **v1 记忆卡**
（56 个真人卡：25 人有"性格"、5 人有"痛处"），比刚开跑、只有 3 个人有记忆的 v2 影子库大得多。

**跑 60 轮的结果**：

- **LLM 盲评基本等于噪声**：most_natural A/B/C = 18/22/20，reciting = 14/9/14，
  inappropriate = 12/11/10——三档几乎均分。**这印证了仓库一贯的立场（regression 判据
  不用 LLM 当裁判）**：这种细微信号，LLM judge 分不出来。
- **确定性指标（真正有用的那个）**：把"性格/痛处"的 key-bigram 和回复求交、再扣掉
  基线（A 组回复里高频出现的词，如"灰泽满"），结果**三档都是 0 提及**——
  常驻并没有让她主动去提这些内容。**担心的"每轮复读/踩雷"没有出现。**
- ⚠️ 但样本很薄：痛处只有 **1 个用户、1 条素材、10 轮**；且只量了"提没提"，
  **量不到"有没有变得更好"**（判官是噪声）。

**结论：不采用。** 实验既没证明有害，也**没证明有益**——用户的条件是"效果好就采用"，
这个条件没达到。要真判，得换更硬的尺子（例如人工读 30 组、或量"回复是否更贴这个人"的
确定性代理），而不是继续堆 LLM 判官。

（顺带得到的一个**可用结论**：把常驻内容塞进 `profile_context` 不会让回复明显跑偏——
这套注入位置本身是安全的。）

## 十、2026-10-10 转正：V2 接管长期记忆

**V2 已是当前长期记忆**（`MEMORY_V2_SHADOW` / `MEMORY_V2_INJECT` **默认开**，要回退设 `=0`）。
v1 的卡停写、停注，代码保留（现在只读它取天气城市），随时可退回：
见 `core.handle_chat` 里的注释。

- **用真实聊天重建**：新增 `run_tool.py memory-rebuild` —— 遍历全部私聊、逐轮提取、写真实
  `user_memory/memory_v2_shadow.json`（先备份旧库）。**全量约 4000 次提取调用**。
  实跑结果：**139 用户 / 110 条**（fact 101 / commitment 9；superseded 仅 3 → 顶替规则正常）。
- **会话阈值拆开**：话题消散 3h（`SESSION_STALE_SECONDS`）、「上次聊过」提示 12h
  （`PREV_SESSION_NOTE_SECONDS`）——不再共用一个常量，否则隔几小时就念一句"上次聊过"。
- **「时间钩子」防复读**（`reply_style.uses_time_hook` + `core` 里的重生成）：
  熬夜场景下她反复拿"凌晨三点…"当开头（逐字复读检测抓不到——说法不同、公共子串不够长）。
  触发很窄：**这条提了时间 且 最近两条也提过**；只认时间词，不碰她别的口癖
  （历史教训：防措辞固化就是死在误伤自称"灰泽满"）。

### ⚠️ 顺带修掉一个真 bug：V2 提取提示词把变量放在了最前面

用户发现缓存"未命中 415 万 / 命中 74.6 万"（≈15%）。查下来：
`MEMORY_V2_EXTRACT_PROMPT` 的**第一个变量在第 130 字**（共 2630 字）→ 只有 **5% 可缓存**，
后面整段静态指令**永远 miss**（正是 `架构.md` 里"变量放前面"那个坑；v1 的提示词一直是 82%
静态前缀，所以没事）。跑几千次重建就攒出 400 万+ 未命中 token。
**改法**：把 `{observed_at}/{current_summary}/对话` 全挪到最后 → 可缓存前缀 **95%**。

> 结论：**提示词里所有变量一律放最后**，静态指令在前。这是硬约束（前缀缓存按位置匹配），
> 写新提示词时别忘。
