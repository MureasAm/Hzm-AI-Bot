## 2. 运行时核心 `src/plugins/chatbot/`（30 个文件）

### 2.1 一条消息的链路（改之前先认路）

```
QQ 消息
  → __init__.py::_handle_chat          采集 + 还原（图/引用/转发/表情/@ → 文本）
  → chat_window.enqueue                进读秒窗口（同会话消息攒批）
  → chat_window._process → _flush      静默 5~10s → 读图 → 归纳 → 群门 → 生成
      → core.handle_chat               主循环（拼 messages → 调模型 → 记忆更新）
      → self_speech.annotate_turn      她的历史原句/自引用 → 中性转述（防复读）
      → core.build_message_list        注入 17 段（见 架构.md）
      → core.generate_reply            调 DeepSeek
      → reply_style.clean_reply        清洗（换行归一 / 去括号前缀 / 省略号纪律）
      → voice.should_voice → send_voice  语音优先（成功就不走文字分段）
      → reply_style.split_reply        文字分段
  → chat_window._send                  发出；chat_window._maybe_send_sticker 补表情包
```

**逐段细节、判据怎么选、为什么这么排 → `架构.md`。**

## 3. 人格数据 `persona/`（35 个文件 / 20 个注入块）

**2026-10-16 起 persona 的骨架构是「一个注入块一个文件夹」**：`persona/injection/` 下
`01_identity` … `19_daily`，**文件夹名的序号就是注入顺序**（顺序有讲究：情绪紧挨用户消息、
当前时间放最后是为了前缀缓存）。每个文件夹里的 `block.json` 写着这块的
**段头 + 文案模板 + 它从哪拿内容 + 什么时候注 + _readme（别把什么写进来）**。

> 为什么这么改：在这之前「一个注入块」在代码里根本不存在——它是 `core.build_message_list`
> 里几十个 `append` 的副产物，文案散在 4 个 py 文件、数据散在 `world/` `behavior/`。
> 改一段话要翻四处，骨架里说`【行为指令】`、代码里叫`【当前情境下的行为指令】`这种脱节就是这么来的。

| 位置 | 个数 | 是什么 |
|---|---|---|
| `core/system_prompt.txt` | 1 | 第 1 块·**骨架**（2774 字），每轮常驻 |
| `injection/NN_块名/block.json` | **19** | 每块的定义（段头/文案/来源/时机） |
| `injection/*/` 里的数据文件 | 11 | 跟着它服务的块走（见下表） |
| `decision/legendary.json` | 1 | **不进提示词**：命中触发词就直发（硬路由） |
| `decision/stickers.json` | 1 | **不进提示词**：回复后判"配哪张图" |

**数据文件都跟着自己服务的块走**（`→ 走向量？` 那列说改完要不要重算）：

| 块文件夹 | 数据文件 | 条数 | 走向量？ |
|---|---|---|---|
| `02_schedule/` | `schedule.json` | 7 条 | 否（每轮注入，地面真值） |
| `04_preferences/` | `preferences.json` | 23 条 | 否（按 keywords 子串命中） |
| `05_core_stories/` | `core_stories.json` + `core_story_vectors.json` | 5 条 | **是** → `precompute core-stories` |
| `07_terms/` | `terms.json` | 27 个词条 | 否（always + 命中） |
| `10_behaviors/` | `behaviors.json` + `behavior_keywords.json` | **18 条** / 3 行为 21 词 | 否（判别词 + LLM 分类） |
| `11_corpus/` | `statement_final.json` + `corpus_vectors.json`（17MB，仓库最大）+ `corpus_keywords.json` + `corpus_asks.json` | 414 条 | **是** → `generate-vectors -i persona/injection/11_corpus/statement_final.json` |

> `persona/behavior/` 目录**已删除**（2026-10-16 数据搬进 `10_behaviors/`）；
> `persona/speech/` 目录**已空**（`phrases.json` / `voice_samples.json` 于 2026-10-04 拆掉并入库 `behaviors` 与骨架）。

**目录长什么样、每块管什么、一条东西该进哪** —— 看 `persona/injection/<块>/block.json` 的 `_readme`，
或在代码里跑 `python -c "from src.plugins.chatbot import injection as i; print(i.overview())"`。

**注入层怎么工作**：`src/plugins/chatbot/injection.py` 只做「取文案」；
**什么时候注、注哪条变体、参数从哪来由调用方决定**——文字和逻辑各归各。
改文案不碰代码，改判断不碰文案。

**四类数据 = 四种"记得"**：`schedule`（今晚播不播）→ `terms`（这词啥意思）→ `preferences`（她是怎样的人）→ `core_stories`（最深处的记忆）。详见 `架构.md` 注入层。
