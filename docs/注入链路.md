# 注入链路 —— 她有什么、怎么被注进去

> 2026-10-04 重写。**这版按两套分类组织**（人格/事实、判定方式），并删掉了所有已下线通道的内容。
> 想知道「线上真发了什么」就看本文第三节（带实测字符数）。

---

## 一、两分钟看懂

一条消息进来后，喂给模型的 messages 由**两层**构成：

```
┌─ 人格层（「她是谁、怎么说话」）────────────── 只有 2 个文件，但对每一轮都生效
│    ① persona/core/system_prompt.txt    骨架 3452 字 ← 占整个输入的 91%
│    ② persona/behavior/behaviors.json   16 条情景 → 命中哪条注哪条 + 它的真实原句
│
└─ 事实层（「她知道什么」）────────────────── 其余全部，按需注入
     周表 / 名词库 / 时间 / 直播记忆 / 偏好 / 核心记忆 / 会话记忆
     / 长期记忆 / 对话历史 / 连续索要计数
```

**关键事实**：人格层的 ① 是常驻的，**占了 91% 的输入**；其余所有东西加起来才 9%。
所以「她像不像」，主要由**骨架 + 命中那条行为的原句**决定，不是靠堆事实。

## 二、分类①：人格文件 vs 事实文件

| | 人格文件 | 事实文件 |
|---|---|---|
| **回答什么问题** | 她是谁、她怎么说话 | 她知道什么、发生过什么 |
| **有几个** | **2 个** | 12 个来源 |
| **注入时机** | 骨架**每轮都注**；behaviors **按情景命中** | 按需（命中才注） |
| **文件** | `core/system_prompt.txt`<br>`behavior/behaviors.json` | `schedule` `terms` `legendary`<br>`statement_final` `corpus_keywords` `corpus_asks`<br>`preferences` `core_stories` `stickers`<br>+ 记忆三件（长期/会话/本场）<br>+ 感知（时间/天气）、周表<br>+ 群记忆、对话历史、连续索要计数 |
| **为什么这样分** | 把它们混在一起，就会出现「用事实文件教她说话」（历史踩过：terms 里塞措辞、corpus 里塞台词） | —— |

> **判据（新增素材时用）**：
> 这条内容是在说「**她怎么说话 / 遇到什么情境怎么反应**」→ 人格层；
> 是在说「**她知道某个词 / 某件事 / 某个偏好**」→ 事实层。
>
> 特别地：**台词/原句一律不算独立文件**——它必须挂在某条 behaviors 的 `samples` 里（按情景触发）。
> 曾经有一份独立的 `voice_samples.json`（86 条问答对），**2026-10-04 已删**，原因见第六节。

## 三、分类②：判定方式（**这张表是本文的重点**）

一个文件「什么时候被注进去」，靠的是下面四种机制之一。**改素材前先确认它属于哪种**——改错了地方不会生效。

| 判定方式 | 谁用 | 怎么判 | 代价 |
|---|---|---|---|
| **⓪ 无条件常驻** | **骨架**、周表、时间/天气感知 | 每轮都注 | 骨架 3452 字 = **91% 预算** |
| **① 关键词/子串/正则** | 名词库 terms、偏好 preferences、legendary、behavior_keywords 兜底 | 用户消息里出现关键词/别名/正则就注 | 免费（本地纯函数） |
| **② 向量相似度** | 直播记忆 corpus（**初筛**）、核心记忆 core_stories | 余弦 ≥ 阈值 | 一次 embedding 调用 |
| **③ LLM 判断** | **behaviors（★真 LLM）**、corpus（向量初筛**后**再审）、连续索要 `same_request` | L3 一次调用读出：行为名 + 措辞组 id + 连续索要计数 | **每轮 2 次 LLM 调用** |

### 3.1 逐个说清（按「改了要跑什么」对齐）

| 文件 | 判定方式 | 备注 |
|---|---|---|
| `core/system_prompt.txt` | **⓪ 常驻** | 改完只要重启 |
| `behavior/behaviors.json` | **③ LLM**（`classify_l3`） | 一次调用同时判**行为**和**措辞组**；判别词兜底（`behavior_keywords.json`）。**不走向量** |
| `behavior/behavior_keywords.json` | ① | LLM 判不出时的兜底词表 |
| `world/statement_final.json` | **② 向量初筛 + ③ LLM 再审** | 两道门：先按余弦取候选，再叫 LLM 判「用户是不是在问她这段」 |
| `world/corpus_keywords.json` | ① | 上面那道关键词门 |
| `world/corpus_asks.json` | ② | 语料自指代词审计表 |
| `world/preferences.json` | **① 关键词** | **不走向量**（2026-09-26 起改判据） |
| `world/core_stories.json` | **② 向量** | 印象最深的结晶 |
| `world/legendary.json` | **① 关键词/正则** | 固定说法（如身份应答） |
| `world/schedule.json` | **⓪ 常驻**（只注 weekly） | 「近况」字段已整条删除 |
| `world/terms.json` | **① 关键词/别名/正则** + `priority=always` 的常驻 | `usage` 只在命中时注，避免每条都蹦黑话 |
| `media/stickers.json` | ① | 表情包 |
| 记忆（长期/会话/本场/群） | 按会话状态 | `memory.py` / `session_memory.py` / `group_memory.py` |
| 时间/天气 | **⓪ 常驻** | `context_probe.get_now_context` |
| 连续索要计数 | **③ LLM**（`classify_l3` 的 `same_request`） | 只给事实「第几轮在要什么」，不给「该不该答应」 |

> ⚠️ **`phrases.json`（措辞）已删**（2026-10-04，情景组并入 behaviors）。上表保留「措辞」这一路的名字只是为了跟 `_split_fused` 对得上。
> ⚠️ `terms` 的注释里提到过一个 `confirm_ambiguous_terms`（LLM 语境确认）——**那个函数已不存在**，terms 实际是纯关键词。

## 四、真实注入序列（实测，2026-10-04）

跑 `outputs/_experiments/_exp_injection_measure.py` 量的，四个真实输入：

| 输入 | 消息条数 | 总字符 | 骨架 | 行为 | 直播记忆 | 常驻事实 |
|---|---|---|---|---|---|---|
| 「在吗」 | 5 | **3802** | 3452（91%） | **无** | 无 | 周表141+词库140+时间67 |
| 「你多高啊」 | 7 | 4772 | 3452（72%） | 653 | 315 | 同上 |
| 「说好的八点直播呢」 | 7 | 4586 | 3452（75%） | 390 | 388 | 同上 |
| 「我最近好累啊」 | 5 | **3806** | 3452（91%） | **无** | 无 | 同上 |

**三条结论：**

1. **骨架占 72~91%。** 无论什么输入，她「是谁」这份底子都在。
2. **「在吗」和「我最近好累啊」一个行为都没命中** → 整轮输入 3802 字里，**只有 350 字是「当下相关」的**（= 9%）。
   这是常态：**大多数普通闲聊判不出情景**，全靠骨架顶。
3. 检索层（行为 + 直播记忆 + 偏好 + 核心记忆）总和一般在 **300~1000 字**，是总量的 5~15%。

### 4.1 实际的消息顺序

```
[0] system  ★骨架 3452 字
[1] system  周表（常驻）
[2] system  名词库（关键词命中才注）
[3] system  时间/农历/天气（常驻）
[4] system  ★行为指令（L3 命中才注）      ← 人格层，含该条行为的真实原句
[5] system  直播记忆（向量+LLM 命中才注）
[6] system  偏好 / 核心记忆 / 会话记忆 / 长期记忆 / 历史（各自命中才注）
[7] system  连续索要计数（≥2 轮才注）
[8] user    ← 真正那条用户消息（最后一条）
```

## 五、分类③：一条消息进来发生什么（流程）

```
__init__._handle_chat
  → chat_window.enqueue（读秒窗口：等 3~8 秒看还有没有后续）
  → _flush：读图（vision）+ 批量归纳（batch_summary）
  → core.handle_chat
      ├─ gather_retrieval   ← 一次性捞齐：
      │    ③ classify_l3    → 行为 + 措辞组 + 连续索要  【1 次 LLM 调用】
      │    ② embed_query    → 向量               【1 次 embedding】
      │    ② corpus 初筛 → ③ judge_corpus 再审  【1 次 LLM 调用】
      │    ① terms / preferences / legendary（纯本地）
      │
      └─ build_message_list  ← 把上面 + 常驻层组装成 messages（见 4.1）
  → generate_reply
  → clean_reply（确定性兜底）→ split_reply（分段）
  → 语音优先：should_voice → send_voice，成功就不发文字
```

**每轮的固定成本：2 次 LLM 调用 + 1 次 embedding**（判行为和判语料），加上最后生成回复那次。

## 六、几个「为什么是这样」（踩过的坑，别走回头路）

### 6.1 为什么 `voice_samples.json` 被删了（2026-10-04）

它是一份独立的「她的原句」文件（86 条问答对），**按话题**向量检索注入。删掉的原因是**结构性的、治不了**：

```
behaviors   ：按【情景】选（「被夸」）→ 话题天然不同 → 只带走形态 ✅
voice_samples：按【话题】选（「吃」）→ 必然捞到同话题的完整回答 → 连内容一起带走 ❌
```

实测翻车三种：

| 用户说 | 检索到 | 后果 |
|---|---|---|
| 你今天吃什么了 | "粉丝问怎么没吃饭「 | 她答」还没吃呢" → **下一轮自相矛盾** |
| 外面下雨了 | "被问到下雨有没有带伞「 | 她答」刚淋着跑回来的" → **编事实** |
| 你最近怎么样啊 | "最近在写什么「 | 她答」要写出百年孤独了" → **近乎逐字搬** |

**并且 assistant 通道注入更糟**（n=32 对照）：样本 user 与真实 user 相邻，模型读成「连着两轮用户发言「→ **与【当前时间】」正在直播中」冲突 13/32**（改成 system 一行只 2/32）、样本词泄漏 4/32（1/32）、反问率 38%（50%）。

**处置**：86 条里该留的 **18 条已并入 behaviors 的 samples**（并为它新建了『对方问日常时答一句自己的事』这条默认情景），其余 68 条删（内容在 corpus 里已有）。

### 6.2 为什么 `traits.json` / `styles.json` 被拆了

它们是个**没有归属的文件**——内容要么本来就是情景（→ behaviors），要么是跨情景的说话习惯（→ 骨架）。

| 原条目 | 性质 | 去处 |
|---|---|---|
| 重复与自我修正 | 描述里自带触发条件（「面对窘境或需要强调时」） | → behavior『窘迫或要强调时碎碎念』 |
| 反问与挑衅式推进 | 每轮都生效 | → 骨架【说话节奏】 |
| 戏剧化叙事与画面感 | 每轮都生效 | ⛔ **删**（见下） |
| 乐观的悲观主义者 | 情景 | → behavior |

**为什么连「戏剧化叙事」也删**（而不是搬进 behaviors）：
① 它逼模型**编**——实测生成「袋鼠蹲在垃圾桶旁」「澳洲大妈说韩语」，素材里根本没有；
② 它和『被追问私事细节时含糊带过』**直接冲突**（一个要含糊，一个要讲具体）；
③ **长文本本身是直播的产物**，私聊里几乎不存在——它是「直播→私聊」的又一处失真。

### 6.3 为什么骨架里明写「私聊里基本没有讲长故事这回事」

因为**篇幅是域相关的**。素材来自直播（要讲故事撑时长），私聊不是。
不显式写的话，模型会按素材的篇幅感走（实测：加「戏剧化」风格后讲一件小事从 23 字涨到 106 字）。

### 6.4 为什么「管怎么用」的包装语都被删了

历史审计（`包装语审计.md`）的结论：**「只学语气/不要照抄/内容要针对当前话题」这类说明，实测零作用**。
原因在机制上：模型看到上下文里的问答对，走的是 **induction head 的 pattern completion**（「续写」），不是「服从指令」。
**能治的只有数据层**：不给自足句、让样本与输入不同话题。详见 `情景条目设计模板.md`。

## 八、改哪份素材、要重算什么

| 改了 | 要跑 | 为什么 |
|---|---|---|
| `core/system_prompt.txt` | 重启 bot | 进程内缓存 |
| `behavior/behaviors.json` | 重启 bot | **不走向量**（LLM 分类） |
| `world/core_stories.json` | `run_tool.py precompute core-stories` | 走向量 |
| `world/statement_final.json` | `run_tool.py generate-vectors -i persona/world/statement_final.json`（**别省略 `-i`**） | 走向量 |
| `world/preferences.json` | 重启即可 | **不走向量**（关键词） |
| `world/terms.json` / `legendary.json` / `schedule.json` / `stickers.json` | 重启即可 | 关键词 / 常驻 |
| 任何素材 | **跑 `retrieval-eval` + `regression --check`** | 单元测试测不出「该不该命中」 |

> ⚠️ 改完数据/代码**必须重启 bot**（有进程内缓存）。
