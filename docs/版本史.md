## 版本规则

- 版本号形如 `V<大>.<小>`。
- **小更新 +0.1**：修 bug、调参数、补数据、加个小功能。
- **大更新 +1**：架构级变化（数据分层重构 / 检索层判据改造 / 新增子系统）——大版本号 +1，编号落到 `X.0`。
- 小版本满 `.9` 再 +0.1 自动进位到 `X.0`。
- **一个版本 = 一批相关改动**：同一天、同一主题的多个提交并成一个版本。

全史 34 个版本，其中**两次大更新**：

| 大更新 | 日期 | 为什么算架构级 |
|---|---|---|
| **V6.0** | 2026-08-13 | **拆 core.py 分四层**：persona 按职责分四子目录、记忆归位、core 1069→584 行——"该改哪"第一次有答案 |
| **V7.0** | 2026-09-10 | **提示词下沉 + 模块重构（P3/P4）**：规则从提示词搬回数据层，天气异步化、记忆加载归位、桥公共件抽取 |

> 诚实说一句：2026-09-25 的**检索层判据改造**（V7.7–V7.8）同样够得上架构级，
> 但 V5.5→V7.8 这个跨度在 "+1 = 十个小更新" 的规则下只容得下**两次**大更新，
> 而终点 V7.8 是已经对外报过的号（不能动）——所以它记在两个小版本里。

V1.0–V5.5 的编号沿用 README 原有的叙述（V1 / V2 / V3 / V3.1–V4 / V5 / V5.1–V5.5），

### V5.5（2026-08-12）· 人设工程大修：身份分层 / 聊天感 / 去标签 / 防复读
**提交：** 20cbd55（大修）、57ce3b2（灵活拆分）、2b625b1（恢复锋芒）、3e5e95b（行为检索）、
9c48b32（人格评测证据）、5058f71（ROADMAP 补全）等当天 20+ 提交 ｜ 测试 160 → 162

一整天围绕"少轮聊天质量"做的人设工程。核心方法论：**治本在输入层（提示词 / 素材），
确定性兜底只在模型默认习惯压不住时才上**；已踩过"用参数压症状"的坑（`SPLIT_MAX_PARTS` 4→2 治段数 →
对话变怪 → 还原）。

- **身份分层（人设 × 真实经历）**："永远 16 岁的风纪委员"是官方对外人设——被问身份就答这个；
  "虚拟主播"是职业、心里默认但**对外装傻**；真实经历（留学 / 四川 / 搬家）用"灰泽满"自称 + 地名加"虚拟"前缀讲述。
- **符号纪律**："省略号是常态" → "**省略号是例外**"（真人 QQ 聊天几乎不打符号）；禁"你、你""就、就"式结巴；
  `clean_reply` 加省略号兜底（归一连串 + 整条约 2 次上限 + 剥开头省略号）。
- **多句 / 分段（治本）**：4 段式的根源是提示词**明令多句**（"回应之后要回抛问题 / 补细节 / 自爆"）→
  重写成"把反问 / 细节 / 自嘲**揉进同一句**把话题带下去"。
- **灵活拆分**：短碎片（<12 字）并入邻居，治"哦？"被切成 4 条戏剧节拍；
  `SPLIT_MERGE_MIN_CHARS` 12→8 修回被并掉的**真整句**（12 太激进，11 字完整句被并回去导致句号不分割）。
- **情绪克制 → 恢复锋芒**：第一轮"减法"过头（克制 / 平淡 / 少语气词），把嘴硬、自嘲、俏皮一起削了，
  用户直接说"她变笨了" → 改成"**平静但有锋芒**"：语气词是味道不是毛病，直播问题给干脆答案、别反复绕圈子。
  **教训：符号纪律管的是"别堆"，不是"别表达"。**
- **素材层省略号清洗（治本）**：根源查清 = 模型 RP 默认腔（主）+ 15% 的 voice_samples 带省略号（次）+
  旧提示词"省略号是常态"（已修）→ 清洗 4 条重灾样本、机械停顿改逗号，只留情绪顶点 1 个，重跑向量。
- **行为反应 → 行为底色**：删掉带引号的台词例句——具体触发-响应交给 behaviors、具体措辞交给 phrases，
  防"prompt 点名口癖 → 模型每条都加"。
- **标签去名化**：核心人格删"-主义者"这类临床标签（只留行为叙述）、traits 的"回避型亲近者"行为化、
  corpus 清标签语（17 条重写 + 重新向量化）。**标签是 tell，模型会当行为模板过度执行。**
- **复读机防护（确定性）**：`_is_echo_reply` 用最长公共子串检测（覆盖 ≥60% 就判复读）+ 强制重新生成——
  **提示词拦不住模型执着复读，得靠代码拦**。
- **话题接地 + 不懂就说不懂**：`probe_session` 的话题提取不许脑补对话里没有的设定（时区 / 位置 / 身份）；
  没听过的词大方说不懂或反问，别硬接编细节。
- **行为检索修复（结构性 bug）**：阈值 0.65 太高（口语质问天花板约 0.55）+ trigger 描述太"分析师化" →
  "被质疑 / 失约被催"几乎从不触发。修：口语化重写 triggers、阈值 0.65→0.55、加**关键词兜底**
  （敷衍 / 骗 / 装的 / 迟到 / 鸽 / 说好的 → 强制命中）。
- **名词库 `terms.json`（lorebook）**：绿冻 / 枪神 8 / slg / HIKAMI 等——核心词 always 注入，
  其余命中才注入；`meaning` 客观打底 + 带她的态度，`reaction` 给固定反应方向（装傻 / 避而不谈）。
  **设计原则：'懂'进 terms / '忆'进 core_stories / '答'进 LEGENDARY，一个词只进一层。**
- **「妈妈」从 terms 挪到 LEGENDARY**：它是常见词（"我妈"也算近），纯关键词会误伤 →
  LEGENDARY 的"关键词 + LLM 语境确认"双路由能分清"喊灰泽满妈妈求宠"和"我妈让我早点睡"。
- **人格数据分层去重（⑤路线：去重 → 增补 → 打磨）**：核心人格精简为 essence（详细性格让给 traits）、
  说话节奏删反问细节（让给 styles）、styles 删括号内心独白（system 已覆盖）。
- **补泛闲聊样本**：voice_samples 补 10 条 casual（熬夜 / 过期鸡蛋 / 感冒 / 吃没吃饭 / 游乐园）——
  治"日常对话回归 RP 腔"的总根；这批素材走 `statement_final → convert-to-chat` 新路线，
  因为**直播素材里挖不出泛闲聊**（新增 `mine-theme` 主题挖掘工具，语义找素材而非关键词硬搜：
  "立 Flag"关键词搜不到，模型挖出 7 条；同批试挖"被表白"得到 0 条，**直接放弃建条目，不硬凑**）。
- **behaviors 第 8 条**"失约被催时认栽滑跪"（samples 全是真素材：生日连麦超时 / 抢 TWICE 票滑跪 / 背疼下不了床）；
  traits 补**价值观维度**（珍惜细水长流 / 警惕捧杀 / 真实不装）。

### V7.2 ·【一致性规则】改成"只管事实" + 事实通道的时效
**提交：** 9e00fde、eed07e0

- **旧文案是错误放大器**：原「解释同一件事时**借口要与之前保持一致**，不要前后矛盾」——**这是直接教它复读**。
  本意是防前后矛盾，实际效果却是把**第一次的随机选择**变成**永久设定**，已经咬过两次：
  **"威严"复读**（第一次用了"威严"，规则就要求之后都用它）和**"搬家"用了一周**。而且规则原文只管"借口"
  这类事实性解释，模型却把它泛化到了**立场 / 态度**上。改成【**别自相矛盾**】：**只管事实别打架**
  （说过的原因、安排、答应过的事下一轮别改口成另一套），**明确不管说法和态度**，
  并直说"**宁可换个方式说同一件事，也别逐字复读**"。
- 顺带补了旧【防复读】的漏洞：它的豁免条件是"用户没有主动追问时"——而用户反复追问**正是复读高发场景**，
  等于**在最需要它的地方自动失效**。现在改成"可以正面回答，但换个说法、别把上轮那句原样搬出来"。
  这样提示词就和代码兜底对齐了：`is_echo_reply`（整句级、窗口 8、3 次重试 + 每次校验）本来就在拦逐字重复。
- **事实类通道的时效**：被问"为什么又迟到 / 不直播"时她总答"在收拾搬家"——`schedule.json` 的「近况」
  更新于 09-05，到 09-12 已经 7 天，却被**无条件注入**，只在文本里附一句"（更新于 X，过期就忽略）"，
  **指望模型自己判断时效**。而模型既不知道过期阈值，也没有"今天 vs 更新日"做减法的习惯。
  更糟的是【一致性规则】在当错误放大器：一旦说了一次"搬家"，借口就被锁死——**错误不会自我纠正，只会自我固化**。
  这不是孤例，是一类问题——数据层存了时间戳、注入时全部丢掉：

  | 通道 | 存了时间 | 之前注入时 | 后果 |
  |---|---|---|---|
  | `schedule.近况` | ✅ `近况_updated` | ❌ 无条件注入 | "搬家"锁死一周 |
  | `group_memory.events` | ✅ `t` | ❌ 只取 `text` | 上周群里的事当"群内近况" |
  | `significant_moments` | ✅ `date` | ❌ 只取 `summary` | 几个月前的事当"最近的记忆" |
  | `last_seen` | ✅ | ❌ 从不注入 | ← V7.1 刚修的那个 |

- **修法（时效判断归代码，不归模型）**：
  1. `schedule` 近况加 TTL（`SCHEDULE_NOTE_TTL_DAYS = 7`）——**超期就整条不注入**，
     而不是"注入 + 一句警告"。过期的事实等于不存在；`core` 里已有的 guard 规定了"没原因就大方说不知道"，
     所以撤掉近况后她的行为是**正确**的，不是空缺。
  2. 群近况事件、长期"最近的记忆"**注入时带上相对时间**（"3 天前" / "昨天" / "1 个月前"），复用同一份措辞函数。
  3. 为此加了按**天**粒度的 `format_day_gap()`：纯日期没有小时精度，复用按秒的函数会把"今天的记忆"
     算成"18 小时前"——**假精度**。

### V7.3 · 撤回水位线 + 微博图床 Referer + 删掉防措辞固化
**提交：** 75272bd、904b18b、6367fd3

- **她撤回一条动态，bot 把昨天的又推了一遍（修 bug）**：动态去重状态里只记**一条** id，
  判据是"**新 id ≠ 记的那条**"。她撤回最新那条后，接口返回的"最新"退回成上一条（更旧、id 更小），
  与记的不同 → 被判成新动态 → **把昨天的动态又广播了一遍**。置顶 / 删博回退同理，微博侧有一模一样的缺陷。
  修法：改成**水位线**——只推"比已见过的最大 id 更新"的。先实测确认了两边 id 都**随时间严格递增**，
  所以"更大 = 更新"成立；判据收敛成 `_bridge_common.is_newer_id()` 一处，两个桥共用。
  基线（prime）也改成"只升不降"。异常数据（非数字 id）退回"不同即新"，保持老行为不倒退。
- **微博配图修复（图终于发得出来了）**：病根在下载那一步，不在解析——**下载时没带 Referer**，

  带 `Referer: https://weibo.com/` → HTTP 200 / 331KB**。修法：把微博图床登记进 `vision._referer_for` 的
  "按图源选 Referer"分流表（那张表此前只登记了 QQ 和 B站，微博是漏的）。下载失败只打日志、不阻塞推送，
  所以表现是"**文字发得出去、图全丢**"。教训写进 docstring：**每接入一个新图源，都要回来登记一次**。
- **删掉"防措辞固化"（一个在帮倒忙的兜底）**：它统计最近几条回复里反复出现的 2 字词，命中就强制换措辞重生成。

  而"威严"那次真正修好它的其实是数据层（behaviors + 判别词）。**口癖这类问题回到数据层解决。**

### V7.4 · 三类"悄悄的失败"：语音被打断 / 表情认不出 / 解析崩了看不懂
**提交：** 0a0f391、281d5a2、e94e70f、0278790、6ac2676

三次失败有个共同点：**它们都不报错**。

- **语音"转出来了但没发出去"**：TTS 明明合成了，消息却没发；而且**时有时无**。根因：`send_voice` 里
  `await _synthesize()` 要几秒（GPU），而 `enqueue` 在收到新消息时会 `win.task.cancel()` 把正在跑的 `_flush` 打断 →
  `CancelledError` 是 `BaseException`，**`except Exception` 抓不到** → `_flush` 直接死掉：
  **wav 已经写进缓存、消息没发出去，文字兜底也不会走**。修法：给语音那一步加 `asyncio.shield`——
  **合成 + 发送一旦开始就让它做完**。另加一道前置判断：起跑后若已被新消息取代，就别再占 GPU 去合成。
  顺带修 `_to_qq_voice` 的 `file:///` 路径（Windows 上 `resolve()` 给反斜杠，漏了 `.as_posix()`），
  **但诚实说它大概率不是本次原因**——路径格式确定的，若它致命就该"一条都发不出去"。
- **QQ 内置表情识别补全**：有些表情她看不懂，消息变成 `[表情：QQ表情6]`，模型只能瞎猜。
  根因：`_extract_face_text` 优先读 NapCat 给的 `raw.faceText`，**但实测有些消息拿不到**，只剩裸 id。
  修法：加一张 **face id → 中文名** 兜底表（248 条）。**表从哪来（重要，别手抄）**：直接从
  **QQ 客户端自己的表情配置**提取（`<QQNT>/resources/app/resource/default-emojis/default_config.json`）。
  **关键坑**：提取规则是 `face id = qzoneCode - 100`（经典小黄脸）/ `qzoneCode - 10000`（新表情），
  **不能用配置里的 `emojiId`**——那是面板自己的编号，跟消息里的 face id 不是一回事：
  配置里 `emojiId=0` 是"惊讶"、`14` 是"微笑"，而消息里 **0=微笑、14=惊讶**（正好相反）。
- **LLM 响应解析加护栏**：会话记忆、行为意图分类、长期记忆提取**同时**报 `'NoneType' object is not subscriptable`——
  三个不同模块同一句话，完全没法定位，其实是**同一个上游形状问题**（9 个调用点都直接写
  `resp.choices[0].message.content.strip()`，上游偶发返回 `choices: null` 就炸）。
  **顺带堵住一个更危险的静默坑**：`deepseek-flash` **默认开思考模式**（不传 `thinking:disabled` 时
  `content` 是**空串**、`reasoning_tokens` 吃光 `max_tokens`）——以前这种情况 `.strip()` 不报错，
  **静默返回空串**，记忆提取 / 行为分类会当"这次没结果"处理，**功能悄悄失灵、日志上什么都看不到**。
  修法：新增 `config.extract_chat_content(resp)`，把三种坏形状统一翻译成人话，9 个调用点全部改用它。
- **兜底回复不再进记忆**：那一轮失败的**兜底文案被写进了短期记忆**（`灰泽满：哎呀，hzm脑子卡了一下……`
  成了"她说过的话"，还会作为 few-shot 喂回去）——**一次上游抖动 = 一份永久污染**。
  现在兜底文案由 `is_fallback_reply()` 识别，命中就**整轮不记**（短期 + 长期都跳过）。
  另：`generate_reply` 的兜底不再把异常原文拼进去（那是内部信息，会原样发给每个用户）。
- **诚实说明**：这个偶发**没能复现**（单发 / 6 组参数逐条发 / 8 路并发发全正常）——所以修的是**脆弱性**
  （同样的形状再来时能一眼看出），不是"某个必然触发的 bug"。

### V7.5 · 微博"读不到"的两层坑：负数的 ok，和顶掉新 cookie 的旧 jar
**提交：** 5b157bb、bb8980d ｜ 测试 422 → 431

- **09-17 误报"该 UID 暂无微博"**：微博的失败码是**负数**（-100 = 未登录 / 被风控），而代码写的是
  `if not data.get('ok')`——`not -100` 是 `False`，**错误分支被整个跳过**；跳过之后 `data` 是 null → 列表空 →
  报成"该 UID 暂无微博"，**把排查方向带偏成"她没发微博"**。顺带发现未登录时登录态藏在 **body 的 `url`** 里
  （不在 302 的 location 头，原来只查 location 的"Cookie 失效"提示**永远不会触发**），现在两者都认，
  且措辞里特意带"登录"二字好让节流提示能识别。空列表也不再断言"暂无微博"，改成"多半是风控限流"。
- **09-18 "换了 cookie 还是不行"**：`_load_jar` 是 `base = .env cookie → base.update(jar)`，
  **jar 优先级更高**（本来是为了接住微博续期下发的 `Set-Cookie`），于是**旧 jar 里那份失效会话把新填的 cookie
  整个顶掉**——实测 9 个键（SUB / WBPSESS / XSRF-TOKEN / ALF / PC_TOKEN…）**一个都不是新值**，换几次都没用。
  修法：jar 存一份"**基于哪份 .env cookie 续期**"的指纹 `_base_fp`，指纹对不上就**整份忽略、回到 .env 的值**；
  旧格式（扁平 dict、无 `_base_fp`）一律视为过期，安全迁移。实测修复后 9/9 个键都来自 .env，真实拉取成功。
- 顺带把三轮深度调研归档成 `调研-角色对话AI架构.md`（含**证据强度分级**与行动清单）。

### V7.7 · 群聊新能力 + 素材本土化：把"接不接话"变成判据
**提交：** 4dbe279、d0e551e、ef3f5f5、a81c282、126765d、354f935、f6ab27c、8a45411

**四个原始问题（都是真实聊天里咬到人的）**

- **用几个月前的记忆回答当下**：问"今天为什么不直播"，她答"搬家的事还没弄完"——而搬家出自 80 天前那场。
  根因**不是**检索排序，是 `voice_samples` 是**唯一以 assistant turn 注入的通道**（"她本人的话"）——
  同一个事实从 corpus（system 说明）进来说 0/5 被采用，从 samples 进来 3/5。
  → **素材本土化**：16 条样本里"某一回的具体情境"改写成"她一贯如何"（实测 3/5 → 0/5）。
  判据：**样本携带的情境越具体越危险**——"明天要搬家"会被当成现在。
- **群里"有话就接"**：新增 `group_gate.py`——攒批安静下来时先判"这批要不要开口"。
  判据由用户标定：**①明确问她 → 必接 ②有情绪表达（纯情绪也算）→ 可以接 ③分享经历 → 偶尔
  ④纯事务 / 附和 / 收尾 → 不接**。⚠️ 判定粒度必须是**批**不是单条（逐条判会"蹭余温"：
  情绪一出现后面每条都靠它的余温被判该接）。**点名了她 → 确定性放行，不调 LLM**（能确定的事不该多一次判错的机会）。
- **同话题回复高度同质**：14 条回复里 8 条以"呃，"开头——而 86 条真实素材里**0 条**这么开头。
  根因是 `behaviors.response` **写死了措辞**（"'呃…'起头"），而注入端写着"**请严格按此模式回应**"。
  → response 只描述"**做什么**"，不描述"**用哪个词**"（措辞是台词，归 samples 承担）。实测 10/10 → 0/10。
- **QQ 引用消息看不到**：适配器其实**早就**调了 `get_msg` 挂在 `event.reply` 上，我们从来没读过。

**新增能力**

- **读合并转发**：取回后**先摘要再注入**（转发几十条几千字，原文会挤爆上下文；实测 1951 字 → 一句话）。
- **发表情包**：24 张（原图是 avif，**QQ 不认，已转 png**），文件名是哈希所以**离线用视觉模型打标**。
  判"这句话配哪张"，**十分对应才发**；失败**不发**（发错比不发难看）。
- **主动发言**：抓到动态 / 微博 → 转成"她会主动说的那句话"（走人设 + 按内容检索的风格样本）。
  现在**原文和这句话两条都发**——转写质量差时，粉丝既看不懂原文、也没得到人话。
- **周表图拖拽更新**：`更新周表.bat`，把图拖上去即识图写入（存 GBK / CRLF，否则 cmd 中文乱码）。
- **可复跑的判据回归**：`ef3f5f5` 把**真实翻车**固化成确定性判据（`regression_test.py --check`），
  顺带修好**导入即崩**的 `retrieval_eval.py`（坏了很久没人知道）。

### V7.8 · 检索层判据改造 + 四处修复（当前版本）
**提交：** f7b27ef、c31f505、35c3517、f2045f0、4cc9c52、cf2d01d、949e4a9 ｜ 测试 528 → 534

**检索层体检（工具化，不再靠猜）**

- 新增 `scripts/threshold_scan.py`：量每路的**噪声地板**（15 条明确无关的输入能顶到多高）。
  体检结果：`voice_sample` 0.610 → 阈值 0.60 **压在地板上**（提到 0.66，评测 27→28/29）；
  `phrase` / `preference` **真信号和噪声完全重叠，任何阈值都分不开**（→ `待办清单.md` 第一节）。
- 新增 `scripts/coverage_check.py`：真实对话下六路全空只有 **1%**——痛点不是"读不到"，
  是"**读到了不该读的**"。
- **corpus 召回重做**：口语问句与第三人称陈述**不同构**（「你多高啊」→ 0.443，低于噪声地板）。

  落地成 `corpus_judge.py` 并加 21 个测试，评测改**镜像线上**，`retrieval_eval` **28/29 → 31/32**
  （诚实标注：这一轮按 `交接文档.md` 记的是"**尚未提交**"——`corpus_judge.py` 与它的测试在整理时仍在工作区）。

- **`corpus` 索引改造（工具）**：`scripts/run_tool.py` 侧的语料索引重建 + **交接档案重写**

**判定兜底方向（三个功能各自不同，别搞混）**

| 功能 | 判不出来时 | 为什么 |
|---|---|---|
| 群聊接话门 | **放行** | "该说时不说"比"多说几句"难发现 |
| 表情包 | **不发** | 发错比不发难看 |
| 主动发言 | **退回通知模板** | 粉丝本来就该知道她发了动态，信息不能丢 |

**其他修复**

- 表情包冷却**根本没生效**（bug）：状态挂在会话窗口上，而窗口空闲就被销毁——私聊里每轮之间必然有静默，
  于是每次都重建、每次重置。表现成"睡觉话题每次都会发那张眠了"。
  **修法**：状态改挂 `target_id` 的模块级 `_sticker_state`；`avoid_ids` 同时从"最近 3 条"扩到全部最近发过的
  （`STICKER_RECENT_KEEP=8`）——用户报的是"**同类**太频繁"，换个话题回来还会撞上同一张。
- 转发动态的**被转发原文一直没读到**：`orig` 在 **item 顶层**，代码查的是 `module_dynamic["orig"]`。
  改成顶层 + **递归**（可能是嵌套转发），拼成 `{她写的话}（转发自：{原文前 150 字}）`。
- **群聊点名 → 确定性放行**：`_addressed_to_her()` 命中（灰泽满 / hzm / 小满 / 满姐 / 满宝 / 满哥）直接接，
  **不调 LLM**——能确定的事不该多一次判错的机会。
- 主动发言"忘记说重点"：prompt 里"别像播报…**就像跟朋友顺口提一句**"被理解成了"少说信息"，
  于是"明天来玩"这种**邀约**被删掉。补一条把话说死：「随口」指的是口气，不是少说信息。
  **实测**：同一条动态各跑 3~4 次，修前 3 条里只有 1 条带邀约，修后 **4/4** 都带。
  **但这是概率改善不是保证**（提示词约束的老毛病）；真要保证信息不漏得做成两步（先抽要点、再用她的口气说），
  先不拆，观察真实效果。
- bili / weibo 的推送测试**真的在调 LLM**（28s → 13s）。
- 删掉 `schedule.json` 的「近况」注入——它治不了"用旧记忆回答当下"，而且手动维护必烂（实测烂了 20 天）。
