# 她是怎么"说话"的 —— 一篇能读完的说明

> **这篇是给"想搞懂"看的。** 两份参考手册分工不变：
> `注入链路.md` = **现在是什么样**（素材清单、每层多少字）｜ `注入设计原理.md` = **为什么、带全部实验数据**。
> 这篇把它们合成一份**能一次读完**的：为什么这么设计、现在什么样、凭什么说它是对的。
> 最后更新：**2026-09-30**（含删掉 10 处无效包装语之后的现状）

---

## 0. 一句话

**这个机器人不是"一个提示词"，是 17 段按需注入 + 一张 3758 字的常驻骨架。**

绝大多数角色扮演是"一个提示词包"（酒馆那种）。这里不一样：**人格拆成了十几份文件，
每轮按"这句话碰到了什么"去检索、只注入该注入的那几段**。真正的资产是 `persona/` 里那批
**从直播里蒸馏出来的数据**。

---

## 1. 一条消息进来，发生什么

```
① 收到消息        → 进"读秒窗口"（攒批：等几秒看他还说不说，说完一起处理）
② 读图 / 归纳      → 有图片先描述成文字；一批 >1 条先归纳成一两句
③ 检索（六路）     → 拿这句话去几个库里找素材（见下一节）
④ 组装 messages   → 17 段 system + 她本人的原话对（assistant）+ 用户那句
⑤ 生成            → 交给模型（DeepSeek）
⑥ 后处理          → 拆句、去括号、省略号纪律、防复读、换行归一
⑦ 发送 + 回写记忆  → 分批发（打字感）；可能发语音/表情包；写回短期/长期记忆
```

**关键在 ③④ 两步**：不是把所有素材一股脑塞进去，而是**按这句话去挑**。
这就是"数据驱动"的落点——数据是资产，检索是让资产在对的时候出现。

## 2. 三样东西决定她的行为

这是理解全项目的总纲。三样经常被混为一谈，但它们各管一件事，而且**各有各的实验结论**：

| | 管什么 | 手段 | 一句话结论 |
|---|---|---|---|
| **判据** | 这句话该不该唤起某段素材 | 分类 / 关键词 / 向量+LLM 判 | **按任务选，不能统一** |
| **形式** | 唤起的素材会被怎么用 | 问答对 / 碎片词 / 陈述 / 指令 | **看"是否自足"** |
| **位置** | 素材以什么身份进上下文 | system 说明 vs assistant 发言 | **通道比位置更要紧** |

下面逐条给数据和例子。

## 3. 为什么这么设计（每条都有实验）

### 3.1 判据：**"检索"底下其实是三种任务**

那是把这三个混着看才会觉得"检索很难"。拆开看，各有各的工具：

| 任务 | 特征 | 该用什么 | 谁在用 | 实测 |
|---|---|---|---|---|
| **归类** | 类别少（十来条），判"这句属于哪类" | LLM 分类 | 行为 / 措辞 | 措辞开火 **100% → 20%** |
| **关键词命中** | 类别名用户能直接说出口 | 子串命中 | 名词库 / 梗库 / 偏好 | 偏好开火 19% → **5%** |
| **检索** | 要从一堆里**挑**，说法不可枚举 | 向量召回 + LLM 判 | 直播经历 / 说话样本 | 见下 |

**踩过的坑（值得记）**：措辞和偏好**原本都坐着"向量检索"的位子**，而它们分别是"归类"和"关键词"任务。
结果：

```
措辞  噪声地板 0.575 ｜ 真信号 0.573   → 完全重叠，阈值形同虚设（100% 开火）
偏好  噪声地板 0.565 ｜ 真信号 0.501/0.552/0.590 → 地板插在正例正中间
```

**根因**：措辞的 `trigger` 是 `"被夸奖、被称赞时"` 这种**类别标签**，不是句子。
拿"用户说的话"去和"一个类别标签"算余弦，是**拿检索工具干分类的活**。

同一个形状的问题，`behaviors` 是通的——它从不拿 trigger 去匹配，而是 LLM 判意图。
**差别只在工具。**

### 3.2 形式：**决定素材"会不会被整句抄走"**

同一个事实（"最喜欢的数字是 7"），写成不同形式，各跑 16 次：

| 形式 | 对应文件 | 采用率 | **逐字复读率** |
|---|---|---|---|
| 不注入（基线） | — | 9/16（瞎猜） | 0/16 |
| system 第三人称陈述 | 直播经历 | 16/16 | **10/16** |
| system 词表（**自足**） | — | 16/16 | **16/16** ← 整个抄走 |
| system 碎片词表（**不自足**） | 措辞 | 5/16 | **0/16** ← 织进新句 |
| **assistant 问答对** | 说话样本 | **15/16** | **0/16** ← 唯一两者兼得 |

**三条结论：**

1. **传不传得进去，从来不是问题。** 只要注入了，全都 15~16/16 用上了。
2. **真正分得开形式的是"会不会被整句搬走"。** 变量不是"哪个文件"，是**"注入的那段是否自足"**：
   - 自足（能独立成句）→ 模型**照抄**
   - 不自足（碎片）→ 只能**织进**她自己造的句子
   - 他本人的原话（assistant 通道）→ **既不抄、又传得进**
3. **每个文件该长什么形式，是能查表的：**

```
想要她"当事实知道"  →  写成事实条目          （偏好 / 名词库）
想要"当风格学"      →  写成问答对            （说话样本）
想要"当台词说"      →  写成自足句（它一定照抄）（梗库）
想要"当措辞用"      →  写成碎片              （措辞）
```

### 3.3 包装语：**零作用**

每个注入段外面都包了一句说明，比如给直播经历那段写了两百多字「只当'她记得的经历'自然带出…不整段复述…」。

**实测：把包装句换掉，模型行为一模一样。**

```
④ 词表  + 「用这些原话组织」      → 逐字 16/16
⑧ 同④的内容 + 「不整段复述」     → 逐字 16/16   ← 一模一样
```

**所以结论是：文件的"角色"不写在包装语里，写在内容形式里。**
（⚠️ 边界：包装语**可能**仍在管别的事——比如"这条比那条优先""这是过去的不是现在"。
那类叫"事实/时间/优先级声明"，不是"怎么用"。2026-09-30 已逐条审过，见 `包装语审计.md`。）

### 3.4 通道：**比位置更要紧**

同一个事实，走两条不同的通道：

```
走 assistant（她本人说过的话）  → 被采用 3/5
走 system（关于她的说明）      → 被采用 0/5
```

**"她本人的话"比任何 system 说明都强。** 这也是为什么"说话样本"那一路特别值得投资。

⚠️ **别过度外推成"所有 system 都没用"**：3/5 vs 0/5 是拿**同一个事实**比的。
system 里放"**信息**"（告诉她一件事）是有效的——【当前时间】【周表】那类实测作用巨大（见 5.1）。

（原来是 18 段；2026-09-30 删掉了【回复节奏】——它和骨架【说话节奏】重复。）

### 4.2 预算分布：**骨架吃掉了绝大部分**

```
常驻 base（骨架 3147 + 性格基底/语言风格 611）   3758 字   ← 每轮无条件
检索层真正注入的内容                        平均 ~125 字   ← 约 3%
```

**这是个很不平衡的分布**，而且已经量过它的后果：
- 常驻那 3758 字：砍到 2315 字时**用户能看出来**（6/6 选原版）→ 说明**那 3758 字是值的**
- 检索层那 125 字：**以极小体量压过大量 system 说明**（说话样本 107 字，采用率就能到 3/5）

**所以"预算"不是按字数算影响力的。** 这是这个项目最反直觉的一条。

### 4.3 各素材用了多少（真实对话里）

| 素材 | 规模 | 真实用到 |
|---|---|---|
| 直播经历（corpus） | 322 条 | **37 条（11%）** |
| 名词库 terms | 27 条 | 3/26 |
| 经典梗 legendary | 8 组 | 3 条（入口覆盖 25%→**89%**已修） |
| 行为示范 behaviors | 11 条 | 3/11 |
| 说话样本 voice_samples | 86 条 | 11/86 |
| 措辞 phrases | 74 条 | 开火 100% → **20%** |
| 周表 / 当前时间 | — | **总是注入** |

**怎么读这张表**：素材"用得少"**不等于**"没用"——很多是"**只有被提起才该想起来**"。
（这块 2026-09-30 绕过一次弯路，见 §7 的教训。）

## 5. 凭什么说它是对的：五套判据

**这是整个项目最值钱的部分**——不是"我们做了很多优化"，而是"**我们有一套能证伪自己的判据**"。
不同的问题要用不同的判据，用错了会得出完全相反的结论（这一条我们踩过好几次）。

| 判据 | 答什么问题 | 怎么跑 | 现在 |
|---|---|---|---|
| **1. 检索评测** | 这句话该不该唤起某段素材 | `run_tool.py retrieval-eval` | **47/48** |
| **2. 判据回归** | 真实翻车的判据有没有被弄坏 | `run_tool.py regression --check` | **8/8** |
| **3. 任务正确性** | 她**答对了没有** | 消融 + 硬判据 | 见 5.1 |
| **4. 形式三指标** | 素材有没有被用好 | 采用率 / 逐字率 / 撞车率 | 见 3.2 |
| **5. 单元测试** | 代码行为有没有变 | `pytest -q` | **765** |

### 5.1 内容类：**作用巨大，而且是客观的**

拿"同一批消息、只删掉那一段"来比：

```
删掉【周表】        问直播时间：答对 88% → 0%
删掉【当前时间】     问日期星期：答对 92% → 0%
删掉直播经历        问"你多高"： 4/4 → 0/4
```

**判据是"她答得对不对"**——答案就在文件里，**不需要任何人当裁判**。这是最硬的一类证据。

### 5.2 形式特征基线（2026-09-30 新加）

数她回复里的**可数特征**，得到一条基线：

```
省略号率 17% ｜ 自称率 70% ｜ 问号率 25% ｜ 括号率 13% ｜ 句长 20.3
```

**它的用途**：以后**任何改动**（删文件/换写法/压缩）跑一遍，看这几个数掉没掉。
**掉了 → 回退；没掉 → 通过。** 这就把"改坏了没有"变成了数得出来的事。

例：删掉性格基底+说话风格（611 字）→ **省略号率 22% → 6%**（8 对里 7 对是这个方向）。

### 5.3 ★ 净作用 = 基线 − 裸模型（这一轮最重要的方法）

**问题**：模型自己就会做的事，不能算到你的数据头上。

**例子**：给她一个"被夸"，看她否认不否认——

```
有全部人格文件    88% 否认
裸模型（只有身份）100% 否认   ← 裸模型比有文件还高！
```

**→ "被夸时嘴硬"是模型的先验**（"傲娇 vtuber"是它的常识），**跟你的数据无关**。

同一批实验里的对照：

| 情境 | 有文件 | 裸模型 | **净作用** | 结论 |
|---|---|---|---|---|
| 被夸 → 否认 | 88% | **100%** | **−12pp** | ⚠️ 模型自带，**别为它花预算** |
| 被捧高 → 推拒 | 38% | **0%** | **+38pp** | ✅ **你的数据真的在教它**（三份文件共扛） |

**这个减法必须做**，否则会把"模型本来就会的"当成"我的数据起作用了"。
（文档里早就有同类教训：测「挑食 → 不吃香菜」时，**不注入的基线也有 13/16**。）

## 7. 这一轮学到的方法（含一次弯路）

### 7.1 弯路：「用人来判'像不像她'」这条路走不通

试了三把尺子：长度/括号指标 → 指纹距离 → LLM 成对比较 → **最后试"你自己盲判"**。
结果：让你标了 30 条，**23 道成对题里 20 道答"差不多"（87%）**。

**根因不是尺子不够好，是问法测错了轴**：两版是同一个模型 + 同一套 base 生成的，
**风格天然一样，差的是信息量**。而且"用人判"是**自指的**——
要校准"能不能看出小差别"，得先造一个"差不多大"的已知差别，而那正是要测的东西。

**→ 结论：别再问"单个文件有没有用"。** 换粒度：

| 你想干什么 | 用什么 |
|---|---|
| **省预算**（删/压缩某份） | 可数特征 + 逐次削减：砍一个 → 数 → 掉没掉 |
| **修问题**（她答错了） | **那一条真实翻车** → 追到原因 → 修（不需要知道全局） |
| **整体质量** | **大改动 + A/B 让你挑**（大差别你分得出，小差别本来就不值得优化） |

### 7.2 一个文件不是"有用/没用"，是**多份共扛**

「被捧高时推拒捧杀」这件事，删任何一份文件都掉 26pp：

```
基线 38%  →  删性格基底 12% ｜ 删行为示范 12% ｜ 删骨架【行为底色】12%
```

**所以"融合"是真的**——但它不是障碍：**一次只删一份，看掉没掉**，就够了。
你**永远不需要**知道"这个特征由几个文件共同支撑"。

### 7.3 别拿旧数字下决定

`注入设计原理.md §七` 原来写"141 条素材没入口该删"——**实际只剩 1 条**（钩子表后来建起来了）。

**清单里的数会过时。** 这一轮两个 ⚠️ 项都是这个毛病：撞车数从 188 条样本变到 1683 条、判别词命中数也早变了。

### 7.4 判据和旋钮要对得上

给检索权重找实测依据时发现：**现有评测根本测不到它**。
因为它判的是"每一路各自有没有召回对的条目"，而权重**只影响融合后的排序与截断**。

**→ 换判据为"融合+截断之后，期望的条目还在不在"** 才量得出来（结论：那个旋钮不敏感，不用动）。

## 8. 别走回头路（踩过的坑）

| 坑 | 为什么别再犯 |
|---|---|
| 把包装语当"控制模型怎么用"的手段 | 实测零作用，改形式才有用 |
| 给措辞/偏好上向量检索 | 它们是"归类/关键词"任务，不是"检索" |
| 靠调阈值挡误报 | 误报的重叠度**比真阳性还高**，方向是错的 |
| 往库里加条目问"是不是越多越好" | 库 10→322 条，噪声地板 0.420→0.474，而正例只有 0.443 → **库到约 100 条，真信号就沉下去了** |
| 消化验结果不看裸模型基线 | 会把"模型本来就会的"当成"我的数据起作用" |
| 用模型当"像不像她"的裁判 | 那个模型根本不知道她是谁 |
| 合成场景自测 | 场景和判据都自己造的 = 循环论证 |
