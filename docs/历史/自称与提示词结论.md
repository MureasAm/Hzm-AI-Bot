# 自称方式 / 否定句式 / 代指 —— 结论归档

> **状态：2026-10-23 起暂时搁置。** 这里只记录已经测出来的结论、上线状态和以后恢复时该怎么走；
> 不再作为「下一步」的活跃任务。相关代码/测试仍在跑，改这段提示词前先读本文件。
>
> 关联：`docs/历史/交接文档.md` 2026-10-23 的「代词错位」「自称方式的回归测试」
> 「为什么名字起手 / 才不才没」三节；`docs/下一步.md` 的已搁置区。

## 1. 目标与边界

- 目标：她**自称**时用「灰泽满 / hzm」替代「我」；同时不要退化成
  「每句名字起手」或「每句才不/才没」。
- 不在这份文件里解决的问题：整体性格要不要从「嘴硬/自嘲」改成「多数肯定」——
  那是人设/产品决策，不是提示词 bug。
- 所有实验都在 `gemini-3.1-flash-lite`（线上主模型）+ 同一套真实检索链路上做的，
  样本 24–50 条/组，属于**方向性证据**，不是统计显著性结论。

## 2. 结论速查

| 问题 | 结论 | 证据强度 |
|---|---|---|
| 名字起手 | 由「不要让名字当第一个词 + 具体替代开头」那半句压着；改成正向说法 51.1%，删自检 24.4%，原样 6.7% | 强（差异 7–44pp） |
| 才不/才没 | **模型先验**为主；素材里 0 次，整个 persona 只有检查句点名了这两个词 | 强（素材统计 + 模型 A/B） |
| 点名「才不/才没」的检查句 | 可能在加码：改成不点名具体词的版本 31.1%→22.2% | 弱（n=45，9pp） |
| 首次即重生成 | 33.3%→17.8%，15 次修 7 次；代价 ≈1/3 轮次多一次调用 | 中（n=45，方向清楚） |
| 确定性归一 | 只改名字/句读后的「才不/才没」，覆盖 94%，零成本；未上线 | 中（2082 条真实回复抽查） |
| 整体翻成多数肯定 | **靠提示词做不到**：肯定优先反而 73.3% 否定 / 才不 44.4%；先行动后嘴硬 62.2% 否定 / 11.1% 肯定 / 才不 31.1% | 强（方向反直觉） |
| behaviors 是主要否定源吗 | **不是**：有行为轮才不 18.5% vs 无行为 24.3%；同题去掉行为块才不 75%→75%，只降其他否定词 16.7pp | 中（轨迹 2,527 轮 + 24 条因果对照） |
| 「真拿灰泽满没办法」 | 无主语的「真(是)拿…」里把对象「你」被自称名顶掉；已有窄兜底 | 强（4 例真实日志 + 单测） |

## 3. 名字起手：为什么只能「原样保留 + 追加」

现役「自称方式」：

> 默认用“灰泽满”或“hzm”称呼自己，不用“我”代称自己。不要让“灰泽满”当一句话的第一个词；
> 句子开头可以是接话、反问、判断或直接陈述，再把名字放进去。指对方时仍然用“你”……
> 不要把指代对方的“你”换成“灰泽满”。

A/B（各 36–45 条）：

| 变体 | 名字起手率 | 说明 |
|---|---|---|
| 旧版（只到“再把名字放进去”） | 2.8–5.6% | 好 |
| 弱化原句（“需要自称时，可以先…”） | **52.8%** | 坏，已回退 |
| 恢复原句 + “只有需要指自己时才用名字” | 19.4% | 仍偏高，已回退 |
| 恢复原句 + 只追加指代规则（现役） | 8.3% | 旧版噪声内 |
| 改成正向说法（“从接话/判断说起”） | **51.1%** | 坏，已回退 |

**结论**：那半句是**承重句**，不是可优化的文字。以后只能追加，不能改写/删弱；
`tests/test_core.py` 有断言锁着原文。正向说法在本模型上不管用。

## 4. 才不/才没：模型先验 + 提示词点名

- 全库 20,772 条回复：含“才否定”2,096 条（10.1%）；才不 1342、才没 752、
  才没有 424、才不是 377；替代说法 哪有 330、少来 324（差一个数量级）。
- 全 `persona/` 里这两个词只出现 **1 次**：骨架里那句
  「回复前检查一遍：如果有“才不”“才没”，换一种说法再发。」behaviors / corpus 0 次。
- 模型 A/B（同一套提示词）：gemini-3.1 **10/20**、gemini-3.8 **0/20**、deepseek **1/20**。

消融（45 条/组，冲突类 query）：

| 变体 | 才不率 | 名字起手 |
|---|---|---|
| 现役 | 31.1% | 6.7% |
| 删掉检查句 | 28.9% | 24.4% |
| 检查句不点名具体词 | **22.2%** | 8.9% |
| 改成正向开头说法 | 37.8% | 51.1% |

## 5. 两种不靠改提示词的压法

**A. 首次即重生成**（实验 `outputs/tic_regen.py`，未上线）：
检测到第一条才否定就重生成，nudge 不点名这两个词，只给“直接说事实/态度，或哪有/少来/想得美”。
45 条：33.3%→17.8%；名字起手 15.6%→6.7%；替代说法分散，没有形成新单一口癖。
代价：约 1/3 轮次多一次调用 + 1–3 秒。

**B. 确定性归一**（原型，未上线）：`clean_reply` 只改“名字/句读之后”的 `才不`/`才没`，
把“才”换成 可/根本/省略 之一，保留“不/没”。
- 覆盖真实回复 2082 条里的 94%；“刚才/人才/天才”不碰。
- 零额外调用、零延迟，出厂率可到 0；代价是后处理、偶尔少一点“才”的强调。

## 6. 整体立场：提示词翻不动

（15 query × 3 轮 = 45 条/组，query 偏冲突类，绝对值偏高）

| 变体 | 否定词率 | 肯定词率 | 才不率 |
|---|---|---|---|
| 现役 | 66.7% | 6.7% | 22.2% |
| 肯定优先（“默认先接住/给肯定”） | **73.3%** | 8.9% | **44.4%** |
| 先行动后嘴硬（“行/好/过来/记住了/陪你”先落地） | 62.2% | 11.1% | 31.1% |

- 明确写“不要先否定”反而更否定（负面指令点名了要避免的东西）。
- “先行动后嘴硬”方向对，但只把否定降 4.5pp、肯定提 4.4pp，且才不升到 31.1%。

**behaviors 是不是主要否定源？不是**：

- 真实注入轨迹（10-20～10-23，2,527 轮）：有行为轮（611）否定 49.4% / 才不 18.5%；
  无行为轮（1,916）否定 44.0% / 才不 **24.3%**。
- 同题因果对照（8 条冲突 query × 3 轮，只去掉行为块）：保留 91.7% / 75.0%，
  去掉 75.0% / **75.0%**——行为只降其他否定词，不降才不。
- 15 条 behaviors 里 9 条是防御/否认型，样本 29% 含否定、12% 含肯定；但它们**只在
  被质疑/被真心/失约/被阴阳这几类情境局部加否定**，不是全局主因。

## 7. 代词错位：「真拿灰泽满没办法」

- 真实日志：全库「拿你没办法/没辙」151 处；「拿灰泽满没办法/没辙」6 处，其中 4 处无主语、
  是错的（真拿…×2、真拿…没辙×1、句首拿…×1），2 处带主语是对的
  （「你也拿灰泽满没办法」「你们拿灰泽满没办法」）。
- 机制：第三人称禁掉“我”，而「真拿你没办法」没有自称槽位，模型把名字挤进对象槽。
- 修法（已上线代码，未提交）：
  1. 骨架追加“指对方时仍然用‘你’……不要把指代对方的‘你’换成‘灰泽满’”。
  2. `clean_reply` 的 `_SELF_AS_OBJECT_RE` 只改**无主语**的「真(是)拿灰泽满没办法/没辙」；
     带主语、句首裸露（有歧义）都不动。
- 项目历史教训：曾删过一刀切把「她/他」换成「灰泽满」的规则（误伤真指别人）；
  这次只碰一个固定句式，并有正/反例单测。

## 8. 上线状态（2026-10-23）

**已落代码（未提交）**：

- 骨架：原句保留 + 只追加指代规则（单测锁定）。
- `reply_style._SELF_AS_OBJECT_RE` + `clean_reply` 窄兜底。
- `self_reference_metrics` / `self_reference_check`（纯函数，有单测）。
- `skeleton-ab --check`：第一人称率 / 三称自指率 / 名字起手率 / 才不才没率 /
  代词错位率 / 开头同质率；固定 8 条靶子；超阈值退出码 1。

**只做过实验、没有上线**：

- 首次即重生成（33.3%→17.8%）。
- 确定性归一（94% 覆盖、零成本）。
- 检查句改成不点名具体词（31.1%→22.2%，n=45）。
- 肯定优先 / 先行动后嘴硬的骨架变体（均未达到“多数肯定”）。

## 9. 如果以后恢复这个问题，推荐顺序

1. **先决定目标**：只是去掉“才不/才没”口癖（→ 确定性归一即可，零成本）；
   还是整体变成多数肯定（→ 这是人设变更，要改 behaviors/samples，不是改自称方式）。
2. 若只去口癖：`clean_reply` 确定性归一，抽 100 条人工看语气；不接受再用首次重生成。
3. 若要换模型：用 `skeleton-ab` 做同提示词 A/B（gemini-3.8 / deepseek），看风格与口癖。
4. 若动 behaviors：只改「被质疑 / 被真心 / 失约 / 被阴阳」四类，用同题“有/无行为”
   对照（`outputs/behavior_ablation.py`）验证；别期待解决全局才不。
5. 任何时候改「自称方式」：先跑
   `run_tool skeleton-ab --b 候选.txt --check --n 20 --runs 3`，
   名字那半句一个字都别动。

## 10. 口径与局限

- 样本 24–50 条/组，单模型、单日；差异大的结论（名字起手 7–44pp）可信，
  小差异（才不 9pp）只能当方向。
- 否定/肯定率是关键词统计，偏粗；“冲突类 query”会放大绝对值。
- 注入轨迹只覆盖 2026-10-20～10-23；行为因果对照只有 8 条 query。
- 所有实验脚本在 `outputs/`（gitignore），不是正式工具。
