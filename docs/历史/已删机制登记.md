## 1. schedule 的「近况」字段（已整条删除，2026-09-25 前后）

曾经有：一个自由文本 + 更新日期 + 7 天 TTL（如"这周在收拾搬家"），无条件注入。

**脉络**：
1. 被无条件注入时把"搬家"当成**当前理由**，且被【一致性规则】锁死用了一周；
2. 于是加了 TTL，超期就不注入；
3. 2026-09-25 实测发现——近况当时早已过期（**19 天**），而漏的根本不是它，而是 `voice_samples` 里一条"她本人说过"的搬家。

**结论**：近况治不了「用旧记忆回答当下」。那条通道是 assistant turn（"她本人的话"），远强于任何 system 说明。且这个字段手动维护必烂（实测烂了 20 天）。
**别再把它加回来**：真正该做的是保持样本库/corpus 与直播内容同步，而不是再设一个会烂的字段。

→ 相关：现在的替代品是 `persona/world/schedule.json` 的 `weekly`（weekday 制固定表，到周自动对，永不"过期"）。

## 2. 声音样本通道 `voice_samples`（2026-10-04 停用，文件已删）

**它是什么**：`persona/speech/voice_samples.json` + 对应的向量文件，走 RRF 融合的第三/四路之一。按【话题】检索"她本人说过的原句"注入。

**为什么删（实测 n=32 + 真实链路观测）**：
1. **按【话题】检索 → 必然捞到"同话题的完整回答" → 把事实灌进对话**：
   - "你今天吃什么了" → 捞到"今天怎么没吃饭" → 她答"还没吃呢" → 下一轮自相矛盾；
   - "外面下雨了" → 她答"刚淋着跑回来的"（编的）；
   - "最近怎么样" → "要写出百年孤独了"（近乎逐字搬）。
2. **assistant 通道注入时样本与真实历史混在一起**（样本 user 与真实 user 相邻，模型读成"连着两轮用户发言"）：
   - 与【当前时间】"正在直播中"冲突 **13/32**（system 一行只 2/32）；
   - 样本词泄漏 **4/32**（system 一行 1/32）；
   - 反问率 38%（system 一行 50%）。
3. **behaviors 按【情景】选，话题天然不同 → 只带走形态不带走内容**。这才是对的做法。

**那批原句里该留的 18 条已并入 `behavior/behaviors.json` 的 `samples`**（按情景触发，不按话题乱捞）。

## 3. 措辞指纹通道 `phrase` + `PHRASE_THRESHOLD`（2026-10-04）

**它是什么**：`persona/speech/phrases.json`，按 L3 判出的组 id 查表取出措辞组，走 RRF。

**为什么删**：
- 措辞组的 trigger 是 6~13 字的**类别标签**（如"被夸奖、被称赞时"），拿它算余弦 = **用检索工具干分类的活**；
- 实测：噪声地板 0.575 / 正例 0.573、中位 0.461 **都过阈值** → **100% 开火，等于没有判据**（真实对话 138 条里 100% 命中）；
- 试过提到 0.63：噪声挡住了，正例也一起被杀。

**现在**：由 L3 的 LLM 分类给组 id（与 behaviors 同构）。情景组已并入 behaviors。

## 4. 偏好走向量 + `PREFERENCE_THRESHOLD`（2026-09-26）

**为什么改**：噪声地板 0.565 插在正例（0.501 / 0.552 / 0.590）**正中间**，余弦分不开；试过提高到 0.62，三个正例全被误杀。
**结论**：偏好本来就是"类别 + 用户能直接说出的词"，跟 terms 同构 → **改成 keywords 子串命中**。
**现在**：读 `persona/world/preferences.json` 的 `keywords`，不走向量。

## 5. `find_repeat_word`（"防措辞固化"，2026-09-12 删除）

**它是什么**：2 字 bigram 统计 + 停用词表；由 `core` 在检测到"最近反复用同一个词"时**强制换措辞重生成**。

**为什么删**：
1. 实测 105 条她的回复里触发 8 次，其中 **6 次拦的是她自己的自称"灰泽满"**——她的第三人称自称是**身份特征不是口癖**，等于在纠正她的人设；
2. 排除自称后只剩 2 次，且拦的是"这边"这类泛词；
3. 它是同类兜底里最弱的一个：只重生成 1 次且**不校验**（防复读是 3 次 + 每次校验），nudge 还只要求"换个说法表达同一个意思"——**只换词不换动作**，治不了"她一直那么答"。

**结论**：口癖这类问题回到**数据层**解决（给她多样的真实说法），别用代码规则硬压。见 CLAUDE.md 黄金律。

## 6. A 类「包装语」（2026-09-30 删除）

被删的三处（`injection-design-principles` §3.5 实测"管怎么用"**零作用**）：

| 位置 | 被删的原句 |
|---|---|
| 【当前会话】末尾 | 「（这是你们这一场对话的调性和发生过的事，回应时要自然地顺着这个语境，不要生硬提及）」 |
| 【当前情境下的行为指令】末尾 | 「请严格按此模式回应：」 |
| 【她经历过的相关背景】末尾 | 「只当'她记得的经历'自然带出…不整段复述、不模仿里面的叙述口吻。」 |

**⚠️ 保留下来的是**「别拿背景记忆编当下的因果」——它管的是**事实/时间**，对应真实故障（「搬家」被当现在用，差 80 天），不是"怎么用"。

**⚠️ 「请严格按此模式回应：」有已知有害的先例**：它曾把 behaviors 里的 `"'呃…'起头"` 变成 **10/10 照抄**（而 86 条真实素材里 0 条那样开头）。那批措辞规定已经删了，这句强制语也一并删了。

## 9. `self_fact` 提取（V1 起停用）

**为什么**：灰泽满的"自我"应来自**真人素材**，而不是聊天时临时编造的自我披露，防止 AI 自嗨污染长期人格。
**现在**：记忆提取的强制规则里，`new_self_fact` 一律返回 null；只提取关于用户的信息。
