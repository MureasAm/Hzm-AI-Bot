### 主动发言：相对时间被换算成错钟点（2026-10-11 实发 → 2026-10-12 修）

**案例**：B站动态 19:45 写"好无聊 **10分钟**后来玩会儿游戏吧"；她 19:52 主动发出的
那句是"**十点后**来玩会儿游戏嘛"——把 19:55 说成了 22:00。

**怎么定位的**（记下来，下次同类问题照这个查）：
- 主动发言**不落 chat_log**（桥直接 `send_private_msg`），但她那句会被写进好友的
  **短期记忆**（`user_memory/short_term/<QQ>.json`，`_push(record=True)`）→ 从那找到原句 + 时间戳。
- 动态**原文**走 B站 API 取回（`bilibili_api.user.User(uid).get_dynamics_new()`；正文在
  `modules.module_dynamic.major.opus` 的 text 里，不在 `desc`）。
- 时间线自洽：19:45 + 10 分钟 ≈ 19:55 开播（19:57:15 真开播 ✓）。

**排除的可能**：不是 corpus 污染（那条动态检索只注入 1 条游戏偏好，无任何含时间条目）；
不是时区（用固定 19:52/21:52 做过受控实验，不触发）。

**结论**：模型默认**不换算**相对时间（12 次复现全保持"10分钟后"），是 temp=0.9 的偶发抽样。
**所以这 bug 复现不了、"修好没"也验不了**，只能靠提示词防。

### 名字：守卫一直在，但对 4/7 个用户**静默失效**（2026-10-12）

### 缓存：① 结构性问题被实测坐实 ② 修掉一个免费的点

**这一轮不靠读代码下结论，直接发真请求读 `prompt_cache_hit_tokens` 量的**（探针在
`outputs/_cache_probe*.py`，不入库）。测试 889 → **890**。

**实测：稳定前缀 = 最前面两块，第 3 块起每轮都变。**
连续多轮、**每轮换检索子集**（贴近真实）发真请求：
- 命中稳定停在 **2176 token**（≈`system_prompt` 3413 字 + 周表），占 62~70%；
- 对照：把检索**固定不变**时能到 **2816（94%）**。
差异全在"per-turn 内容"上。**为什么第 3 块就断**：`相处方式`(profile) 是用 `_relevance(当轮
query, m)` 选的、`偏好/名词库/核心记忆/会话记忆/短期记忆`**全都按当轮消息现算**——所以
`下一步.md` 里"从第 4 块起都是现算"这个观察**基本成立**（我量到的是**第 3 块**就是分界线）。
**结论：重排块序不是杠杆**（能救的早救了：感知本来就被挪到末尾）；截图起注释里那句
"分界线推到倒数第二块"**是错的**，已改成实测口径。想提高命中只有**减少注入量 / 换模型 / 接受**。

**免费的点：`corpus_judge` 的 prompt 把 `{query}` 夹在中间 → 每轮 0% 命中。**
DeepSeek 按前缀匹配，query 每轮都变，夹在中间把**后面整段候选经历**一起拖成 miss。
实测（12 条候选、连发 4 轮）：query 在中 → **每轮 0%**，挪到末尾 → **~43%**。
修法：**只调位置**（判据用词一字未动——这是模块 docstring 点名"改词=改行为"的地方，
所以先跑了 12 条真实例的 A/B：**6/6 行为一致**，正例该留的留、反例该拒的拒）。
另加了一条**位置守卫测试**（谁把 query 挪回去就红）。
⚠️ 排查过其余 LLM 调用点，**只有它一个违反**：`group_gate`(0%→68%)、`routing` 行为分类、
`legendary_confirms` **都已经把变量放末尾了**；`terms`(术语消歧) 的 `{msg}` 虽在中间，
但它后面的词条也随 msg 选、重排救不了，不是同类问题。

**`下一步.md` 里那条"直播记忆判真实流量 16%"的解释**：不是"模型每次重新建缓存"，
而是**布局把后面的内容拖死了**——修完这个，它应该能到 40%+。

## 负二、（2026-09-30，路线已停止）**风格层标注集 —— 把「像不像她」固化成数据**

> ⚠️ **历史章节**：这一节记录最初的目标和工具设计，不代表当前建议。
> 同日实测后路线已停止；最新结论看本文“当前（2026-10-01）”。

> 这一轮只做一件事：**补上风格层缺的那个标准**（`待办清单.md` 第 0 条，也是上一轮标「下一件该做的」）。
> 用户原话：**"现在的需求是创造一个风格层的标注集，我在里面进行比较方便的标注，
> 然后你拿这份标注对人格文件进行消融实验，判断那些文件对恢复是否发生作用。"**

### 为什么必须是「数据」而不是「再找一把尺子」

风格层原来什么都没有（检索层有 `retrieval_eval_cases.json`、生成层有 `regression_cases.json`），
所以**风格类结论全不可靠**——上一轮换了三把尺子（长度/括号指标 → 指纹距离 → LLM 成对比较）全废，
最后一把废得最彻底：**那个 LLM 根本不知道灰泽满是谁**。

**「像不像她」的标准只能来自懂她的人**，而这个标准必须**固化成数据**，不能每次临场判。

### 建了三个文件

| 文件 | 角色 |
|---|---|
| `scripts/style_eval_cases.json` | **用例库（唯一真值）**。机器读，你不用碰 |
| **`风格标注.md`**（根目录，**不入库**） | **你手上唯一要碰的文件**。分批出题、勾选即可 |
| `scripts/style_annotate.py` | 出题 / 回读 / 读数 / 现生成对照（入口 `run_tool.py style-annotate`）|

```
python scripts/run_tool.py style-annotate            # 出一批题 → 写 风格标注.md
#   ↑ 你在 风格标注.md 里把 [ ] 改成 [x]，想写就补一句「理由」
python scripts/run_tool.py style-annotate --ingest   # 回读 → 落进用例库
python scripts/run_tool.py style-annotate --report   # ★消融读数（按文件/小节 + 双侧 p 值）
python scripts/run_tool.py style-annotate --status   # 进度
python scripts/run_tool.py style-annotate --run "【说话方式参考】"   # 给没测过的段**现生成**对照（要跑 LLM）
```

### 两种题，各管一件事

| 形态 | 长什么样 | 回答什么 | 用途 |
|---|---|---|---|
| `pair` | 同一句话的两版（**有**那文件 / **删掉**那文件），左右打乱 | **哪一版更像她** | **直接就是那个文件的消融读数**（你在判的就是答案，不需要模型当中间人） |
| `single` | 一句回复（**她本人真实** / 生成，来源蒙住） | **这句像她吗** | 建「正例锚」——将来验自动判的参照；也能量「生成离她本人有多远」 |

外加一问（`compare=without_vs_placebo`）：**删掉 vs 等长无关填充**——
回答「是那段的**内容**在起作用，还是只是上下文变短了」（这是本仓一直要求的安慰剂对照）。

### 纪律（都写进代码 + 测试了，不是口头约定）

- **左右打乱 + 内容哈希定序**：`cond` 真实条件只在 JSON 里，md 里看不到；同一内容两次跑不翻边
- **单条绝不泄露来源**：`real`/`gen` 只在 JSON 里 —— 否则题变成「猜这题出得对不对」
- **集中出题**：一批只做 3 个段（`--sections-per-batch`），**摊开会让每段 n=1、读数全废**
- **没标的不丢**：只标一半，重出题时另一半天还在
- **只增不改**：已标不会被覆盖；`--relabel` 才覆盖（它同时是**复标查一致性**的入口）
- **每条都带「用户说的那句话」**：脱离上下文的对比是上一轮的坑 5
- **必须报双侧 p**：本仓踩过「只算下尾再乘 2 → 100% 却 p=1.0」

| 文件 | 依据 | 强度 |

### ⚠️ 这一轮最大的教训：**风格类不能用模型当裁判**

风格类（「像不像她」）**没有客观标准**，我先后换了三把尺子都不可靠：

| 尺子 | 怎么废的 |
|---|---|
| 长度/括号/叹号 | 指标没对准被测对象 |
| 指纹距离（与她自己 620 条回复的距离） | **噪声 ≥ 信号**（两次运行 baseline 自己差 0.03） |
| LLM 成对比较（「哪句更像她」） | **那个模型根本不知道灰泽满是谁**（只看过我塞给它的 20 句）→ 判 traits/styles「没用」，**而用户盲判是 76% 有用**，结论相反 |

**→ 已作废**：所有靠 LLM 裁判的风格类结论（traits/styles、骨架各节、behaviors 100%、core_stories 79% 等）。

### ★ 下一步的正确标准（用户提出，已确认方向）

**风格层要有一个「标注集」，就像检索层的 `retrieval_eval_cases.json`：**

```
① 用户标注一批「像她的回复」（正例样本）——一次性的
② 之后消融实验拿这批标注当**参照基准**：
   生成的两版，哪一版**更接近标注里对的那些** → 自动判、不用每次问用户
③ 裁判不是模型、也不是临场判断，而是「用户已经标过的数据」
```

⚠️ 顺带排除一个变量：**别用 RAG 向量相似度去比**（「像不像」的语义相似度测不出风格）。

### 这一轮踩过的坑（都写进注释/文档了）

1. **判据必须能失败**：「如果她答错了，这个判据会通过吗？」会通过就不是判据（偏好放了 `猫|怕`、terms 放了 `绿冻` → 两侧都 100%）
2. **假阴性成功骗人**：消融实验第一版「差异恰好为 0」看着很干净，其实是生成函数没换回来（拿回的是占位符）
3. **安慰剂对照必须有**，而且必须**中性**（第一版用「关于她的真实陈述」当填充 = 平光镜也有度数）
4. **p 值算错**：只算下尾再乘 2 → 100% 却 p=1.0；**抓到它靠「结论自相矛盾」**
5. **无上下文的测试接不上话**：例「真的骚」的真话延续上一轮「16岁没发育」的梗，无上下文版完全接不上 → **脱离上下文的对比，比的是两个都不像她的东西**

## 二、⭐ 这一轮真正的产出：十条认知

**比上面所有代码都值钱**，因为它们决定后面怎么做：

1. **唯一 assistant turn 通道最强** —— 「她本人的话」比任何 system 说明都管用
   （同一事实走 voice_samples 3/5 被采用，走 corpus 0/5）
2. **注入的措辞，具体到什么粒度决定它会不会被落成词**
   （`'呃…'起头`→说「呃」；`表示收到但不接`→说「收到」；`不当回事地略过`→不渗）
3. **提示词约束不可靠，要代码兜底**（表情包「别再选最近发过的」，模型 2 次里 1 次不听）
4. **判断和生成写在一个调用里，模型会偏向生成**（主动发言「判不适合」判不出来就是这个）
5. **判据措辞稍动，结果从 0% 跳到 74%** —— 判定噪声大；要么概率采样，要么**严格偏向**
6. **三个功能的兜底方向必须分别设计**：接话门**放行**／表情包**不发**／主动发言**退回通知**
7. **合成场景自测 = 循环论证**（我造 8 个场景得 100%，真实数据一上就崩）
8. **关键词表扫描永远会漏**（漏了 `peer_5`，换个扫法才发现）
9. **裸模型 ≠ 走链路**（人格层接上后「幻觉式接话」自己就好了）
10. **难点从来不是「谁来跑」，是「判据是什么」** —— 判断该不该上 DSH 的关键

## 三、检索层：corpus 已修（asks 那条路的结论被推翻）

### corpus：阈值判据 → **LLM 语义判**（2026-09-25 第二轮，已做）

**原来的判断（上一轮）**：corpus 的问题在「库和 query 形态不同构」，
所以给每条经历挂「用户可能怎么说」当索引（`build_corpus_asks.py`，485 条）就能解决。

**这一轮实测：那个方案不成立** ——
- asks 当索引确实把正例从 0.44 拉到 **0.88**，**但噪声地板同步抬到 0.822**：
  `「明天几点开会」→「明天几点下课」0.822`（比部分正例还高）。
  语义、共享 bigram、IDF 加权重叠**三种都试过，全分不开**。
- 把 asks 拼进陈述一起编码（零代码改动的简化版）**也无效**：稀释后排名几乎不动。

**根因**：差别不在文本里，在**「她到底有没有这段经历」这个事实**——这是判断，不是相似度。

**真正的修法**（用户拍板「LLM 的判断是很有智慧的」）：**判据换成 LLM 判**。
- ~~门放行的照旧**直通**；门没放行的取 top-N 候选交 LLM 判。~~
  ⚠️ **2026-09-29 已改**：门/钩子只决定候选，**判定全部交 LLM**（取消直通，见第「零」节）。
- 因为实测发现：**正例对正确那条的排名是对的**（「你多高啊」→ 身高那条排第 1），
  只是分数（0.443）低于噪声地板——**排序有用、阈值没用**。
- **失败一律不带经历**（与接话门相反，与表情包一致）：宁可漏，不可错。
- 判据措辞是核心。起点「撞到同一个词/话题就算」→ **反例漏 3/10**（含评测用例「9点是你那边」，属退化）；
  改成「**用户是不是在问她**」→ **反例 0/10、正例 4/7**。
- 工具：`corpus_judge.py`；开关 `CORPUS_JUDGE=0`；评测 `retrieval_eval.py` **31/32**
  （新增 co6 你多高啊 / co7 明天几点开会 / co8 感冒吃什么药，**co7/co8 是只有 LLM 判才挡得住的反例**）。

⚠️ **评测脚本已改成镜像线上**（`corpus_items()`）：corpus 一路也走 LLM 判。
否则测的就不是线上真正跑的东西。
