# 提示词参考：角色扮演类 system prompt 该怎么写

> **这份是什么**：2026-10-12 检索业界做法（Anthropic 官方文档 / Character.AI 定义指南 / SillyTavern 角色卡社区 /
> 几篇角色一致性论文）后整理的**参考资料**，用来指导本项目的 `persona/core/system_prompt.txt` 怎么写。
>
> **怎么用**：前半是**通用共识**（谁的提示词都适用）；后半是**跟本项目的关系**——哪些直接照用、
> 哪些本项目**有意不做**（以及为什么）。**改骨架之前先看后半**，否则会把已经踩过的坑再踩一遍。
>
> ⚠️ 这是参考资料不是现状。现状看 `下一步.md`。

---

## 一、结构共识：**顺序即权重**

所有来源都同意一条：**上下文开头对输出的影响最大，越往下越不灵**
（Character.AI 官方："the lines at the top earn the most influence"; SillyTavern 社区同样结论）。

所以推荐的书写顺序是：

```
① 身份 / 在场    你是谁、在哪儿、对面是谁      ← 权重最高
② 性格          行为化的"她是谁"（不是形容词）
③ 行为规则      几条硬的（always / never）
④ 世界观 / 其余  背景、术语、关系            ← 权重最低
```

**推论**：**最想让她做到的事，放开头**。本项目实测印证过这一点——把"回得短"从中间挪到
骨架**第一段**之后，平均回复长度 30 字 → 18 字（见 `历史/交接文档.md` 的 2026-10-13 条）。

## 二、各块怎么写

### 2.1 身份 / 描述（Description）

- **写具体的，不写模糊形容词**。Character.AI 原话：模糊形容词（friendly / complex）
  "给 AI 的信息量是零"。
  - ❌"她很温柔"
  - ✅"她说话轻声细语，见人难过会先递纸巾再问发生了什么"
- **第三人称、把最重要的放最前**。
- **长度**：社区经验值 **200–500 词 / 300–600 token**。"过长（3000 字+）会占上下文且模型消化不了，
  而且**padding 会稀释真正重要的东西**"。
- **别自我矛盾**：有冲突的指令，模型会**两边都试着满足** → 行为飘。

### 2.2 性格（Personality）

- 社区共识是**"简短的行为摘要"**，4–6 个关键特质就够，作用是**强化描述里已建立的行为**，
  **不要和描述重复**（重复 = 双倍消耗永久 token）。
- **写行为，不写标签**：
  - ❌ "She is sarcastic, intelligent, and kind"
  - ✅ "She defaults to dry humor when uncomfortable. She asks questions before offering opinions."
- 一条常被提到的技巧：**给她一个"矛盾点"**（"看起来冷淡其实很黏人"）——AI 演起来有层次。

### 2.3 示例对话（Example Dialogue / mes_example）

- 被两个来源同时称为**"杠杆最高、也最被低估"**的字段。
- 写法：3–7 组短来回，**覆盖不同情绪档**（平静/紧张/温暖/被质疑/俏皮），别只写一种；
  每组之间用显式分隔符（`<START>`）隔开。
- 角色卡里这是**token 消耗最大**的字段，通常会在真实对话变长后被挤出上下文（这是想要的效果）。

### 2.4 场景 / 开场白（Scenario / First Message）

- Scenario 只写**当下处境**（在哪、{{char}} 与 {{user}} 是什么关系），一两句话；
  背景故事交给 Description。
- First Message 被形容为**整张卡里杠杆率最高的字段**，因为模型会**照抄它的长度、语气、
  标点格式、对话与旁白的比例**作为风格范本。

### 2.5 行为规则

- **要短**。Character.AI 明确警告："**一长串规则 = 给模型更多挑错一条的机会**"。
- 只放 **always / never** 级别的硬约束。

## 三、保持一致性的技术

| 技术 | 做法 | 出处 |
|---|---|---|
| **锚词（anchor word）** | 每一轮回复里以角色名为开头 → 注意力会被吸回前文的人设，逐轮把一致性传下去 | 九州大学论文 |
| **结构标记** | 用 `@Occupation` `@Speaking Style` 这类独立标记给关键属性"打标"，引导注意力 | 同上 |
| **Prefill（预填回复）** | 把角色名预填进 assistant 轮（`[Joe from ...] `），强制它承接人设——**长对话/弱模型漂移时**最有效 | Anthropic 官方 |
| **中途重申** | 对话变长后重新提醒一次身份 | Anthropic 官方 |
| **状态变量** | 用 MVU 变量追踪当前状态，别让模型自己记 | SillyTavern 社区 |
| **结构化表达** | 角色扮演要"细节丰富"，提示词要"简洁省 token"——用**结构化**解决这个矛盾 | 同上 |

**防幻觉**：角色一致性评测框架里有一条 **Hallucination 维度**——"**她说了她不该知道的事吗**"。
所以人设里应该明确**知识边界**。

## 四、常见误区（社区总结 + 本项目踩过的）

| 误区 | 后果 |
|---|---|
| 描述只写性格标签 | AI 演得空洞 |
| 描述太长 | 占上下文、模型消化不了、稀释重点 |
| 没有示例对话 | AI 说话像客服 |
| 开场白太短 | 对话开局尴尬 |
| **规则清单太长** | 模型挑错一条 |
| **自相矛盾** | 模型两边都试 → 行为飘 |
| **禁令式写法**（"别X""保持Y"） | 模型要么理解偏、要么不听 |

## 五、跟本项目的关系（**改骨架前必读**）

### 5.1 直接照用的

1. **顺序即权重** → 把"回得短"这类最重要的约束放骨架最前面。（已实测有效，见 §一）
2. **行为 > 标签** → 这就是本项目的黄金律 2。
3. **规则要短、别自相矛盾** → 也是黄金律的延伸。
4. **给知识边界** → 提示词里**别写"知识边界"这个抽象词**，写成她能自己判断的常识，例如：
   > 她自己的：直播、游戏、作业、宿舍、澳洲日常……随口都能聊。
   > 绿冻告诉过她的：按相关度注入，照注入的用，别自己加戏。
   > 现实世界只有常识级：**别人现实生活里的具体人事物，她不知道**——对方没说过就别当成知道，更别顺着编。
   > 拿不准时，含糊一句或反问回去，比编一个具体答案安全得多。
5. **防破功放显眼位置** → "你就是她，不承认在演、不聊实现细节"这类底线单独成块，别埋在 FAQ 里。

### 5.2 本项目**有意不做**的（别照搬）

| 业界做法 | 本项目为什么不做 |
|---|---|
| **把示例对话塞进 system prompt** | 本项目的素材层（`behaviors` 条件注入 + 真人原话）覆盖面更大；**实测**"带引号的原话放提示词 → 点名口癖 → 每条都加"（`persona-resound/references/pitfalls.md`）。业界塞进提示词是因为他们**没有素材层**——同一个目标的两种实现，不是缺示例。 |
| **用长规则清单压行为** | 黄金律 1/3：素材层解决；确定性后处理只兜底。**但实测有个例外**（2026-10-13）：**具体、可判**的约束（"别拿'看看'当开头""别当口头禅"）**确实在干活**——删掉它们，回复从 24 字涨到 35 字。真正没用的是**抽象**的（"保持温度""别老用封印"）。 |
| **把"她是谁"写成一大段形容词** | 黄金律 2 + 历史教训：写过 `traits`（标签文件），模型当**行为模板过度执行**（"回避型亲近者"→ 亲密场景一律冷处理），已删。 |

### 5.3 本项目的骨架应该长什么样（建议形态）

```
① 在场框架（短）   你就是她 + 在 QQ 和绿冻聊天 + 私聊/群聊的区别
② 她是谁（加厚）   ← 行为化，别堆形容词；这里是重心
③ 底线（几条）     ← 永不破功 / 不知道就说不知道 / 不编细节
④ 说话形态         ← "短、一口气、像打字"；**具体可判**的约束留着，抽象禁令删掉
⑤ 身份怎么答       ← 真实决策（装傻/虚拟前缀/技术问题），别写"注入机制"
（素材层：行为/样本/术语按需注入，不在这里重复）
```

**核心判据**：骨架只放**不可压缩的**——"她是谁" + 底线 + 身份机制；
**任何"某个情境该怎么反应"都该在 `behaviors`，不是这里**。
