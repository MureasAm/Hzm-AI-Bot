# 问题驱动：看到的问题 → 永久用例

> **这份是操作手册。** 想知道"原理为什么这么设计"见 `注入设计原理.md`；
> 想知道"数据存在哪个文件、字段什么意思"见 `FILE_MAP.md` §4.2。
> 对应工具：`scripts/problem_cases.py`（入口 `python scripts/run_tool.py problems`）。

---

## 一句话

**你只做一件事：把"这条答得不对"记下来。** 变成用例是工具的活——
包括"该不该命中"这种判断，也用**事实**帮你想清楚（见下面第 3 步）。

⚠️ **没有"人工标注"这个动作**。`scripts/retrieval_eval_cases.json` 里那 48 条是**已有资产**，
平时不用看、不用标。只有两种情况你才打开它：想改某条已有期望 / 想看看现在覆盖了哪些情况。

---

## 三条入口

| 你想干什么 | 用哪条 |
|---|---|
| 平时聊天看到答得不对 | **随手记**（下面 A） |
| 想主动抽查她最近答得怎么样 | **抽查**（下面 B） |
| 想复核**已有用例**里有没有标错的 | **复核**（下面 C）——⚠️ 老用例是人手工定的，**可能有错** |

---

## A · 随手记（最常用）

**第 1 步**：打开根目录 `问题记录.md`，在最下面写（三行，格式随意）：

```
用户说：你多高啊
她答：灰泽满大概一米七吧
应该是：该想起身高那条（她说自己1米6）
```

**第 2 步**：终端跑

```
python scripts/run_tool.py problems --from-note
```

**第 3 步**：屏幕给你两样东西——

1. **这句话实际召回了什么**（各类素材逐条列出来、带原文）← **这是最有用的部分**
2. 一条**草案**（准备写进去的用例）

**第 4 步**：看着实况决定，然后二选一——

- **草案不对** → 回 `问题记录.md` 补一行，说明你认为该怎样，再跑一次（第 2 步）：
  ```
  该中：corpus:1米6        ← 该命中哪条（说不出是哪条就写 corpus:*）
  不该中：phrase,behavior   ← 这几路该是空的
  层：检索                  ← 检索 / 生成（不写它会替你猜，猜错就写这行覆盖）
  禁词：搬家,搬东西          ← 生成层专用：这些词她一个都不许出现
  ```
- **草案对** → 加 `--write` 正式写进去：
  ```
  python scripts/run_tool.py problems --from-note --write
  ```
  （**同样的 query 不会重复写**，写错了去 `scripts/retrieval_eval_cases.json` 里改那一行）

**第 5 步（关键，别跳）**：确认新用例**是红的**

```
python scripts/run_tool.py retrieval-eval --case <上一步打印的 id>
```

- **红 = 好**：说明它真的复现了你看到的问题 ✅ 这时才该去改素材
- **绿 = 白加**：说明这条判据没抓住问题 → 回第 4 步改判据
  （⚠️ 这是本项目踩过的坑：**合成场景自测 8/8，一上真实数据就崩**——绿的用例给的是假信心）

---

## B · 抽查（主动找问题）

```
python scripts/spot_check.py              # 自动挑出最可疑的几条
```

打开 `outputs/spot_check.md`，每条后面把 `[ ] 有` 改成 `[x] 有：为什么不对`，然后：

```
python scripts/run_tool.py problems --from-spot
```

后面和 A 的第 3~5 步一样（加 `--write` 才写）。

（每条带一个 `t=` 是定位用的唯一键，**别手改它**。）

---

## C · 复核已有用例（**老用例可能有错**）

48 条里有一部分是早期**人手定**的标签（来源见每条 `source` 字段，`why` 写了理由），
**它们没经过你复核**。复核流程：

```
python scripts/run_tool.py problems --audit
```

它会读**最近一次评测报告**（`outputs/eval/retrieval/eval_report.json`），把用例按
"**最可能标错**"排序给你看（当前失败的 → 边界案例 → 老标注），每条打印：

```
[id] 用户那句话
     现有期望：corpus 该命中「1米6」
     实测结果：✗ 没命中（实际 0 条）
     为什么这么标：……（原标注的理由）
     来源：标注集（早期人手定的）
  认可这条期望吗？[回车=认可 / s=有问题 / q=退出]
```

标 `s` 的会被写进 `问题记录.md`（**复用 A 的通道**），你补上"应该是"再走 A 的流程。
**没有评测报告它会让你先跑一次评测**（因为"实测结果"是复核的主要依据）。

## 写完之后去哪里改

用例落定后，屏幕会打印指针。对应关系：

| 问题出在 | 去改 |
|---|---|
| 该想起某段经历却没想起 / 想起了不该想的 | 检索层：`persona/world/*.json`（corpus 是 `statement_final.json`）；**入口不够**就先看 `python scripts/entry_audit.py all` |
| 用户的说法勾不出那条素材 | `persona/world/corpus_keywords.json` 的钩子（**合并式**，手补不会被重跑覆盖；补完记进 `_readme`） |
| 她话说错了（用旧事当现在 / 复读 / 客服腔） | 生成层：`persona/behavior/behaviors.json`、`persona/speech/voice_samples.json`、`persona/core/system_prompt.txt` |
| 想知道整条链上到底哪一步出了问题 | `python scripts/trace_chain.py "那句话" --reply`（每个决策都打出来） |

⚠️ **改数据后**：改 `voice_samples`/`phrases`/`preferences`/`core_stories`/`statement_final` 要重算向量
（见 `CLAUDE.md` 黄金律 5）；**改完必须重启 bot**（有进程内缓存）。

## 常见疑问

**草案的 id 是 `case_5103` 这种，看不懂？**
纯中文的句子提不出英文 id，就用"case_+数字"。**不影响使用**（评测打印时连句子一起打）。
想好读就在 `问题记录.md` 里……暂时没这个开关，介意的话说一声我加。

**一条问题会变成几条用例？**
看它属于哪层：**检索层**进 `retrieval_eval_cases.json`，**生成层**进 `regression_cases.json`。
一条问题只进一个文件（`层：` 那行说了算）。

**生成层的用例跑起来贵吗？**
贵。一条用例一次检查 ≈ `跑次` × 4~8 次 LLM 调用（现有 8 条约 190~230 次）。
所以 `跑次` 默认 3，**加之前先单跑一条**：`run_tool.py regression --check --case <id>`。
