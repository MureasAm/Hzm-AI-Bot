# persona 更新流水线

这份文档只讲一件事：**拿到一场新直播素材后，怎样安全更新 corpus / voice_samples / phrases / behaviors。**

统一入口：

```bash
python scripts/run_tool.py persona-pipeline <target> [参数]
```

`target` 有四个：

```text
corpus
voice-samples
phrases
behaviors
```

---

## 一、统一流程

每条流水线都遵守同一套流程：

```text
音频或清洗 JSON
  → 生成候选
  → 写入 outputs/persona_pipeline/<session>/
  → 人工查看 review.md
  → 确认后 --apply
  → 写入 persona
  → 自动备份原文件
  → corpus / voice 自动重建向量
```

默认是 `prepare` 模式：

```text
只生成候选，不改 persona。
```

只有显式加 `--apply` 才会写回。

---

## 二、输入方式

### 方式 A：直接从音频

```bash
python scripts/run_tool.py persona-pipeline corpus \
  --audio assets/audio/xxx.m4a \
  --session 20261001
```

内部顺序：

```text
transcribe → clean-transcript → 对应 persona 处理
```

同一个 `--session` 第一次跑完会保留 `cleaned.json`；后续另外三条流水线
直接复用这份清洗素材，不会重复转写和清洗。需要强制重跑音频时加 `--refresh`。

如果当前 Python 环境没有 `faster-whisper`，设置：

```text
WHISPER_PYTHON=D:\whisper_env\Scripts\python.exe
```

### 方式 B：从已清洗 JSON

```bash
python scripts/run_tool.py persona-pipeline corpus \
  -i outputs/clean/cleaned_xxx.json \
  --session 20261001
```

可传多份清洗 JSON：

```bash
persona-pipeline phrases -i outputs/clean/a.json outputs/clean/b.json --session 20261001
```

---

## 三、输出位置

每次都会生成：

```text
outputs/persona_pipeline/<session>/
├── cleaned.json                  # 从音频开始时
├── corpus_raw.json               # 各流水线的原始生成结果
├── corpus_candidates.json
├── corpus_review.md
└── backup/                       # --apply 时自动备份
```

文件名会随 target 改变。

---

## 四、corpus 流水线

命令：

```bash
python scripts/run_tool.py persona-pipeline corpus \
  --audio assets/audio/xxx.m4a --session 20261001
```

内部链路：

```text
cleaned
  → generate-statements
  → corpus_candidates.json
```

目标 schema：

```json
{
  "_readme": "保留",
  "statements": [
    {"statement": "灰泽满当时……"}
  ]
}
```

写回文件：

```text
persona/world/statement_final.json
```

写回后自动：

```text
generate-vectors → persona/world/corpus_vectors.json
更新 corpus_keywords.json（只补缺失索引，不覆盖手工钩子）
```

判断标准：

- 只写“发生过什么”；
- 不保留她的成句台词；
- 具体事件要真实；
- 不要带时间戳。
- **不要写“灰泽满……她/他……”**：先写灰泽满后，后续同主语省略主语或继续写灰泽满；
  只有“她/他”明显指别人时才保留。

流水线会在写回前自动审计这种自指代词，并用 LLM 只改写确实复指灰泽满的句子。
改写前后分别保存：

```text
corpus_self_pronoun_before.json
corpus_self_pronoun_after.json
```

## 五、voice-samples 流水线

命令：

```bash
python scripts/run_tool.py persona-pipeline voice-samples \
  --audio assets/audio/xxx.m4a --session 20261001
```

内部链路：

```text
cleaned
  → convert-to-chat
  → 归一化成 user/reply
  → 自动生成 id
```

目标 schema：

```json
{
  "id": "session_abcd1234_001",
  "type": "daily",
  "length": "short",
  "user": "粉丝问：……",
  "reply": "灰泽满：……"
}
```

写回文件：

```text
persona/speech/voice_samples.json
```

写回后自动：

```text
precompute voice-samples → persona/speech/voice_sample_vectors.json
```

判断标准：

- `user` 和 `reply` 都必须是真实对话对；
- 不要带一次性的具体事件；
- 优先改写成她一贯会怎么回答；
- `reply` 保持短句和她的真实节奏。

---

## 六、phrases 流水线

命令：

```bash
python scripts/run_tool.py persona-pipeline phrases \
  --audio assets/audio/xxx.m4a --session 20261001
```

内部链路：

```text
cleaned
  → mine-phrases
  → 按 meaning 合并
  → 自动生成/保留组 id
```

目标 schema：

```json
{
  "id": "new_1234abcd",
  "meaning": "被夸时的否认",
  "trigger": "被夸奖、被称赞时",
  "phrases": ["也没有啦", "别夸了"],
  "usage": "先否认再转移"
}
```

写回文件：

```text
persona/speech/phrases.json
```

phrases 不走向量，不需要 precompute。

判断标准：

- 每条必须是素材中真实出现过的话；
- 优先短碎片，不写完整句；
- 同一个 meaning 会合并，不重复建组。

---

## 七、behaviors 流水线

命令：

```bash
python scripts/run_tool.py persona-pipeline behaviors \
  --audio assets/audio/xxx.m4a --session 20261001
```

内部链路：

```text
cleaned
  → convert-to-chat
  → extract-persona
  → 聚合为行为候选
```

目标 schema：

```json
{
  "name": "被夸时嘴硬否认",
  "trigger": "收到正面评价或夸奖时",
  "response": "先否认，再自嘲带过",
  "samples": [
    {"user": "……", "reply": "……"}
  ],
  "evidence": [
    "素材样本：……"
  ]
}
```

写回文件：

```text
persona/behavior/behaviors.json
```

behaviors 不走向量，不需要 precompute。

判断标准：

- 只保留反复出现、稳定的行为模式；
- `response` 只描述“做什么”，不写具体台词；
- samples 必须来自 convert-to-chat 的真实素材。

---

## 八、审查后写回

先生成候选：

```bash
python scripts/run_tool.py persona-pipeline corpus --audio xxx.m4a --session 20261001
```

查看：

```text
outputs/persona_pipeline/20261001/corpus_review.md
```

需要删条目或改文字时，可以直接编辑同目录的 `<target>_candidates.json`。
之后不要加 `--refresh`，直接 `--apply`，流水线会复用你改过的那份候选。

确认后复用同一份候选写回：

```bash
python scripts/run_tool.py persona-pipeline corpus --session 20261001 --apply
```

如果希望重新生成：

```bash
python scripts/run_tool.py persona-pipeline corpus \
  --audio xxx.m4a --session 20261001 --apply --refresh
```

corpus / voice 如果暂时不想重建向量：

```text
--no-vectorize
```

一般不这么用，除非你在批量合并多场素材，最后统一重建。

---

## 九、安全规则

- 默认不写 persona；
- `--apply` 才写；
- 写回前自动备份原文；
- 重复内容自动去重；
- corpus / voice 写回后检查向量文件是否真的更新；
- corpus 写回后自动补 `corpus_keywords.json`；已有钩子和手工钩子不会被覆盖；
- 向量生成失败时保留 persona 写回结果和备份，并报错提醒。

---

## 十、和旧工具的关系

旧工具仍可直接使用，但推荐只用这些：

```text
transcribe
clean-transcript
persona-pipeline
```

其中：

- `convert-to-chat`
- `generate-statements`
- `mine-phrases`
- `extract-persona`

仍然保留，作为 persona-pipeline 的底层步骤和诊断工具。

已停用的向量步骤：

```text
precompute phrases
precompute preferences
```

不要在更新 phrases / preferences 后再跑它们。

### corpus 钩子

新 corpus 条目如果没有钩子，用户换一种说法时就可能进不了候选池。

`persona-pipeline corpus --apply` 默认会在写回后运行：

```text
scripts/build_corpus_keywords.py
```

它只处理 `corpus_keywords.json` 里缺失的索引，已有手工钩子保持不变。

如果本轮不想要这一步：

```text
--no-hooks
```

### 清理已有 corpus 的自指代词

如果历史 corpus 已经落库，但仍有“灰泽满……她/他……”：

```bash
python scripts/run_tool.py persona-pipeline corpus \
  --session corpus-self-pronoun-cleanup \
  --from-index 0 \
  --sanitize-existing --apply
```

它会审计整个 `statement_final.json`：

- “她/他”复指灰泽满 → LLM 定向改写；
- “她/他”指女同学、老师、满妈等别人 → 保持不动；
- 索引不变化，所以 `corpus_keywords.json` 不需要重建；
- 默认同时重建 `corpus_vectors.json`。

只想清理某一批新增条目时指定起始索引，例如本次新增从 `322` 开始：

```bash
python scripts/run_tool.py persona-pipeline corpus \
  --session 20260923-wanjianzatan \
  --from-index 322 \
  --sanitize-existing --apply
```
