# 灰泽满（Hazel）· 基于素材驱动的 LLM 角色一致性对话框架

一个虚拟主播"灰泽满"的 QQ 聊天机器人（NoneBot2 + OneBot V11 + NapCat）。目标不是"能聊天"，是"**像她**"。

做到这件事的路径是：从真实直播语料蒸馏人格数据 → 按需检索注入 → 分层提示词 → 三层记忆 → 感知 → 评测闭环。这个仓库记的是这条路上踩过的坑、量出来的结论，以及被数据推翻过的想法。

> 一个 LLM 从"会聊天"变成"像某个人"，靠的不是模型本身，是数据、检索、记忆、评测这套体系。

|  |  |
|---|---|
| **使用情况** | 日志覆盖的 17 天里，**190 人**在私聊里跟它聊过——**121 人回访 ≥3 天、28 人 ≥7 天**；另有 **11 个群、53 位群友** |
| **规模** | **11,152 轮**对话 ｜ **1332** 个单元测试 ｜ **414** 条直播记忆 ｜ **15** 条情景行为 |

## 为什么做这个

LLM 默认的"AI 腔"和真人差得很远。"像一个人"这件事，**靠提示词堆规则是没用的**——这一条是在反复看着模型"聊着聊着就变回 AI 腔"、一遍遍推翻重来之后才确认的。

## 四个反直觉的发现

这些不是设计时想出来的，是量出来之后被迫接受的。每条都有实测数据。

### ① 样本放错位置，比不放更糟

曾经有一路注入叫"她的真实原句"，按**话题**检索——听起来天经地义，实际是灾难：

| 用户的这句 | 检索捞到的 | 她答的 | 后果 |
|---|---|---|---|
| "你今天吃什么了" | "今天怎么没吃饭" | "还没吃呢" | **下一轮自相矛盾** |
| "外面下雨了" | —— | "刚淋着跑回来的" | 编的 |
| "最近怎么样" | "要写出百年孤独了" | 近乎逐字搬 | |

而且样本和真实历史混在一起后，**与【当前时间】"正在直播中"冲突 13/32**（走 system 通道只冲突 2/32）。

**根因**：按话题检索，必然捞到"同话题的完整回答"——**事实**就这么被灌进对话了。
**处置**：整条通道删除——6.4 MB 向量缓存 + 4 个脚本 + 8 条过时用例。该留的 18 句改成挂**情景**，并进 `behaviors`：情景天然跨话题，只带走"形态"，不带走"内容"。

### ② "说明"零作用，"形式"才有作用

把 10 处提示词里的"包装语"逐条审计（"请严格按此模式回应""只当背景记忆，别整段复述"…）：

- **A 类"用法说明" 6 处 → 实测零作用，全部删除**；
- 真正管用的是**改形式**：同一件事写成"自足句"会被整句搬走（16/16），写成"碎片"就只能织进新句（0/16）。

### ③ 别拿模型当裁判

想量"像不像她"，试了三把尺子，**先后全部失败**：

| 尺子 | 怎么坏的 |
|---|---|
| 自定义指标 | 权重得人肉定，等于把主观判断挪了个地方 |
| 指纹距离 | **噪声 ≥ 信号**：baseline 自己跑两次就波动 0.03，而效应量只有 0.01~0.06；两版**安慰剂**给出了**相反判定** |
| LLM 成对比较 | 拿一个不认识的模型判"像不像她"——它自己也不知道她是谁 |

最后站得住的只有一条路：**左右打乱 + 不标注 + 用户盲判 + 复现两次**。

> 由此立了一条铁律，后来每个判据都要过这一关：
> **「如果她答错了，这个判据会通过吗？」会通过，它就不是判据。**

### ④ 一个变量放错位置，能让一条判据静默失效

两个都是真跑很久之后才发现的：

- **判据**：`corpus_judge` 的提示词把 `{query}` 夹在中间（前后都是静态指令）→ 每轮 **0% 命中**；把变量挪到末尾 → **43%**。
- **成本**：记忆提取提示词的第一个变量出现在第 130 字（全篇 2630 字）→ **只有 5% 能命中前缀缓存**，后面整段静态指令每轮重算。挪到最后 → **95%**（此前跑几千次重建，攒出 400 万+ 未命中 token）。

> 同类问题一次修了三条提示词，缓存率 **0% / 17% → 97% / 98%**。

## 技术要点

- **两层人格**：人格层只有 2 个文件——骨架（每轮常驻）+ 15 条情景行为（命中才注）；其余全是事实层。"她怎么说话"和"她知道什么"分开维护。
- **按需注入，四种判据**：常驻 / 关键词子串 / 向量 / LLM 判断——**按任务选**（归类用 LLM、能说出口的词用子串、说法不可枚举才上向量+LLM）。改素材前先确认它属于哪种，改错地方不会生效。
- **三层记忆 + 类型化长期记忆**：短期（最近几轮，每条带"多久前"）/ 会话（当前话题 + 情绪，按话题老化）/ 群；长期记忆是**类型化条目**（事实 / 偏好 / 承诺），每条**带证据、带时间域、带隐私闸门**（电话/地址/证件/银行/医疗拒收并打码），支持作废。
- **评测闭环**：48 条检索期望（唯一真值）+ 7 条真实翻车判据 + 消融实验，改任何东西都能量化"变好还是变坏"。
- **1332 个单元测试**；方法论与被删机制的实测数据全部沉淀进 `docs/`。

## 技术栈

| 模块 | 技术 |
|:---|:---|
| 机器人框架 | NoneBot2 + OneBot V11 |

| 语音 | GPT-SoVITS（本地权重）；faster-whisper（离线语料转写） |
| 数据存储 | JSON（记忆、向量、人格数据） |

## 快速开始

```bash
git clone https://github.com/MureasAm/Hzm-AI-Bot.git
cd Hzm-AI-Bot
python -m venv .venv
.venv/Scripts/activate        # Windows（Linux/macOS: source .venv/bin/activate）
pip install -e .              # 依赖声明在 pyproject.toml（仓库里没有 requirements.txt）
```

前置：Python 3.10+、QQ 账号（NapCatQQ）、DeepSeek 与智谱 API Key、本地 GPU（语音合成可选）。
创建 `.env.prod` 填配置 → NapCat 登录 → `python bot.py`。

## 人格蒸馏流水线（离线工具箱）

从直播素材到人格数据的全链路，统一入口 `python scripts/run_tool.py <工具>`：

```
【流水线】persona-pipeline corpus|behaviors   素材 → 候选 → 人工审 → --apply 写回
【蒸馏】  transcribe → clean-transcript → convert-to-chat → analyze-pace
【生成】  generate-statements / generate-vectors / extract-persona
【评测】  regression --check / retrieval-eval / persona-eval / problems
【工具】  bili-check / vision-test / memory-audit / memory-replay ...
```

每次注入素材都先出候选、人工过一遍再写回，不一次性跑完流水线。

## 结语

这个项目在试的一件事：**让 LLM 稳定还原一个真实人物的说话方式，能不能被工程化。** 现在的答案是"能"，但它靠的不是模型更聪明——是数据蒸馏、检索、记忆、评测这套体系，加上大量的、可复现的试错。
